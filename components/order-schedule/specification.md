# مواصفة جدول الطلبات المجدولة — order-schedule

## التحديث الحالي

تسري [عقود النظام](../../docs/SYSTEM-CONTRACTS.md): **Light-only**، Geometry B، أرقام Western وتقويم ميلادي. المنطقة الزمنية وقراءة تواريخ الأعمال مسؤولية المضيف؛ البيانات محلية للعرض. في نمط الشهر تُعرض **شبكة الشهر الكاملة عند كل عرض جذر** (تحت 360px بعرض مدمج موثق أدناه) مع Month/Year Picker؛ لا انتقال auto-Day صامت. أزرار الأوامر 48px على الأقل، وخلايا الشهر المدمجة تحتفظ بأرضية ارتفاع 48px وعرض ≥ 24px (الحد الأدنى WCAG 2.5.8). يفصل المكوّن شهر العرض عن التاريخ المحدد، ويعرض حالة «لا يوم محدد في هذا الشهر» بصدق أثناء تصفّح شهر بلا تحديد، وتبقى العائلة DRAFT FOR REVIEW دون ادعاء اختبار جهاز أو تكبير أصلي.

الحالة: **DRAFT FOR REVIEW** — مكوّن جديد من [فهرس المكونات](../../docs/COMPONENT-INVENTORY.md) وبطاقة [مرجع الإصدار](../../docs/UI-RELEASE.md) (CAL-01..15). مواصفة المكوّن الحالية. RTL افتراضيًا وLTR معكوس الاتجاه ومدعوم، أرقام 0–9 غربية، IBM Plex عبر `var(--micro-font-family)`، فاتح، بلا مكتبات خارجية، والملفان `order-schedule.js` + `order-schedule.css` هما المصدر.

## 1) الغرض والدور

عرض الطلبات المجدولة على تقويم شهري (طلبات اليوم أسفل الشبكة داخل الصفحة) وعلى عرض يوم وقائمة (قادمة/سابقة/غير مجدولة) مع حالة كل طلب **كما يمررها المستهلك**. المكوّن يعرض ويطلق الأحداث؛ المستهلك يملك تفاصيل الطلب والحفظ والبيانات. **لا أرباح ولا أرصدة ولا مبالغ ولا أي مصطلح مالي، ولا استنتاج «تم التسليم/متأخر» من التاريخ — الحالة تأتي من البيانات فقط، والماضي لا يتحول تلقائيًا إلى شيء.** لا حجز مندوب ولا محرك قواعد.

## 2) بنية الجذر والسيمانتيكس (data-ocal-*)

`MicroOrderSchedule.init(rootElement, options)` يستملك الجذر ويبني داخله (كل النص من البيانات عبر `textContent`/عُقد DOM — لا HTML من البيانات):

| السمة/العنصر | المعنى |
|---|---|
| `data-ocal-init="1"` | علامة تهيئة على الجذر (تزول في `destroy()`) |
| `[data-ocal-root]` + `.m-ocal` | علامة الجذر + صنف النطاق |
| `data-ocal-view="calendar\|list"` / `data-ocal-cal-view="month\|day"` | حالة العرض الحالية على الجذر |
| `data-ocal-preferred-cal-view="month\|day"` | اختيار نمط الشهر/اليوم؛ لا يغيره تكيف العرض مع عرض الجذر |
| `data-ocal-layout="month-grid\|day\|list"` | طريقة العرض الفعلية: شبكة الشهر (كل العروض) أو عرض اليوم/القائمة |
| `data-ocal-compact="true\|false"` | العرض المدمج لشبكة الشهر عند عرض جذر أقل من 360px (عرض CSS فقط — بنية DOM واحدة) |
| `data-ocal-selected-date="YYYY-MM-DD"` | التاريخ المحدد مستقلًا عن الشهر المعروض |
| `[data-ocal-screen="calendar"]` / `"list"` | شاشة فرعية واحدة ظاهرة حسب العرض |
| `[data-ocal-action]` | كل زر: `view` / `cal-mode` / `prev-month` / `next-month` / `today` / `month-picker` / `picker-back` / `picker-prev-year` / `picker-next-year` / `picker-month` / `prev-day` / `next-day` / `day-cell` / `order-row` / `add` / `retry` |
| `[data-ocal-add-date="YYYY-MM-DD"]` | على زر `add`: اليوم الذي سيُطلقه الحدث؛ فارغ = بلا يوم (قائمة/شهر تصفّح بلا تحديد) → الحدث بـ `date:null` |
| `[data-ocal-grid]` | شبكة الشهر: `role="grid"` + صفوف `role="row"` + خلايا أزرار `role="gridcell"` بـ `data-ocal-date="YYYY-MM-DD"` — تُعرض كاملة عند كل عرض جذر |
| `[data-ocal-day-browsing="true"]` | على لوحة اليوم: حالة تصفّح شهر لا يحوي التاريخ المحدد — عنوان «لا يوم محدد في …» + عدد طلبات الشهر المعروض + إضافة بلا يوم؛ لا صفوف يوم من شهر آخر |
| `[data-ocal-picker]` | طبقة اختيار محلية للشهر والسنة؛ خيارات الأشهر فقط داخل مجموعة الأشهر |
| `[data-ocal-day-panel]` | لوحة اليوم أسفل الشبكة (وفي شاشة اليوم): عنوان التاريخ الكامل h3 + عبارة العدد + زر الإضافة + `ul.m-ocal__rows` من صفوف `[data-ocal-id]` |
| `[data-ocal-legend]` | مفتاح الحالات (نقطة + نص) للنطاق المعروض |
| `[data-ocal-status="loading\|error\|empty"]` | صناديق حالات العرض (loading: `role="status"`، error: `role="alert"`) |

## 3) عقد الواجهة (كما يستهلكه الموصل)

```js
var inst = MicroOrderSchedule.init(rootElement, options);
// options: orders, statuses, today, weekStart, selectedDate,
//          view ('calendar'|'list'), calendarView ('month'|'day'), loading
inst.setData(orders);                 // تحديث كامل بلا إعادة تهيئة
inst.setSelectedDate('2026-10-09');   // صامت: بلا أحداث
inst.setView('list');
inst.setCalendarView('day');
inst.setLoading(true);                // / false
inst.setError(retryCallback);         // / null لإزالة الخطأ
inst.destroy();
var same = MicroOrderSchedule.getInstance(rootElement);
```

أحداث `CustomEvent` على الجذر (bubbles — يمكن التقاطها على أي سلف):

| الحدث | detail | متى |
|---|---|---|
| `order-schedule:day-select` | `{date:'YYYY-MM-DD'}` | اختيار يوم من الشبكة بنقرة أو Enter/Space، زر «اليوم»، أو سهما اليوم في عرض اليوم؛ تغيير الشهر أو السنة المعروضة لا يختار تاريخًا ولا يطلق الحدث |
| `order-schedule:order-open` | `{id:'od-01'}` | نقرة/Enter على صف طلب — **مرة واحدة لكل فعلة** |
| `order-schedule:add-request` | `{date:'YYYY-MM-DD'\|null}` | زر «إضافة طلب»: `date` = اليوم المحدد في لوحة اليوم، و`null` في القائمة وأثناء تصفّح شهر بلا يوم محدد فيه (لا يوم مختار يُنسب إليه الطلب) |

قرارات موثقة:

- **أفعال المستخدم فقط تطلق الأحداث**؛ العمليات البرمجية (`setSelectedDate`/`setView`/`setCalendarView`/`setData`) صامتة — يمنع حلقات الاستدعاء بين الموصل والمكوّن.
- **التهيئة المزدوجة**: `init` على جذر مُهيأ يعيد المثيل نفسه بلا مستمعات جديدة ولا تكرار أحداث؛ الخيارات الأولى تُحتفظ (المُهيأ الثاني لا يعيد تطبيق خيارات).
- **أسبقية حالات العرض — آخر استدعاء يملك الشاشة**: `setError(cb)` يمسح الانتظار، و`setLoading(true)` يمسح الخطأ، و`setData` يمسحهما معًا — لا يُعرض تقويم/قائمة أثناءهما (لا نجاح كاذب). الرد المتأخر مسؤولية الموصل (تتابع الطلبات عنده).
- **إعادة المحاولة**: زر `retry` يستدعي callback المستهلك فقط — **المكوّن لا يعيد التحميل بنفسه**؛ `setError(null)` أو `setData` يزيلان الخطأ.
- `destroy()` ينزع كل مستمع (مراجع مخزنة في مصفوفة)، يفرّغ محتوى الجذر، يزيل `data-ocal-init`/`data-ocal-root`/`data-ocal-view`/`data-ocal-cal-view` وصنف `m-ocal`، ويحذف المثيل — بعده لا أحداث إطلاقًا، والمستوى بعد الدمار لا-عملي، و`init` جديد على الجذر نفسه يعمل. لا مؤقتات ولا rAF داخل المكوّن أصلًا.
- البنية: **مستمعان مفوّضان على الجذر فقط** (click + keydown) يسجلان مرة عند التهيئة؛ إعادة التصيير لا تضيف مستمعات أبدًا.
- التركيز بعد كل فعل يعاد إلى مكافئ العنصر المنقور (خلية اليوم المحدد، زر السهم نفسه، زر التبديل المضغوط) — لا يضيع إلى body.
- خيار غير صالح (view غير معروف، weekStart خارج 0–6، تاريخ غير نصي…) يسقط إلى الافتراضي الموثق بلا خطأ. `init` بجذر غير عنصر يرمي خطأ عربيًا (خطأ مطور فادح).

## 4) عقد البيانات

```js
orders: [ { id:'od-01', title:'طلب القهوة العربية', date:'2026-10-08'|null,
           time:'14:30'|null, statusKey:'progress', customer:'مطزاوية الفيصل' } ]
statuses: { progress:{label:'قيد التنفيذ',tone:'progress'}, ... }
```

- `id` فريد (نص)، `title` نص، `date` نص `'YYYY-MM-DD'` أو `null`، `time` نص `'HH:mm'` أو `null`، `statusKey` نص، `customer` نص اختياري.
- **تحقق صارم**: تاريخ لا يطابق `YYYY-MM-DD` (أو غير نص) → `null` (غير مجدول)؛ وقت لا يطابق `HH:mm` → غائب (**لا يُخترع وقت أبدًا**). كل قيمة تُقرّب إلى نص خام — لا HTML من البيانات (حقن `<img onerror>`/`<b>` يظهر نصًا حرفيًا).
- خريطة `statuses` من المستهلك: مفتاح → `{label, tone}`. **المفتاح المجهول أو الخريطة الغائبة**: عرض محايد (رمادي ثانوي) بنص المفتاح الخام كما ورد — لا إخفاء ولا خطأ. `statusKey` فارغ → بلا شريحة حالة. `tone` غير مسموحة → محايد.
- نبرات الحالات المسموحة (أزواج توكنات معتمدة فقط — لا ألوان جديدة):

| tone | لون النقطة/النص | سطح الشريحة |
|---|---|---|
| `progress` (و`info` مرادفه — نفس الزوج) | `--micro-info` | `--micro-info-surface` |
| `success` | `--micro-success` | `--micro-success-surface` |
| `warning` | `--micro-warning` | `--micro-warning-surface` |
| `neutral` (والمجهول) | `--micro-text-secondary` | `--micro-surface-page` |

- الحالة تظهر **نصًا + لون دائمًا** (لا لونًا وحده): نقطة + النص في الصف، ونقطة + النص في المفتاح، والعدد نصيًا في `aria-label` الخلية.
- عبارات العدد العربية: 0=«لا طلبات»، 1=«طلب واحد»، 2=«طلبان»، 3–10=«N طلبات»، 11–99=«N طلبًا»، 100+=«N طلب».
- أسماء الأشهر والأيام مصفوفات عربية داخلية؛ عنوان الشهر «أكتوبر 2026»؛ التاريخ الكامل «الأربعاء 7 أكتوبر 2026»؛ صف القائمة يحمل شارة تاريخ قصيرة («8 أكتوبر» + السنة إن خالفت سنة اليوم) — امتداد موثق لسياق القائمة فقط.

## 5) الرياضيات والتواريخ (لا UTC)

- كل التواريخ نصوص `'YYYY-MM-DD'`: **ممنوع `Date.parse`/`toISOString`/أي تحويل UTC** — تجميع الطلبات ومقارنات القائمة بمقارنة نصية حرفية (صفر-مبطّن فالفرز النصي = الزمني).
- `daysInMonth(y,m)` = `new Date(y, m, 0).getDate()` محليًا (فبراير 2028=29، 2027=28).
- `weekdayOf(y,m,d)` = `new Date(y, m-1, d).getDay()` محليًا — يوم الأسبوع لتاريخ مدني لا يتغير بالمنطقة (CAL-09).
- التنقل بين الشهور بحساب عائم `(y*12 + (m-1)) ± delta` — ديسمبر→يناير وم31→فبراير بلا انزلاق ولا حدود أعوام (الماضي والمستقبل غير محدودين).
- `today` الافتراضي = تاريخ اليوم **المحلي** كنص من `getFullYear/getMonth/getDate` (بلا toISOString). قابل للتثبيت في الخيارات للاختبارات.
- `weekStart` خيار لكل مثيل (0=الأحد..6=السبت)، الافتراضي **6 (السبت)** كخيار سياق عربي أولًا — ليس معيارًا مفروضًا عالميًا؛ العينة تمرره صراحة.
- **الشهر المعروض منفصل عن التاريخ المحدد — وبتعامل صادق:** سهم الشهر وPicker الشهر/السنة يستكشفان الشهر المعروض فقط؛ لا يغيّران `selectedDate` ولا يطلقان حدثًا. إذا كان التاريخ المحدد داخل الشهر المعروض تظهر لوحته كاملة أسفل الشبكة. إذا كان التصفّح في شهر **بلا يوم محدد فيه** تعرض لوحة اليوم حالة تصفّح صادقة (`data-ocal-day-browsing`): «لا يوم محدد في الشهر السنة» + عدد طلبات الشهر المعروض + زر إضافة بلا يوم — **لا يُعرض يوم محدد من شهر آخر كأنه من الشهر المعروض**. اختيار يوم من الشبكة يحدّث التحديد فقط ويطلق الحدث مرة واحدة. `setSelectedDate` البرمجي صامت ويزامن الشهر المعروض مع الشهر المطلوب.
- بالمقابل: **عبور حدود الشهر بلوحة المفاتيح (الأسهم) يغيّر الشهر المعروض وينقل التركيز فقط** — بلا تحديد وبلا حدث؛ التحديد يبقى للضغط/Enter (قرار موثق: الأزرار تختار والأسهم تستكشف).

## 6) العروض والسلوك

- **هرمية التحكم**: شريط علوي «تقويم/قائمة» بزرين معلني الضغط `aria-pressed`. تبديل الشهر/اليوم إجراء واحد «عرض اليوم» أو «عرض الشهر» بدل عرض أربعة خيارات متساوية. أهداف التحكم ≥48px (`--micro-touch-min`).
- **رأس الشهر**: [السابق][الشهر والسنة][التالي][«اليوم»] — زر الشهر/السنة يفتح Picker حقيقيًا محليًا. Picker يحوي أزرار السنة السابقة/التالية وشهور السنة الاثني عشر وزر «رجوع للتقويم». اختيار شهر/سنة يبدّل الشهر المعروض فقط. Escape و«رجوع للتقويم» يغلقان الطبقة ويعيدان التركيز إلى زر الشهر/السنة؛ عند الاختيار يعود التركيز إليه كذلك. حد السنوات 1–9999. في RTL يقع السابق يمينًا بسهم لليمين والتالي يسارًا بسهم لليسار (اتجاه الزمن RTL؛ معكوس في LTR).
- **خلية اليوم**: رقم + عدّاد طلبات (شريحة رقمية تظهر فقط عند وجود طلبات) + **≤3 نقاط حالات** (أنواع الحالات الموجودة ذلك اليوم، نقطة ≥6×6px بلون النبرة) — لا نقطة لكل طلب بلا سقف. **اليوم الحالي**: حد خارجي 2px بلون `--micro-brand-primary` + نقطة 4px تحت الرقم + `aria-current="date"` + كلمة «اليوم» في `aria-label`. **المحدد**: تعبئة `--micro-brand-primary` ونص `--micro-text-inverse` و`aria-selected="true"`؛ عند اجتماعهما يتحول الحد والنقطة إلى المعكوس فتبقى علامة اليوم ظاهرة بلا اختلاط.
- **التكيف عند ضيق الجذر (عقد 2026-10-24 — شبكة الشهر الكاملة المدمجة):** شبكة الشهر تُعرض **كاملة عند كل عرض جذر** — لا تمثيل جزئي للشهر ولا مسار تواريخ جانبي. عند عرض أقل من 360px يظهر `data-ocal-compact="true"`: العرض حالة CSS على الجذر فقط (بنية DOM واحدة)، فلا إعادة تصيير ولا فقدان تركيز عند تغيّر المساحة. خلايا الأيام المدمجة: عرض `(100%−24px)/7` (37.7px عند جذر 288px — ≥ الحد الأدنى WCAG 2.5.8 وهو 24px) وارتفاع ≥ 48px (`max(2.7em, --micro-touch-min)`) — هندسة تقاويم الهاتف المعروفة؛ وأزرار الأوامر كلها (رأس، تبديل، Picker، صفوف، إضافة) تبقى ≥48px. عند 360px فأكثر تختفي السمة وتعود الخلايا المربعة 48px. اختيار «يوم» و«قائمة» يظل صريحًا ولا يُفرض تلقائيًا. يراقب `ResizeObserver` عرض الجذر الفعلي (مع fallback إلى resize للنافذة) ويفصل في `destroy()`.
- `aria-label` الخلية كامل: «الأربعاء 7 أكتوبر 2026، اليوم، 5 طلبات».
- **عرض اليوم**: شريط [اليوم السابق][التاريخ الكامل][اليوم التالي] ثم العدد وزر الإضافة وصفوف اليوم المدمجة. لا سطر زمني بالساعات — الوقت داخل الصف فقط إن وُجد.
- **صف الطلب موحّد** (اليوم/الأسفل/القائمة): زر صف كامل (100% × ≥48px، محاذاة يمين RTL)؛ سطر أول العنوان (body وزن 500، `overflow-wrap: anywhere` فلا يكسر الصف)؛ سطر ثانٍ: العميل (اختياري) + شارة الوقت (ساعة SVG مضمّنة + قيمة معزولة `direction:ltr; unicode-bidi:isolate`) + الحالة (نقطة لون + النص بشريحة سطحيّة من زوج النبرة). الضغط/Enter يطلق `order-open` مرة واحدة لكل فعلة.
- **القائمة**: «الطلبات القادمة» (من today فأحدث — تصاعديًا بالتاريخ ثم الوقت ثم العنوان)، ثم «الطلبات السابقة» (الأحدث أولًا؛ داخل اليوم نفسه: الوقت تصاعديًا ثم العنوان)، ثم «طلبات غير مجدولة» (بترتيب الإدخال). القسم الفارغ يُخفى؛ كل طلب مرة واحدة في نطاقه. الترتيب داخل اليوم: ذات الوقت أولًا ثم بلا وقت، والعنوان ترتيبًا نصيًا حتميًا (بايت — لا مطابقة لغوية). إجمالي بيانات فارغ (0 طلبات) → حالة فراغ صادقة «لا توجد طلبات بعد.» + مرشد إضافة.
- **مفتاح الحالات**: صف صغير تحت الشبكة (نطاق الشهر المعروض) وفوق القائمة (كل الطلبات المعروضة) — الحالات الموجودة فعلاً في النطاق فقط؛ يختفي إن لم توجد. عرض اليوم بلا مفتاح (الصفوف تعرض نص الحالة كاملًا).
- **زر «إضافة طلب»**: في رأس لوحة اليوم (شهرًا ويومًا) برأس القائمة وفي حالة الفراغ — يطلق `add-request` بتفصيل التاريخ المذكور أعلاه.

## 7) الإتاحة

- **شبكة حقيقية**: `role="grid"` + `role="row"` + أزرار `role="gridcell"` مع **roving tabindex** فعلي: `tabindex=0` لخلية التركيز/المحددة فقط و`-1` للباقي — توقف Tab واحد للشبكة.
- **الشبكة بلوحة المفاتيح**: الشبكة ذات roving tabindex واحد. يمين/يسار تحرك ±1 يوم (في RTL الأيسر = التالي والأيمن = السابق؛ معكوس في LTR)، أعلى/أسفل ±7. عبور الشهر يحدّث الشهر المعروض والتركيز فقط (وتظهر حالة التصفّح الصادقة في لوحة اليوم). `Home`/`End` أول/آخر خلية في صف الأسبوع. `Enter`/`Space` يختاران عبر click الأصلي ويطلقان حدثًا واحدًا. داخل Picker تحرك الأسهم التركيز بين الأشهر، وEscape يغلقه.
- `aria-selected` على الخلية المحددة، `aria-current="date"` على خلية اليوم، `aria-label` كامل لكل خلية (التاريخ + اليوم + العدد). صفوف أيام الأسبوع `aria-hidden` (المعلومة كاملة في label الخلية). صناديق الحالات: loading بـ `role="status"` وerror بـ `role="alert"`.
- التركيز مرئي: `outline` بسمك `--micro-focus-ring-width` ولون `--micro-focus-ring` وإزاحة `--micro-focus-gap`.
- `prefers-reduced-motion`: `transition: none` و`animation: none` لكل عناصر المكوّن.
- لا عشرات توقفات Tab: الشبكة توقف واحد + أزرار الرأس/التبديل + صفوف الطلبات (أهداف مشروعة ≥48px).

## 8) هندسة الشهر عند ضيق الجذر

- عرض الشبكة المربعة 48px يتطلب `7 × 48px + 6 × 4px = 360px`؛ تحت ذلك لا تُخفى الشبكة ولا تُستبدل بتمثيل جزئي: **الشهر كامل بكل أيامه عند كل عرض** (قرار 2026-10-24: تمثيل شهر ناقص يفشل في وظيفة المكوّن الأساسية — اكتشاف أيام الشهر كلها والوصول إليها — بينما خلايا 24–48px عرضًا و48px+ ارتفاعًا هي الهندسة القياسية لتقاويم الهاتف وتتجاوز الحد الأدنى WCAG 2.5.8 بوضوح).
- تحت 360px: `data-ocal-compact="true"` على الجذر. عرض الخلية `(100%−24px)/7` (37.7px عند 288px، 43.4px عند 328px، 47.7px عند 358px) وارتفاع الصف `max(2.7em, 48px)` فتتمدد الخلايا رأسيًا. رأس الأسبوع المختصر (`أحد/إثن/ثلا/أرب/خمي/جمع/سبت`) صُمم أصلًا لأعمدة ~38px.
- من 360px فأعلى: خلايا مربعة ≥48px بroving tabindex. اسم اليوم كاملًا في `aria-label`.
- ارتفاع صف الشبكة الأدنى 2.7em؛ الخلايا تتمدد رأسيًا عند تكبير النص بدل قصّ العدد والنقاط أو توسيع الصفحة — في الوضعين معًا.
- نتائج الأدوات التاريخية المذكورة في إصدارات سابقة ليست نتائج لهذه النسخة؛ يعاد التحقق من المصدر الحالي عبر `python3 tools/light-calendar-check.py`.

## 9) حدود الاستخدام

- بلا أرباح أو أرصدة أو مبالغ أو أي مصطلح مالي؛ وبلا استنتاج حالة من التاريخ («متأخر»/«تم التسليم» تأتي من `statuses` المستهلك فقط)؛ وبلا حجز مندوب أو مواعيد سفر أو محرك حجز جديد.
- المكوّن عرض وأحداث فقط: لا يفتح تفاصيل الطلب ولا يحفظ ولا يستدعي شبكة؛ الموصل يملك ذلك.
- لا يُفترض sprite أيقونات عند المستهلك: السهمان والساعة والزيادة SVG مضمّنة صغيرة داخل JS.
- عربي RTL أولًا؛ LTR مدعوم بعكس اتجاه أسهم التنقل (اختُبر في فحص Chromium المصدرّي، دون ادعاء اختبار جهاز أو قارئ شاشة).
- لا مطابقة لغوية في فرز العناوين (ترتيب بايت حتمي) — موثق.
- تعمل الأسماء العربية والصيغ من مصفوفات داخلية — لا Intl/Calendar API (تتطلب بيئة كاملة وتختلف بين المتصفحات).

# إعدادات الحساب والتطبيق — SPEC-03

## تهيئة النسخ ودورة الحياة — تدقيق 2026-11-11

سمات DOM المنسوخة مثل `data-*-bound` أو `data-*-ready` ليست دليلًا على وجود مستمعات أو مراقبين أحياء. عند `cloneNode(true)` ثم تركيب النسخة واستدعاء `init` عليها، تملك العقدة الجديدة ربطها ومواردها الخاصة؛ تكرار `init` لا يكرر التفعيل. يُنظّف المستهلك الأصل عبر API العائلة قبل إزالته، ويحدّث معرّفاته التي يملكها عند عرض نسختين معًا. تبقى ملكية المراقبين والحالة والتنظيف وفق العقد الحالي.

الفحص المستقل: `python3 tools/clone-lifecycle-check.py`؛ يثبت فشل النسخ القديم أيضًا باستخدام `--source-ref 041c5a1096424047ebacccc9ca19c4b49e20aac1` للقراءة فقط، دون تبديل فرع.


## العقد الحالي الإضافي

تسري [عقود النظام](../../docs/SYSTEM-CONTRACTS.md): Geometry B وLight-only. `disconnect(root)` و`destroy(root)` يفصلان أحداث التركيب؛ التنظيف الطبقي عبر `MicroNavigation.disconnect` أيضًا، وتنظيف أي Selection مضمّن عبر API العائلة. لا حفظ إعدادات فعليًا ولا history/Back أو ثيم دائم يملكه المكوّن.

**الحالة: STABLE UI — [UI-RELEASE](../../docs/UI-RELEASE.md).** أجزاء قابلة للتركيب، لا شاشة منتج أو صلاحيات إدارية.

## أجزاء مستقلة

- ملخص الحساب `.m-account-profile`، مجموعة `.m-setting-group`، صف قراءة/تنقل `.m-setting-row`، وصف إعداد بمفتاح الاختيار الحالي `.m-switch`.
- حاوية مثال الإعدادات `[data-account-settings]`: زر مستهلك يحمل `data-account-open`، وطبقة واحدة من عائلة B07. داخلها منظور الحساب ومنظور التطبيق متجاوران في DOM، ولا تُكدّس نافذتان.

## عقد الطبقة

يستعمل component المكتبة الحالية كما هي: عنصر `div.m-layer` و`.m-layer--center` وغشاء `.m-layer-backdrop` و`MicroNavigation.openLayer/closeLayer`. تعلن اللوحة `data-account-layer-id` أو تعيش داخل طبقتها. `data-account-to-application` يفتح إعدادات التطبيق، و`data-account-back` يرجع للحساب داخل الطبقة نفسها. `data-account-close` يغلق ويعيد تركيز المشغّل. Escape، inert للخلفية، حصر التركيز واستعادته من تنفيذ B07.

**سلوك إعادة التوسيط في النموذج الموسّط (F-10 — 2026-10-10، قرار مالك
مسجل):** الطبقة `m-layer--center` حوار **موسّط** بعقد B07 — عند تغيّر ارتفاع
محتواها (الانتقال بين منظور الحساب ومنظور إعدادات التطبيق) يعاد توسيطها
فقيرتفع/ينخفض زر الإغلاق مع رأس الطبقة (قياس F-10 في المعرض: إزاحة ~38px
بين المنظورين، والطبقة تبقى على مركز الشاشة بدقة). هذا سلوك النموذج
الموسّط الشرعي والمستقر الحتمي — ليس عيبًا ولا يجمّد الزر بموضعة تعسفية.
البدائل (لوحة سفلية برأس ثابت `m-layer` غير center، أو عمود بطبقة قابلة
للتمرير الداخلي) تبقى خيارات تكوين معلنة للمستهلك إن طلب استقرار الرأس؛
اختيار النموذج الأنسب لكل موضع قرار تركيب مستقبلي للمالك عند نشوء حاجة
منتج فعلية. لا تغيير سلوك في هذه الجولة.

## بيانات وسلوك

كل أسماء الحساب والإعدادات والصفوف تأتي من HTML. المفاتيح اختيار أصلي `role="switch"`/checkbox ضمن `.m-switch`. عند وسم عنصر الاختيار `data-account-setting`, يطلق تغيره `micro-account-settings:change` ببيانات `setting` و`checked`. لا تخزين خادمي أو محلي افتراضيًا. أضف `data-demo-only` لعينة مؤقتة لعرض تنبيه أن التغيير لم يُحفظ.

## RTL والإتاحة

أهداف الصفوف 72px على الأقل، المفتاح يوفّر الهدف الموجود في B03، والصفوف تستخدم اتجاه الخصائص المنطقية. تسميات العناوين ترتبط بسمات الحوار وتُخفى مع المنظور الآخر. أيقونات HugeIcons محلية بأصول موجودة؛ لا تستخدم علامة بديلة أو عائلة أخرى.

## اعتماد

`account-settings.css` و`account-settings.js` يتطلبان `navigation.css/js` للمشهد الحواري، و`buttons.css` للأزرار، و`selection.css` للمفاتيح الأصلية؛ حمّل `selection.js` عند استعمال سلوك المجموعات أو pending المشترك، إضافة للتوكنات والخطوط. مثال مستقل كامل في `example-usage.html`.
تفاصيل التهيئة وتنظيف الطبقة والأطفال: [بطاقة الاستهلاك](../../docs/FAMILY-CONSUMPTION.md).

## منظور افتتاح اختياري
`data-account-initial-view="application"` يفتح القائمة أولًا. `data-account-to-account` يفتح الحساب داخل الطبقة نفسها وBack يعود للمنظور الأول. غياب السمة يبقي السلوك السابق. لا تبديل صلاحيات/حساب أو حفظ ضمن المكتبة. مثال `previews/mobile-experience/menu.html`.

# C06 — وصفة ملخص خارجي متزامن مع التقويم

تركيب Draft يستعمل C01 من Info Strip بجوار Order Schedule. لا CSS أو محرك حالة أو API جديدة داخل التقويم. [المثال القابل للتشغيل](../../previews/mobile-capabilities/calendar-summary.html) و[عقد C01](../../docs/COMPOSITIONS.md).

## حدود الملكية

- البطاقة خارج جذر Order Schedule؛ لا تكتب داخل DOM الذي يعيد التقويم رسمه.
- يختار المستهلك صراحة نطاق «اليوم المحدد» أو «الشهر المعروض»، ويعرض العنوان والفترة والوحدة؛ selectedDate وdisplayedMonth مستقلان.
- يمرر المستهلك القراءة. المكتبة لا تحسب دخلًا أو تحصيلًا أو سعة أو صلاحيات أو recurrence.
- تبقى حقول الطلب الحالية دون توسعة metadata/HTML slots؛ التوسعة الداخلية تتطلب محتوى محددًا وحاجة تثبت أن الملخص الخارجي غير كافٍ.

## المزامنة

1. اقرأ نسخة `calendar.getState()` بعد init وارسم البطاقة من مصدر المستهلك.
2. عند `order-schedule:state-change` اقرأ الحالة العامة مجددًا. تغيير الشهر لا يغيّر اليوم المحدد تلقائيًا.
3. بعد أي setter برمجي يملكه المستهلك أو setData أو تحديث قراءة/خطأ، حدّث الملخص صراحة؛ setters صامتة، فلا تنتظر حدثًا غير صادر ولا تصطنع حدث مستخدم.
4. عند انتظار بيانات فترة جديدة، أظهر انتظارًا واضحًا أو قراءة قديمة موسومة بفترتها؛ لا تعرض قيمة قديمة تحت عنوان جديد. الغياب/الخطأ ليس صفرًا، والمصدر الفارغ المعلوم يمكن عرضه0 مع الوحدة.
5. عند التنظيف أوقف مستمعات المستهلك وألغِ طلباته/نتائجه المتأخرة، ثم `calendar.destroy()` وأزل الملخص. لا callbacks تقرأ getState بعد تدمير المكوّن.

CSS المطلوب: fonts/tokens وinfo-strip.css وvalue-context.css وorder-schedule.css، مع order-schedule.js. كود calendar-summary.js في المثال **مستهلك محلي فقط**: يعد سجلات عينة للفترة المختارة، ويمثل الانتظار/الخطأ/الفراغ من أدوات المعاينة. لا يعبر عن قواعد بيانات Micro أو يدعي اتصالًا بها.

التنفيذ للهاتف Light/RTL، باستخدام أحجام C01 الحالية ودون ملخص مكرر مفروض على كل شاشة. [الفحص](../../tools/mobile-capabilities-check.py) يثبت المزامنة المستقلة لليوم/الشهر، setter الصامت، الصفر مقابل الغياب، عدم الكتابة داخل التقويم، والتنظيف.

## مساحة العرض حسب المهمة

[مختبر المقارنة](../../previews/mobile-capabilities/calendar-tasks.html) يستخدم Order Schedule نفسه، ويبدأ بالأسبوع لمثال المتابعة. مبدّل يوم/أسبوع/شهر هو المكوّن الحالي؛ لا toolbar مكرر أو API جديدة. لا يغيّر ذلك افتراضي العائلة أو التطبيق. اختيار المهمة يسبق قرار الحجم؛ لا تصغر أهداف الأيام لإبقاء شهر كامل فوق كل قائمة.

# مواصفات الرسائل والحالات العامة — B06

الحالة: **STABLE UI** — الأوزان البصرية والحالات تتبع [UI-RELEASE](../../docs/UI-RELEASE.md)؛ النصوص أمثلة لا رسائل أعمال نهائية.

## 1) الأجزاء والعقد

| الجزء | العقد |
|---|---|
| `m-note` (help/info/success/warning/error) | رسالة ثابتة برمز المعنى ونصه — **لا تختفي ذاتيًا**؛ إغلاق يدوي اختياري؛ الإعلان (SUI-010): مساعدة `role=note`، معلومة/نجاح/تحذير `status`، **خطأ `alert` فقط** — الخطأ الثابت القابل للتصرف هو الذي يقاطع (إعلان واحد عند الظهور)؛ لا يرفع كل تحذير إلى alert بحكم الاسم |
| `m-toast` | **تأكيد غير حرج فقط** — عقد `MicroMessages.toast(el, {duration})`: مدة المستهلك (افتراض 4000ms)، إغلاق يدوي دائمًا، إعلان عبر القناة الحية الواحدة، **مع بديل ثابت إلزامي** بجانبها. الرسالة المهمة أو المطلوبة لتصحيح إدخال ليست Toast أبدًا. حاوية الـtoast توضع على مستوى التطبيق خارج أي وجهة مخفية (تركيب F03: SUI-001) كي يكون مستطيلها >0 دائمًا |
| `m-wait` | مؤشر + تسمية صريحة دائمًا؛ تقليل الحركة يجعله ثابتًا (الدلالة من التسمية) |
| `m-skeleton` | خفيف للشكل المقابل عند فائدته فقط — بلا تفاصيل مزيفة ولا لمعان عند تقليل الحركة |
| `m-empty` | ثلاث حالات مفهومة: لا بيانات (بدء) / لا نتائج (خطوة تصحيح) / فشل قراءة (إعادة محاولة المستهلك) — لا بيانات مالية مخترنة |
| `MicroMessages.announce` | إعلان بهوية الحدث (SUI-012): `announce(text, {id})` — الحدث ذاته (id نفسه والنص نفسه) يُعلن مرة واحدة؛ الحدث المستقل (id مختلف أو بلا id) يُعلن ولو تطابق النص. الوسيط الثاني يقبل المنطقي القديم (assertive) للتوافق الخلفي |

- الخطأ لا يمحو محتوى معروفًا بلا سبب (منطق الحفظ عند المستهلك — القاعدة موثقة ومطبقة في أمثلة B02/B06).
- لا مركز إشعارات ولا منطق retry شبكي داخل المكوّن (حدود التكليف).

### مراجع عقد الإعلان (SUI-010)

- [WCAG 2.2 — Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): النجاح/المعلومة/التحذير قيد التقدم = `status` (polite) — يُعلن دون تحويل التركيز.
- [WAI-ARIA Alert Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/): الخطأ الثابت القابل للتصرف = `role=alert` — إعلان واحد عند الظهور؛ لا يُستعمل لمعلومة غير مهمة ولا يُعمم على كل تحذير بحكم الاسم.
- قناة واحدة لكل سياق: الرسالة الثابتة (m-note) قناتها دورها نفسه؛ الرسالة العابرة (toast) قناتها المنطقة الحية المشتركة — لا تكرار نص واحد بمسارين.

### عقد هوية الحدث في announce (SUI-012)

- **متى تمرر `id`:** عند احتمال إعادة إعلان الحدث نفسه (مثل إعادة إظهار تأكيد لطلب واحد بعينه من المصدر نفسه) — المرّة الثانية بنفس `id` والنص تُمنع.
- **متى لا تمرر `id`:** لكل حدث مستقل حتى لو تطابق النص (حذف عنصرين متتاليين بنص «تم حذف العنصر.») — كل فعل يعلن نتيجته (S28/S32).
- الاستدعاء بلا وسيط ثانٍ أو بالمنطقي القديم يبقى حدثًا مستقلًا — التوافق الخلفي محفوظ (فحص المستدعين بـgrep في جولة الإصلاح: لا مستدعي مباشر خارج المكوّن يعتمد المنع النصي).

## 2) أين أعدّل؟

| أريد تغيير | المكان |
|---|---|
| ألوان المعاني | `shared/tokens.css` — أزواج المعنى |

| نصوص الرسائل | HTML المستهلك |
| أيقونات المعاني | أصول `assets/icons/` |

## 3) حدود التحقق

قارئ شاشة فعلي غير مفحوص (الأدوار الإعلانية مطبقة كسمات وفُحصت وجودًا وسلوك "دون تكرار" برمجيًا)، لا لمس حقيقي، لا متصفحات غير Chromium، وتوقيتات العابرة مفحوصة بمدى محدد في اللوحة.

# مواصفات الرسائل والحالات العامة — B06

الحالة: **STABLE UI** — الأوزان البصرية والحالات تتبع [UI-RELEASE](../../docs/UI-RELEASE.md)؛ النصوص أمثلة لا رسائل أعمال نهائية.

## 1) الأجزاء والعقد

| الجزء | العقد |
|---|---|
| `m-note` (help/info/success/warning/error) | رسالة ثابتة برمز المعنى ونصه — **لا تختفي ذاتيًا**؛ إغلاق يدوي اختياري؛ الإعلان (SUI-010): مساعدة `role=note`، معلومة/نجاح/تحذير `status`، **خطأ `alert` فقط** — الخطأ الثابت القابل للتصرف هو الذي يقاطع (إعلان واحد عند الظهور)؛ لا يرفع كل تحذير إلى alert بحكم الاسم |
| `m-toast` | **تأكيد غير حرج فقط** — عقد `MicroMessages.toast(el, {duration})`: مدة المستهلك (افتراض 4000ms)، إغلاق يدوي دائمًا، إعلان عبر القناة الحية الواحدة، **مع بديل ثابت إلزامي** بجانبها. الرسالة المهمة أو المطلوبة لتصحيح إدخال ليست Toast أبدًا. حاوية الـtoast توضع على مستوى التطبيق خارج أي وجهة مخفية (تركيب F03: SUI-001) كي يكون مستطيلها >0 دائمًا |
| `m-wait` | مؤشر + تسمية صريحة دائمًا؛ تقليل الحركة يجعله ثابتًا (الدلالة من التسمية) |
| `m-skeleton` | خفيف للشكل المقابل عند فائدته فقط — بلا تفاصيل مزيفة ولا لمعان عند تقليل الحركة |
| `m-empty` | ثلاث حالات مفهومة: لا بيانات (بدء) / لا نتائج (خطوة تصحيح) / فشل قراءة (إعادة محاولة المستهلك) — لا بيانات مالية مخترنة |
| `MicroMessages.announce` | إعلان بهوية الحدث (SUI-012 + SUI-R1-03): `announce(text, {id})` — الحدث ذاته (id نفسه والنص نفسه) يُعلن مرة واحدة داخل عمر الهوية؛ الحدث المستقل (id مختلف أو بلا id) يُعلن ولو تطابق النص. الوسيط الثاني يقبل المنطقي القديم (assertive) للتوافق الخلفي. سجل هوية محدود (انظر «عقد سجل هوية الإعلان» أدناه) |
| `MicroMessages.resetAnnouncements` | (SUI-R1-03) يمسح سجل هويات الإعلان — كل الأحداث بعده جديدة؛ لاستخدام المستهلك عند تغيير السياق أو الوجهة. لا يمس المنطقة الحية نفسها ولا التوست |

- الخطأ لا يمحو محتوى معروفًا بلا سبب (منطق الحفظ عند المستهلك — القاعدة موثقة ومطبقة في أمثلة B02/B06).
- لا مركز إشعارات ولا منطق retry شبكي داخل المكوّن (حدود التكليف).

### مراجع عقد الإعلان (SUI-010)

- [WCAG 2.2 — Status Messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): النجاح/المعلومة/التحذير قيد التقدم = `status` (polite) — يُعلن دون تحويل التركيز.
- [WAI-ARIA Alert Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alert/): الخطأ الثابت القابل للتصرف = `role=alert` — إعلان واحد عند الظهور؛ لا يُستعمل لمعلومة غير مهمة ولا يُعمم على كل تحذير بحكم الاسم.
- قناة واحدة لكل سياق: الرسالة الثابتة (m-note) قناتها دورها نفسه؛ الرسالة العابرة (toast) قناتها المنطقة الحية المشتركة — لا تكرار نص واحد بمسارين.

### عقد هوية الحدث في announce (SUI-012 + SUI-R1-03)

- **متى تمرر `id`:** عند احتمال إعادة إعلان الحدث نفسه (مثل إعادة إظهار تأكيد لطلب واحد بعينه من المصدر نفسه) — المرّة الثانية بنفس `id` والنص داخل عمر الهوية تُمنع.
- **متى لا تمرر `id`:** لكل حدث مستقل حتى لو تطابق النص (حذف عنصرين متتاليين بنص «تم حذف العنصر.») — كل فعل يعلن نتيجته (S28/S32).
- الاستدعاء بلا وسيط ثانٍ أو بالمنطقي القديم يبقى حدثًا مستقلًا — التوافق الخلفي محفوظ (فحص المستدعين بـgrep في جولة الإصلاح: لا مستدعي مباشر خارج المكوّن يعتمد المنع النصي).

#### عقد سجل هوية الإعلان (SUI-R1-03 — إغلاق «آخر إعلان فقط»)

- **السجل:** قائمة آخر **12** هوية معلنة فقط (كائن `{id, text, at}`) — آخر إعلان واحد لم يكن يمنع عودة الحدث ذاته بعد حدث مستقل (A ثم B ثم A كانت تعلن 3 مرات؛ العقد يستلزم 2).
- **عمر الهوية: 60000ms (60s):** إعادة الإعلان بنفس id والنص داخل العمر تُبتلع (لا إعلان)؛ بعد انتهاء العمر تصبح الهوية حدثًا جديدًا يُعلن. الزمن عبر `Date.now()` داخل الصفحة.
- **السعة: 12 هوية:** عند تسجيل هوية جديدة بعد امتلاء السجل تُقصى الأقدم — الهوية المقصية تصبح حدثًا جديدًا إن أُعيد إعلانها. الذاكرة محدودة دومًا (تنظيف كسول عند كل استدعاء: حذف المنتهية ثم الفائض).
- **id نفسه بنص مختلف:** حدث محدّث المحتوى — يُعلن ويحدّث نص الهوية المسجلة ووقتها.
- **بلا `id`:** يُعلن دائمًا (حدث مستقل) ولا يمس السجل أصلًا.
- **`resetAnnouncements()`:** يمسح السجل (كل الأحداث بعده جديدة) — لاستخدام المستهلك عند تغيير السياق/الوجهة؛ لا يمس المنطقة الحية نفسها.
- **حدود القياس:** عدّ «مرة واحدة» هنا قياس DOM بنيوي (MutationObserver على `.m-live-region`) — ليس إثبات صوت قارئ شاشة فعلي.

## 3) حدود التحقق

قارئ شاشة فعلي غير مفحوص (الأدوار الإعلانية مطبقة كسمات وفُحصت وجودًا وسلوك "دون تكرار" برمجيًا)، لا لمس حقيقي، لا متصفحات غير Chromium، وتوقيتات العابرة مفحوصة بمدى محدد في اللوحة.

## W2.2 — أدوار m-note الافتراضية من النوع (A2-F04 — D-UI-02 — إصلاح جذري 2026-10)

- عند `init` يضبط المكوّن دور أي `m-note` بلا دور صريح **من نوعه** وفق عقد SUI-010 نفسه: مساعدة `role=note`، معلومة/نجاح/تحذير `role=status`، خطأ `role=alert` فقط — لا يُعمم alert بحكم الاسم.
- الدور الصريح من المستهلك مالك دائمًا ولا يُداس؛ والترميز الناقص (لا نوع ولا دور) يُكشف بتحذير صريح في console لا بصمت (عقد D-UI-02: العقد الناقص يُكشف بالتحقق).
- حدود الدليل: مطابقة DOM/ARIA — الفحص السمعي بقارئ شاشة فعلي NOT RUN.

## W2.3 — قناتا الإعلان المنفصلتان (A2-F05 — إصلاح جذري 2026-10)

- `polite` و`assertive` قناتان منفصلتان (`.m-live-region` و`.m-live-region--assertive`) — لا تبديل aria-live على عقدة واحدة ولا جعل القناة عالمية لكل المستهلكين.
- **أُلغي المؤقت الثابت 50ms:** الكتابة متزامنة بالترتيب داخل كل قناة؛ إعادة إعلان النص ذاته في القناة نفسها (حدث مستقل بنص متطابق بلا id) تُدار بمسح ثم تعيين في إطار الرسم التالي (rAF) — أسرع ومرتبط بدورة العرض، ولا يُطغى النص الأحدث. أحداث burst المتزامنة تحفظ ترتيبها داخل كل قناة.
- عقد سجل الهوية (SUI-012/SUI-R1-03) كما هو دون تغيير.

## W2.5 — عقد init(root) الموحد (A2-F08)

- `MicroMessages.init(root)` يعالج الجذر نفسه إن طابق `.m-note` أو يحوي أهداف الربط، ثم الأبناء — نفس عقد init الموحد للعائلات.

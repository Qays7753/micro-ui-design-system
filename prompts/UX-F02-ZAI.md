## 2. المرحلة A — صحح الأخطاء الأربعة المحددة

- **F02-P01**: حالة تحديد الكل بلا خيارات مفعلة؛ صفّر checked/indeterminate عند التهيئة والتغيير، مع بقاء العناصر المعطلة محفوظة. لا observer أو API جديد.
- **F02-P02**: حراسة click في segmented تستعمل `isDisabled` كحراسة الأسهم؛ disabled وaria-disabled يمنعان تفعيل المؤشر وEnter/Space وإصدار حدث اختيار.
- **F02-P03**: ملخص فلاتر بشري موجز، يدعم `data-filter-label` اختياريًا أو تسمية مرتبطة، ثم fallback عددي آمن؛ لا مفاتيح داخلية أو «العدّاد يخفي 0» في النص. احتفظ بـevent.detail.applied/count وبسلوك draft/applied.
- **F02-P04**: أصلح وصف المنتقي المؤقت في §6 من specification.md إلى ربطه الفعلي بـB07.

المسموح لهذا الجزء: `components/selection/selection.js` و`components/navigation/navigation.js`، و`components/selection/specification.md` و`components/navigation/specification.md` لتوثيق التصحيح والتسمية الاختيارية. لا تعديل picker/core آخر أو CSS/tokens/assets أو الأدوار أو إعادة كتابة هذه الملفات من الصفر. اختبر القائمة الموجودة بعد كل إصلاح ذي صلة؛ لا تغيّر اختبارًا رجعيًا لمجرد أنه كشف خللًا. إذا كان اختبار قديم يفحص **العبارة التقنية المطلوب حذفها تحديدًا**، يسمح تصحيح هذا assertion وحده مع إظهار القديم/الجديد والسبب، لا حذف مسار الفحص.

## 3. المرحلة B — العينات الثلاث فقط

كل التفاصيل في بطاقة F02. المطلوب مصدر مستهلك بسيط قابل للاستبدال، دون framework/workflow engine:

1. **choice-lifecycle**: مجموعات native checkbox/radio وsegmented قصيرة منفصلة؛ منتقي قابل للبحث في B07، قراءة loading/ready/empty/error/no-results، اختيار محلي فوري ومسح، تحديث/زوال الاختيار، تجاهل رد قراءة قديم. إغلاق العرض لا يثبت إلغاء قراءة أو حفظ.
2. **filter-lifecycle**: قائمة محلية وsearch+checkboxes في لوحة B07؛ draft لا يغيّر applied/list/badge. تطبيق/مسح draft/إلغاء بكل الوسائل وإعادة فتح؛ count للشروط منفصل عن عدد النتائج؛ no-results مع تصحيح. لا API أو save وهمي.
3. **switch-lifecycle**: إعداد تركيبي مع confirmed/current/submitted attempt؛ تحديث واحد، saved/not-saved/unknown/checking، استرجاع عند رفض مؤكد فقط، تحقق لنفس المحاولة دون تحديث جديد، رد قديم لا يفسد الحالي. سياسة التركيز قبل تعطيل input وبعد إخفاء check محددة في البطاقة.

المستهلك يدير snapshots/IDs/guards/messages، والمكتبة تعرض وتحرس التحكم وفق عقدها. `change` و`rendered` وزوال pending لا تثبت حفظًا. لا toast لفشل أو نتيجة مجهولة. لا نجاح لون فقط، أو أخطاء مبكرة دون سبب.

أبقِ الرسائل موجزة؛ نصوص التشخيص/العدادات/أزرار السيناريو في **SIMULATION** منفصلة عن واجهة المستفيد. قناة إعلان واحدة لكل حدث، وفي نطاق الطبقة المفتوحة حين يلزم؛ لا تعلن داخل خلفية inert، ولا تضاعف role=status وannounce لنفس النتيجة. لا ادعاء قارئ شاشة فعلي من وجود attributes.

نفس IBM Plex/HugeIcons/RTL/0–9/الفاتح/24px/التحميل B/nمطَي A05 المعتمدين. هذه الدفعة لا تحتاج A05 أو charts أو شاشات منتج، فلا تضفها. لا تغيير tokens أو أنماط controls. CSS الجديد للتجميع والتركيب وحراسة hidden محليًا عند الحاجة، لا override للهوية.

## 4. المصدر القابل للتعديل — قائمة التسليم

في كل مسار من الثلاثة:

- `previews/ux-patterns/<name>/index.html`.
- `example.css`: التركيب فقط.
- `example.js`: سلوك المستهلك كاملًا؛ state واضح لا متغيرات DOM متضاربة.
- `mock-adapter.js` للاختيار والمفتاح فقط: واجهة ووعود/تسوية حتمية، لا شبكة أو تخزين. الفلاتر محلية فلا تضف mock بلا غرض.
- `README.md`: التشغيل، الهدف/الخارج، ثوابت البداية، مواضع تعديل البيانات/النصوص/السلوك/الموصل، جدول الحالات وسياسة الإغلاق والتركيز/الإعلان، UX IDs المستعملة، وحدود المحاكاة.

مصدر editable إلزامي: لا screenshot/PDF/build/ZIP وحده، ولا CSS/JS مضغوط بلا المصدر. بيانات البداية مصدر واحد لا قيم مكررة في HTML. تغيير fixture ينعكس في العرض والموصل والفحص دون إعادة إنشاء العينة. لا تغيّر defaultات مكونات UI من أجل السيناريو.

ملفات مشتركة لهذه الدفعة:

## 5. المرحلة C — التحقق الحقيقي

- افحص **32 صفًا كاملةً** بالسيناريو والنتيجة والقيمة والتركيز وعدد الدعوات. لا تستبدلها بعدد assertions كبير. FAIL/NOT RUN/NEEDS REVIEW حالات صادقة لا PASS.
- أفعال المستفيد بالنقر الفعلي/لوحة المفاتيح. خاصة aria-disabled: لا تقبل توقف Playwright تلقائيًا كدليل حراسة المكوّن؛ نفذ مؤشرًا حقيقيًا على الإحداثيات وEnter/Space حيث يلزم. DOM injection مقبول لبناء fixture، وليس بديلًا عن تفاعل المستفيد.
- اختر سيناريو الدعوة التالية ثم سوِّ الطلب حتميًا؛ لا نقر لوحة SIMULATION يفسد قياس التركيز. رد قديم يُفحص مع تسوية الحالي في الصفحة نفسها، لا reload يخفي تعليقًا.
- كل hidden: display/rect/Tab، كل تحديث اختيار: قيمة وعرض خارجي وsummary، كل filter: applied/list/count، كل switch: confirmed/submitted/current، لا text-only.
- المقاسات 320/360/390/430 لكل عينة؛ نص 200% بمضاعفة fontSize المحسوب وقياسه قبل/بعد (محاكاة معلنة، لا native zoom)، مع النص الطويل والحوار/رسالة unknown والفعل؛ reduced-motion عبر تفضيل فعلي. تمرير داخل جسم B07 مشروع إذا أبقى كل المحتوى والأفعال قابلة للوصول؛ لا تشترط عرضه كله دون تمرير.
- لقطات ready/error/empty/no-results وdraft/applied وصفر الشروط وpending/not-saved/unknown/checking، والحوار عند ضيق/200% حسب الحاجة. انتظر حالة انتقال مستقرة. اذكر اللقطات وما تثبته؛ الصور دليل لا المصدر.
- zero pageerrors وموارد 404 عبر التحميل والتفاعلات. فحوص رجعية `tools/b03-screenshots.py` و`tools/b07-screenshots.py` بسبب إصلاحات المصدر، و`tools/ux-f01-check.py --round f02-regression` بسبب الطبقات المشتركة. لا تكتب فوق أدلة F01 القديمة؛ اكتب نتائج الجولة تحت F02، باستعمال خيار output موجود أو wrapper/checkout فحص منفصل ونسخ النتائج المقصودة. تغيير وسيلة إخراج الفحص فقط موثق، لا توقعاته.
- إذا الفحوص القديمة تكتب أدلة UI في مكانها تلقائيًا، احتفظ بنسخة نظيفة المصدر، شغّل منها ثم احفظ السجلات المقصودة تحت F02؛ لا ترفع إعادة توليد عشوائية لكل المعرض. لا تغيير counts في وثائق إصدارات قديمة وكأنه اختبار جديد.
- WebKit/Safari والمنصات الحقيقية وTalkBack/VoiceOver/native zoom/keyboard/safe areas/back **NOT RUN حتى تُنفذ فعليًا**. تجربة غير متاحة تعطي سجل سبب؛ لا تقابل نجاح Chromium بنجاح كل المنصات. لا شهادة WCAG من هذه الدفعة.

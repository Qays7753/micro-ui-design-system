تحقق من رأس main الحالي ثم اعمل على فرع release/ui-professional الموجود وحده من main الموحّد؛ لا تنشئ فرعًا آخر. حافظ على العمل القائم، لا force-push، ولا merge أو نشر تلقائي. ارفع commits وافتح Draft PR واحدًا إلى main عند التسليم.

الألوان والصور المفهوميتان والفيديو ومصادر العائلات موجودة، والمسارات في handoff/ASSET-REGISTER.md. افتح المراجع المرئية المتعلقة بالتغيير فعليًا؛ صرح إن لم تستطع. حافظ على الهوية المعتمدة والمنحنيات والخطوط والأيقونات و24px/تحميلB، ولا تستنتج ألوانًا جديدة أو تنقل تصميم النظام القديم. أصلح A01/A02/A04 وT01، وقدم مقارنةA05 دون اعتماد ذاتي. راجع واكمل الحالات اللازمة للعائلات12 وقواعد التركيب والحركة والهاتف وأندرويد وiOS وفق التكليف؛ لا بناء شاشات أو UX/منطق أعمال أو backend.

سلّم المصدر الأساسي الكامل القابل للتعديل والتشغيل، وليس صورًا أو build فقط: المواصفات والعقود وtokens والأصول والأمثلة المستقلة وSOP وأدلة فعلية من مصدر نظيف وMANIFEST/ZIP محدثان. استخدم المصدر الحالي وأصلحه بدل إعادة البدء. حدّث handoff/WORK-TRACKER.md؛ لكل بند دليل أو حد صريح لا ادعاء نجاح. سجل الروابط والرؤوس والمصدر الذي ولّد اللقطات والنتائج وما لم تختبره. الحالة DRAFT FOR REVIEW حتى مراجعتنا.

## The Twisted Psychology Behind Top 1% Apps
- source: Tim Gabe · https://youtu.be/nQKWYmrixCU
- type: product-psychology
- tags: psychology, personalization, onboarding, paywall, retention, growth, conversion, copywriting

### Takeaways
- Products that feel made for one person often use no real personalisation tech: no interviews, recommender or custom model. Two psychological effects do the work instead.
- Effect 1, the Barnum (Forer) effect: a generic read, written to sound personal, feels like it was written about you. Forer showed it in 1948 (creator's claim, unverified).
- Effect 2, effort justification: the more effort people spend getting something, the more they value it, even when it is mediocre. Aronson and Mills showed it in 1959 (creator's claim, unverified).
- The creator admits that much of the "feel seen" output in these apps is "somewhat fake". The opening teasers (the month you'll meet your soulmate, your face rated out of 10) are not tied to a named app except Starcross.
- Pattern 1, "the mirror" (Starcross):
  - A long, demanding input phase comes before any result.
  - Then the app reveals a result that feels precise because the user worked for it.
  - The long quiz is not friction. It amplifies how much the result is valued.
- Onboarding rule from the mirror: the more a user invests before the reveal, the more the reveal feels worth it. The creator says this is why quiz-style onboarding is everywhere now (creator's claim, unverified). See "How To Solve The App Onboarding Paradox" below for where he limits this.
- Onboarding only gets people in the door. Whether they stay decides the business, and patterns 2 and 3 work on staying.
- Pattern 2, "the label" (16Personalities):
  - The quiz returns a four-letter code with a named archetype, e.g. INFJ "Defender", ENTP "Debater".
  - The description is flattering and specific-sounding but fits almost anyone.
  - Over a billion of these tests have been taken (creator's claim, unverified).
- Why labels retain: people put the label in dating bios, bring it up at work and use it to explain their feelings. Once adopted, a label becomes sticky. People see the world through it, defend it and return to whatever confirms it. If your product is part of how users describe themselves, leaving it means giving up part of their identity.
- How to build a label, three steps:
  1. Make it specific enough to feel earned.
  2. Make it flattering enough to want.
  3. Put it somewhere it can be shown off.
- Label forms the creator lists:
  - a type code (16Personalities)
  - a status, e.g. top percent of listeners
  - a role, e.g. speaker or expert
- Pattern 3, "the flex" (Airbuds), is the one the creator weights most. It retains the user and also turns them into an acquisition channel.
- Unlike the first two, the flex uses real data (the user's actual listening). The persuasion is in the packaging: a clean card that says something about the user's taste, which is what makes people post it.
- Make the share action and the growth action the same action. Airbuds locks the fuller recap behind inviting friends, so the selfish urge to share doubles as an invite. The creator says this is how it grows for free (creator's claim, unverified).
- Find the one thing your product already knows about the user that they would be proud to share, then wire sharing to growth. A referral programme attached to something nobody wants to show off does nothing.
- The same move elsewhere: Spotify Wrapped (yearly), Strava (a mileage map), Wordle (the grid of green and yellow squares in everyone's feed).
- Investor framing (Alexis Ohanian, paraphrased): music was never only about access. It is identity, a way of telling the world who you are.

### Recipes
1. Mirror flow, as narrated for Starcross [02:00–04:32] (screen order only; no visual values stated)
   1. Input screens ask for high-effort personal data before showing anything: birthday, exact time of birth, birth city, plus more personal details.
   2. A staged processing sequence names each step as it runs: generating, reading your chart, building your result. The loader copy says it is reading your stars.
   3. The result screen is specific and concrete: an exact month and year, a face drawing of the soulmate, and a full breakdown of who she is.
   4. The full reveal sits behind a paywall placed after the investment, when the user has sunk enough time to pay.
   5. Under the hood, per the app's FAQ: each soulmate attribute is picked from a few options pre-selected as compatible with the user. The result is assembled to fit, not revealed.
2. Label result screen, as narrated for 16Personalities [05:30–08:02]
   1. Quiz.
   2. Result headline: a short code plus a named archetype.
   3. Description written in a flattering, second-person, "rich inner life, high standards, hard on yourself" register, accurate for almost anyone.
   4. A place to display or claim the label.
3. Flex loop, as narrated for Airbuds [08:32–10:32]
   1. A small home-screen widget shows what friends are listening to.
   2. Every Sunday a recap of the user's top items arrives, like a weekly mini Spotify Wrapped.
   3. The recap is a clean, shareable card that makes a statement about taste.
   4. The fuller version of the recap unlocks only after inviting friends, so sharing = inviting.

### Gotchas
- Assuming "feeling seen" needs heavy data or AI. These apps get it from copy, effort and packaging.
- Cutting a quiz-style onboarding as "friction" when the effort is what makes the result valued (but see the next video's limits).
- A label too generic to feel earned, or not flattering enough to want, or with nowhere to show it off.
- A referral or share feature attached to something users aren't proud of.
- Share and invite as two separate actions; the creator's point is that they should be one.

### Examples named
- Starcross (name as heard in captions): soulmate app started from the founder's TikTok. Long birth-data intake, staged "reading your chart" loader, month/year plus face-drawing result, paywall after the investment.
- 16Personalities: four-letter type plus archetype label people adopt as identity.
- Airbuds: friends' listening widget, Sunday recap card, fuller recap gated behind invites. Investor Alexis Ohanian.
- Spotify Wrapped, Strava (mileage map), Wordle (green/yellow grid): the same share-as-proof-of-self move.
- Forer (1948) and Aronson & Mills (1959): the research cited (creator's claim, unverified).

## The Weird Design Playbook of 6 App Outliers
- source: Tim Gabe · https://youtu.be/HA4yB_sd62Q
- type: product-psychology
- tags: psychology, mobile, ios, ai, layout, colour, icons, accessibility, retention, habit, onboarding, growth

### Takeaways
- Note: the title says six outliers, but the video says four exceptions and covers four patterns. PictureThis (a precedent) and MyFitnessPal (the incumbent) also come up.
- Framing: after looking at more than 200 top-charting App Store apps, the creator says most are well-marketed copies of the category leader (creator's claim, unverified). The outliers flipped their category's design rule. He calls this "first principles design".
- Pattern 1, niche depth (Tiimo):
  - Every mainstream to-do app, whether Notion, Apple Reminders, Todoist or Microsoft To Do, assumes a task is a text row with a checkbox in a vertical list.
  - On the mass market you then compete on more list features, views, integrations and automations.
  - For a niche, the mass-market convention is usually a trap. An ADHD productivity app should look entirely different, not like Notion in another font.
  - The reason given: reading text rows is cheap for most people, but scanning a vertical list of strings takes focused attention, which ADHD users have less of (creator's claim, unverified).
  - Tiimo's move:
    - each task is a coloured, illustrated block on a vertical timeline
    - block size is weighted by task duration
    - custom icons come from a library of thousands
    - users see their schedule rather than read it
  - It won iPhone App of the Year 2025, and Apple's editors described it as a visual planner with well-implemented AI (creator's claim, unverified).
  - Why it's a moat: broad apps like Notion can't follow you into a niche interface without losing their mass audience. Win the niche by going deeper on the interface, not by adding features.
- Pattern 2, rebuild around the new technology (Cal AI):
  - The incumbent's logging path took 4–5 steps per meal, and every competitor copied it while competing on features and database size.
  - Cal AI made the camera the home screen. The first action is taking a photo. AI identifies the food, estimates the portion and writes the entry.
  - Correcting the entry is the exception path, not the main path.
  - The question behind the rebuild: what does this technology let us do that we couldn't before?
  - Business context: Cal AI was sold to MyFitnessPal, and the team's second app reached over $300,000 MRR within months (creator's claim, unverified).
- The same principle predates the current AI wave: PictureThis (2017) used image classification for plants. Point the camera and it names the plant (creator's claim, unverified).
- Rule: when a new technology lands (AI vision, voice, ambient compute), rebuild the interface primitives around it rather than adding it to the old UI as a feature. Adding a feature ships a feature; resetting the primitives can define a category.
- Pattern 3, no-shame tracking (MacroFactor):
  - The category assumed shame drives compliance: red numbers when over target, broken streaks after a skipped day, push notifications about missed goals.
  - MacroFactor expects users to miss targets and designs for it.
  - It combines actual logs with a trend weight smoothed over about 3 weeks to back-calculate the user's real metabolism, then adjusts targets.
  - Co-founder Greg Nuckols framed it as asking what nutrition apps would be like if they didn't try to guilt people into losing weight.
  - Business context: bootstrapped, from the Stronger by Science team, $72 a year, about 500,000 users at recording (creator's claim, unverified).
- Every category holds an unspoken assumption about its user. Ask whether it is true, and build for who the user really is.
- The moat of no-shame tracking is trustworthy data. Users who aren't shamed don't fudge their logs. MyFitnessPal's user-submitted database is said to be full of bad data from people gaming their own logs (creator's claim, unverified).
- Pattern 4, synchronised ritual (Ladder):
  - Workout apps assume motivation is solo, with maybe an optional leaderboard.
  - Ladder pins every member of a team to the same workout on the same day: about 5,000 strangers doing the same set at the same hour (creator's claim, unverified).
  - Acquisition was a TikTok-to-quiz funnel. Retention came from the cohort calendar: skipping becomes visible to the cohort, so it is a social failure, not just a personal one.
  - The CEO, Greg Stewart, said on the Sub Club podcast that they hit 500% growth. Ladder was an App of the Year 2025 finalist (creator's claim, unverified).
- Rule: where you can, turn solo interface moments into shared ones. Ladder's social pressure lives in the workflow itself, not in a separate motivational feature.
- Meta-pattern: Tiimo removed the text row, Cal AI removed manual entry, MacroFactor removed shame and Ladder added shared timing. Each one inverted the category's default rather than iterating on it.

### Recipes
1. Duration-weighted visual timeline, as narrated for Tiimo [02:05–03:07] (no sizes, colours or icon specs stated)
   1. Replace the list of text rows with a vertical timeline.
   2. Render each task as a block with its own colour and an illustrated icon (picked from a large icon library).
   3. Size each block by the task's duration, so time is read by height.
   4. Let the picture carry the meaning; text is secondary.
2. Camera-first logging, as narrated for Cal AI [04:40–06:12]
   1. Home screen = live camera; the primary action is the shutter.
   2. After the photo, AI identifies the food, estimates the portion and creates the entry automatically.
   3. Editing or correcting the entry is a secondary path after the auto-entry, not the way in.
   4. Old path being replaced (MyFitnessPal): Add food → search field → scroll results → select → confirm (4–5 steps).
3. No-shame tracking states, as narrated for MacroFactor [07:15–09:22]
   1. Remove these states: red over-target numbers, broken-streak indicators, "you missed your goal" push notifications.
   2. Treat a missed target as expected input, not an error state.
   3. Show a smoothed trend weight (about a 3-week average) rather than letting a single day's number drive the feedback.
   4. Recalculate targets from logged intake and the trend, and present them as adjustments.
4. Cohort ritual, as narrated for Ladder [09:53–11:25]
   1. Assign each member to a team that does the same workout on the same day.
   2. Give the team a shared cohort calendar.
   3. Make each member's attendance or absence visible to the cohort.
   4. Acquisition sits upstream: TikTok → quiz → app.

### Gotchas
- Copying the category leader's interface shape and competing on feature count.
- Building a niche app as the mass-market app with a new skin (e.g. Notion in a different font for ADHD users).
- Adding new technology to the old UI (a camera button on a search-first logger) instead of rebuilding the primary action around it.
- Designing guilt states (red overages, broken streaks, missed-goal pushes). Per the creator they also corrupt the data, because users game their logs.
- Treating a habit app's core moment as solitary when it could be shared.

### Examples named
- Tiimo (Copenhagen; iPhone App of the Year 2025 per creator): colour-and-icon blocks on a vertical timeline, sized by duration; first aimed at neurodivergent users.
- Notion, Apple Reminders, Todoist, Microsoft To Do: the text-row-plus-checkbox convention.
- Cal AI: camera as the home screen, AI writes the entry, correction is secondary; sold to MyFitnessPal (per creator).
- MyFitnessPal: the incumbent's 4–5 step manual logging path; user-submitted database described as unreliable.
- PictureThis (2017): camera-first plant identification, an earlier "rebuild around the tech" case.
- MacroFactor (Stronger by Science; co-founder Greg Nuckols): no-shame tracking, 3-week smoothed trend weight, adaptive targets.
- Ladder (CEO Greg Stewart; Sub Club podcast): same workout, same day, team cohort calendar; TikTok → quiz funnel.

## Why Leaderboards Kill App Retention (How To Fix It)
- source: Tim Gabe · https://youtu.be/BxhsCu9hNpY
- type: product-psychology
- tags: gamification, retention, psychology, habit, states, mobile

### Takeaways
- Typical retention advice pushes features, notifications and streaks. The creator argues that apps which keep users for years build a feeling instead: being in a race, either climbing or falling behind. He calls it the "invisible scoreboard".
- The leaderboard is only the surface; social comparison is the engine underneath. Shipped as a nice-to-have, a leaderboard is just a glorified list, and lists don't move retention. That is the sense of "kill" in the title.
- Invisible scoreboard definition: the product makes another user's progress feel like a race you are in.
- Move 1, put the comparison at the moment of completion. Whatever completion means in your app (end of a workout, a transaction, a listen), show right then whether the user is ahead or falling behind.
- Who sits on the other side of the comparison changes how it lands. Chasing a world-record holder feels different from chasing a neighbour.
- Move 2, localise the cohort (Strava):
  - Strava's core loop is segments: public leaderboards for specific stretches of road or trail. Rankings appear as soon as a ride ends.
  - Ranking isn't only global. Users can rank against their neighbourhood, their friends, or the dozen riders who rode the same hill in their city.
  - A global board feels unwinnable, so most people stop trying. A local board feels winnable, so they keep coming back.
  - Rule of thumb: cohort size is the lever. Shrink it until winning feels possible.
  - Strava has more than 100 million athletes (creator's claim, unverified).
- Move 3, design a recognition moment (Peloton):
  - Peloton kept people paying $44 a month for years, and the creator credits the instructors rather than the bike (creator's claim, unverified).
  - Instructors became celebrities. During live classes riders watched the live leaderboard while instructors called out riders' names in front of thousands.
  - The lesson isn't to hire instructors. The leaderboard creates the race, and the human call-out is the emotional hit of recognition that makes people push.
  - Most apps can't do live shout-outs. They can still design a moment that acknowledges effort in a social, emotional way rather than a mechanical one.
- Summary of the three moves:
  1. Comparison at completion.
  2. A cohort small enough to win.
  3. Human-feeling recognition of progress and effort.

### Recipes
1. Completion screen with an invisible scoreboard [01:02–02:04, 04:09–04:39] (no layout values stated; structure derived from the narration)
   1. Trigger the screen at the end of the core action: a workout, a transaction or a listen.
   2. Lead with the comparison: the user's rank against a named cohort, with a clear "climbing" or "falling behind" state.
   3. Default the cohort to the smallest scope where a win is realistic (derived from his "shrink until winning feels possible" rule).
   4. Add a recognition element that names the user and their effort socially (Peloton's live call-out as the model), not a generic badge.
2. Cohort scope switcher, as narrated for Strava [02:04–03:06]
   1. Leaderboards are tied to a specific place or segment.
   2. Offer scopes from widest to narrowest: global → city/neighbourhood → friends → people who did this exact segment.
   3. Rankings appear immediately after the activity finishes.

### Gotchas
- Shipping a leaderboard as a feature without the social-comparison psychology; it becomes a list nobody returns to.
- Defaulting to one global board, which feels unwinnable for almost everyone.
- Comparisons that appear somewhere other than the completion moment, when the user isn't looking.
- Recognition that feels mechanical (an automated badge) rather than social and human.

### Examples named
- Strava: segment leaderboards shown right after a ride; global, neighbourhood, friend and same-hill cohorts.
- Peloton: live class leaderboard plus instructors calling out riders by name; subscription kept for years.

## How Top 1% Indie Apps Beats Giants
- source: Tim Gabe · https://youtu.be/MAvKHToGiVY
- type: product-psychology
- tags: psychology, retention, habit, gamification, copywriting, imagery, animation, micro-interaction, states

### Takeaways
- Context: AI is generating apps faster than ever. The creator says iOS releases jumped 80% year over year in Q1, and gives a second figure ("almost 90%") that is garbled in the captions (creator's claim, unverified). Three apps that are about a decade old survive by building experiences, not screens.
- Most products have at least one screen where users read numbers, and most stop at showing the data. The survivors made the data secondary to how it feels.
- Pattern 1, the human pattern (Carrot Weather):
  - The trap is adding personality at the edges: a friendly empty state, confetti on first save, a mascot on the loading screen. That is decoration. The core surface is still the same chart, number row, list or table as every competitor.
  - Carrot was a paid app competing with Apple's free, pre-installed weather app. It ran on practically the same forecast data and sources.
  - The forecast's headline is a character reacting to the actual weather, with custom poses, scenery and dialogue. The numbers are still there, but secondary.
  - Examples of the character's reactions: in a heatwave it sweats and calls the user "meatbag". In the cold it is bundled up against a frozen backdrop, threatening that you dress warmer or die.
  - You know how the weather feels before reading a number.
  - Business context: solo developer Brian Mueller, launched 2013, ran it as an indie business for over a decade. Apple Design Award 2021 for Interaction (creator's claim, unverified).
- Rule: sometimes the data isn't the product; the way you deliver it is. A genuine personality at the core is hard to copy quickly, and it compounds with brand voice over years.
- The limit of the human pattern: when the user is mid-task on something hard (focus, fitness, habits), a witty reaction isn't what helps. Stakes are.
- Pattern 2, the behaviour pattern (Forest):
  - You start a session (the example is 25 minutes not on your phone) and a small virtual tree begins growing. Leave the app to scroll Instagram and the tree dies.
  - The whole session screen is a tree, a timer and a tag for what you're focusing on.
  - The tree is the only moving element, breathing slowly as the minutes pass. The timer is there but secondary.
  - The urge shifts from "I should focus" to not wanting to be the one who killed the tree.
  - Coins earned in the app led to more than 2 million real trees being planted (creator's claim, unverified).
- Rule: for a behaviour you want to last, don't just track it. Make skipping it cost something the user notices.
- Forms a stake can take, per the creator:
  - a visible stake
  - a streak that breaks
  - a status that drops
  - a story that pauses
  - a relationship that fades
- Recap phrasing: put the stake on screen, not the metric.
- Pattern 3, the craft pattern (Day One), which the creator calls the hardest and the biggest long-term moat:
  - The data layer, typed journal text, is commoditised. Apple Notes and Apple Journal are free and pre-installed, yet Day One charges a subscription and thrives.
  - It didn't change where journaling lives. It enriched what surrounds the text:
    - auto-captured weather
    - location pinned on a map
    - photos embedded in the entry
    - a day-by-day timeline across years
    - polished search across everything written
  - The analogy: a basic IKEA notebook versus a Moleskine (back pocket, elastic band, ribbon bookmark, paper weight). Both hold the same text, but the sensory experience differs.
  - Business context: Paul Mayne and Bloom Built won the 2014 Apple Design Award in the Mac category, alongside Monument Valley on iOS. Rated 4.8 stars from over 116,000 reviews (the intro says "over 100,000") and still updated monthly (creator's claim, unverified).
- Craft is the work users won't see but will feel: animation timing, font weight, metadata appearing in the right place at the right time. Features can be copied; years of compounding small decisions can't.
- Meta-rule: apps that survive the AI era build experiences, not screens.

### Recipes
1. Data delivered through a character, as narrated for Carrot Weather [02:33–03:34] (no art or type specs stated)
   1. The primary element is an illustrated character whose pose, scenery and dialogue are chosen by the live data (e.g. heatwave vs cold).
   2. The dialogue uses a consistent, irreverent brand voice.
   3. The raw numbers stay on screen but rank below the character.
2. Stake-based session screen, as narrated for Forest [04:36–05:38]
   1. Show three elements only: the growing tree (hero), the timer (secondary) and a focus tag.
   2. The tree is the only animated element, with a slow breathing loop.
   3. Leaving the app during a session switches the tree to a dead state.
   4. Completing sessions earns in-app coins, which tie to planting real trees.
3. Enriched entry, as narrated for Day One [07:14–08:18]
   1. Around the plain entry text, auto-attach metadata: weather and location (with a map pin).
   2. Embed photos inline in the entry.
   3. Provide a day-by-day timeline view of past years and full search across entries.

### Gotchas
- Personality as decoration (confetti, a cute loading mascot, a friendly empty state) while the core surface stays a generic chart or table.
- A witty reaction in a mid-task moment that needs stakes.
- A timer or metric as the hero of a habit or focus screen, with no visible stake.
- Competing on the commoditised data layer instead of enriching what surrounds it.

### Examples named
- Carrot Weather (Brian Mueller): a character's reaction to the forecast is the forecast; paid app beating a free default.
- Apple Weather: the free, pre-installed default with the same data.
- Forest: a tree that grows while you focus and dies if you leave; real trees planted from coins.
- Day One (Paul Mayne, Bloom Built): journal text wrapped in weather, map, photos, timeline and search.

- Monument Valley: the iOS winner in the same 2014 Apple Design Award year.

## How To Solve The App Onboarding Paradox
- source: Tim Gabe · https://youtu.be/Aa89MC8jX2c
- type: product-psychology
- tags: onboarding, retention, conversion, personalization, psychology, paywall, mobile

### Takeaways
- Opening claim: on average, apps lose 77% of users within 3 days (garbled in the captions), and a single onboarding choice is a main lever (creator's claim, unverified).
- Most apps onboard like a government form: sign-up screens, permission requests and walkthroughs. By the time users can do anything, they have clicked through screens unrelated to the product's value.
- If the product doesn't depend heavily on personalisation, the fix isn't more onboarding. It's onboarding that does work for the user, not data collection for you.
- Short-onboarding model (Granola, an AI notes app):
  - Screen 1: sign in with Google.
  - Screen 2: grant microphone access.
  - Then the user simply opens Granola in their next meeting. It records, transcribes and summarises, so value lands inside something the user was already going to do.
  - Many AI productivity apps instead run sign-up, then a feature tour, then a goals wizard. Granola skips all of it.
  - Granola raised $125 million in March 2026 at a $1.5 billion valuation, six times its value 12 months earlier (creator's claim, unverified).
- The paradox: some of the fastest-growing apps have very long onboarding:
  - Cal AI: a 20-plus-step quiz before you see the product, and $35 million revenue in year one (creator's claim, unverified).
  - Noom: 113 onboarding screens (creator's claim, unverified).
- Long onboarding works when it does two jobs at once:
  1. It earns a personalised first experience. Without the answers, Cal AI's first home screen would feel as generic as every other calorie tracker. You trade speed for a first screen built for that user.
  2. It filters for buyers. People who drop out of a 20-step quiz were less likely to convert anyway. Finishers signal deep pain and willingness to pay.
- Calorie tracking qualifies because it is a deep-pain niche where personalisation matters. The quiz both qualifies the buyer and builds the aha moment.
- The rule:
  - Default: keep onboarding as short as possible, or better, surface tangible value as fast as possible.
  - Exception: go long only when the length buys something users need in order to stick, either a first experience that can't be personalised without the data, or a filter that finds real buyers.
- How this squares with "The Twisted Psychology Behind Top 1% Apps" above: effort before the reveal raises perceived value, but it only pays off when the data feeds a personalised result or qualifies buyers. Otherwise short wins.

### Recipes
1. Two-screen onboarding, as narrated for Granola [01:02–02:06]
   1. Screen 1: a single sign-in option (Sign in with Google).
   2. Screen 2: the one permission the core feature needs (microphone).
   3. No feature tour, no goals wizard. The first value moment is the user's next real use (the next meeting).
2. Onboarding-length decision [02:06–04:10]
   1. Ask: will the first home screen feel generic without user data? If yes, a longer quiz can earn a personalised first screen.
   2. Ask: is this a deep-pain niche where finishing a long quiz signals willingness to pay? If yes, length doubles as a buyer filter.
   3. If neither is true, cut to the minimum screens and the fastest route to real value.
   4. If going long, every question should visibly feed the first personalised screen (derived from his "earns a personalised first experience" point).

### Gotchas
- Front-loading sign-up, permission prompts and walkthroughs that don't relate to the product's value.
- Responding to poor retention by adding more onboarding when the product isn't personalisation-led.
- Copying a long quiz from Cal AI or Noom without the personalisation or buyer-filter payoff that justifies it.
- Asking for permissions the core action doesn't need yet. Granola asks only for the microphone.

### Examples named
- Granola: two-screen onboarding (Google sign-in, microphone), with value in the next meeting.
- Cal AI: a 20-plus-step quiz that personalises the first screen and filters buyers.
- Noom: 113-screen onboarding.
- AI productivity apps in general: the sign-up → feature tour → goals wizard pattern to avoid.

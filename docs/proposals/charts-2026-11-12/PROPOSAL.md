## الاتجاه المقترح

قراءة رقمية واضحة، رسم صغير وظيفي، وتفاصيل عند الحاجة. لا مجسمات أو حلقات كبيرة لكل قيمة أو دوائر يصعب مقارنة مساحاتها. الألوان والخطوط والتوكنز من المصدر الحالي، دون تعديل قيمها. زر السياق المختار يستعمل متغير Buttons primary الحالي؛ غير المختار secondary، دون إصلاح مظهر المكوّن العام بقاعدة خاصة.

| الاستخدام | المقترح | لماذا يناسب العمل الصغير؟ |
|---|---|---|
| متابعة أيام فعلية | أعمدة صغيرة، وبديل خط مستقيم، مع قراءة اليوم المحدد خارج الرسم وجدول كامل. | معرفة المبلغ وتغيره بسرعة، مع بقاء الوصول لكل يوم. |
| مقارنة الأصناف/المبالغ | صفوف بأرقام كاملة وأشرطة أفقية بمقياس واحد للوحدة والفترة المتوافقتين. | مقارنة أسماء عربية طويلة وقيم دقيقة داخل حاوية الهاتف. |
| قيم موجبة وسالبة وصفر | أشرطة حول صفر مشترك؛ الرقم الموقّع مكتوب دائمًا. | فصل البيع/المرتجع في المثال دون اعتبار السالب خطأ أو تحويله إلى موجب. |
| توزيع مجموع معلوم | حلقة صغيرة بجانب الإجمالي، وقائمة مبالغ قابلة للاختيار؛ النسبة للفئة المختارة ثانوية. | تقليل مساحة الدائرة وإبقاء المبالغ أساس القرار. |
| تحصيل من قيمة معلنة | المبلغ المحصّل والقيمة الكاملة والمتبقي، وشريط تقدم خفيف. | معرفة كم تحصّل وكم بقي؛ النسبة تصف هذه العلاقة فقط. |

النموذج ليس شاشة منتج أو اقتراح مسارات/صلاحيات/تدفق مالي جديد. «النشاط/المقارنة/التوزيع» أدوات مراجعة لسياقات المكونات فقط. لا نقر على الصف كله دون فعل معلن أو إجراءات تشغيلية وهمية. الخط الزمني/Steps والإجراءات والحقول وباقي العائلات خارج إعادة تصميم الرسوم الحالية وتبقى حسب العقود الموجودة.

## البيانات والصدق

**الأرقام قيم مطلقة ببيانات توضيحية صريحة، وليست سجلات حقيقية من Micro.** لم يُقرأ أو يُخمن أي مصدر إنتاجي. الأمثلة عامة وليست حصرًا لنوع مشروع واحد.

- الأيام السبعة6–12 نوفمبر2026 لها قيم معلنة منفردة:580،720،640،810،690،560،820 د.أ. المجموع4,820. الأسبوع السابق4,180 معلن مستقل؛ الفرق+640، بلا نسبة. لم تُولد أيام من مجموع فترة أو عشوائية.
- الأصناف36/24/18 قطعة؛ الأرصدة820+460+280=1,560 د.أ؛ والمقبوض3,120 والمدفوع2,480 والفرق640. الفرق النقدي لا يُسمى ربحًا.
- المصروفات600+360+180+120=1,260.48% و29% قيم مقربة لحصص فئتين مختارتين، مع مبالغهما الدقيقة. النسبة لا تستبدل القراءة المالية.
- التحصيل1,260 من1,800، المتبقي540 و70%. عينة التجاوز2,340 تعرض130% وزيادة540؛ امتلاء الشريط لا يخفي الزيادة العددية. الهدف المجهول أو الصفر لا ينتج نسبة.
- المفقود يقطع الخط ويجعل إجمالي الفترة غير متاح بدل تمرير مجموع جزئي كأنه كامل. الصفر معروف ومختلف. القيمة السالبة تحت خط الصفر. الرقم الطويل كامل دون تصغير قسري؛ فرص كسر السطر عند فواصل التجميع تبقي الجزء العشري متصلًا ما أمكن.

التحقق التجريبي بهذه العينات ليس التزامًا أن المكوّن سيحسب إجماليات أو قواعد مالية لاحقًا. الأرقام والوحدات والفترات والبيانات المجمعة مسؤولية المستهلك؛ عقد المصدر النهائي يُحسم بعد الموافقة.

## قرارات تحتاج موافقة قبل التنفيذ

1. اعتماد هذا الاتجاه البصري وكثافته، مع الأعمدة/الصفوف للأغلب والحلقة الصغيرة عند معنى الحصة.
2. **طريقة قراءة الرسم المضغوط:** المقترح يستعمل قراءة نقطة مختارة وجدولًا كاملًا بدل طباعة كل قيمة فوق كل علامة. هذا يختلف عن عقد bars الحالي الذي يلزم القيمة فوق العمود؛ لن يتغير الافتراض الحالي صامتًا. يمكن اعتماده كمتغير compact اختياري مع بقاء العرض الحالي.
3. **اتجاه الزمن:** النموذج يختار LTR صراحة داخل RTL، دون قلب الزمن عند تبديل لغة الواجهة. مصدر line الحالي يملك data-axis-dir وافتراضًا آخر؛ هذا قرار للمتغير المقترح وليس تغييرًا منفذًا لافتراض المصدر.
4. اعتماد التحديد العام باللمس/المفاتيح والعرض الرقمي الثابت بدل tooltip عائم صغير. نموذج الاختيار يستعمل تحكم range أصليًا وهدف رسم كبير وزرين48px؛ API المكتبة والتنظيف والمزامنة يحتاجان تصميمًا واختبارات بعد الموافقة.
5. إبقاء الخيارات المتخصصة خارج العرض الافتراضي الدقيق دون حذفها؛ إذا أريد حذف/إهمال متغير قديم فهذا قرار توافق منفصل.

عند الموافقة: تفصيل العقد العام المتوافق، تنفيذ تدريجي في المصدر الصحيح على الفرع نفسه، تحديث المواصفات/الكتالوج/الأمثلة/standalone عند الحاجة، واختبارات مصدر/دورة حياة/تفاعل وبوابات Light. لا يبدأ تنفيذ هذه الخطوات من موافقة عرض المقترح وحدها.

## ما تحقق الآن وما لم يتحقق

الفحص المركّز `python3 tools/chart-proposal-check.py --out OUT` يختبر المقترح فقط: **48 نجاح/0 إخفاق**، بنتائج وبصمات المصدر في [verification.json](verification.json). الفحص الساكن الحالي282 نجاح/0 إخفاق، وملف المقترح المولد والكتالوج وstandalone المكتبة مطابقة حتميًا، وMANIFEST مولّد ومطابق. يقيس فحص النموذج الأهداف والقراءات والفيض/التداخل، اختيار اليوم بالمؤشر ولوحة المفاتيح، الفجوة والصفر والسالب والرقم الطويل، اختيار الفئة، حالات المقام والتجاوز، وتبديل السياق مع hover والتركيز. كشف الفحص البصري أثناء إعداد المقترح تعارض hover في CSS التبويب المحلي؛ صُحح باستعمال متغير Buttons الصحيح، دون تعديل المصدر أو تغيير التوكنز.

المقاس الأساسي360×780 RTL Light DPR1؛320 للرقم الطويل فقط وLTR لاتجاه المحور. مراجعة اللقطات فعلية. الملف المولد فُحص عبر HTTP دون طلب موارد شبكة إضافية. تجربة file:// حُجبت بسياسة المتصفح الإدارية `ERR_BLOCKED_BY_ADMINISTRATOR`؛ لم تُتجاوز السياسة ولم ندّع اختبار فتح الملف محليًا. لا iOS/Android فعلي أو WebKit/Safari أو قارئ شاشة/لوحة نظام، ولا Dark أو zoom أو مصفوفة واسعة.

لا نعيد عداد588 للمرحلة5 كأنه تشغيل جديد أو قبول للمقترح؛ لم تتغير مصادر المكونات أو الأصول. نجاح اختبارات النموذج لا يجعله مكوّنًا جاهزًا للإنتاج أو مثبت التركيب داخل Micro. **التوقف للمراجعة البصرية قبل تنفيذ المصدر.**

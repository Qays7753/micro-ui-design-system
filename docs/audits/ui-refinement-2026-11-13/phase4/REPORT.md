# المرحلة4 — Ask Micro وأزرار الرد والنشاط

البداية05f3f98، فرع Feature نفسه. امتداد UI فقط دون AI/backend أو هوية بديلة.

## التنفيذ

actions داخل رسالة assistant: متابعة، طلب عرض مورد، وطلب تنفيذ بعد مراجعة وتأكيد. payload معرفات ورسالة ونسخة؛ لا URL أو كود أو صلاحية ضمنية. رفض المعرفات المكررة/الأنواع غير الصالحة، وتعطيل الاقتراح المنتهي والمكتمل وغير المتاح مع سبب. replace/تبديل السياق يبطلان التأكيد والطلب.

مؤشر نشاط مستقل بجانب عبارة واحدة صادقة؛ بحث فقط عند activity=searching وreplyPending. رمز Micro v2 ثابت دون تعديل الأصل، مع المساحة الخالية الموثقة. لا mascot أو3D. هذا اتجاه بصري للمراجعة، لا ترقية نضج.

الكاتب يبدأ52px وينمو حتى156px ثم تمرير، والإرسال بجواره. بقيت الأبعاد القياسية؛ لم يصغر الخط أو اللمس. proposal القديم مدعوم قبل الكاتب، ولا يحتاج المستهلك إلى تحويل فوري. أضيفت حالات actions/searching/expired-actions للمختبر نفسه.

## الدليل والنتيجة

assistant-actions-check.py: **24 نجاح/0 إخفاق**. يغطي grants والتأكيد والإلغاء وتغيّر النسخة والسياق، وتعطيل المنتهي وعدم تكرار الطلب، وحقن النص كنص فقط، والنشاط وتقليل الحركة، والكاتب الطويل، وعرض320 عند التفاف الأزرار. الصور ask-actions360 وask-searching360 في evidence؛ راجعت مواضع الأزرار وحضور الشعار والمؤشر بصريًا، مع بقاء اعتماد المستخدم النهائي مفتوحًا.

التبعيات الحالية product-core/buttons/fields/messages/navigation/action-sheet ومؤشر CSS من التوكنز، وشعارv2 الأصلي. backend يجب أن يطابق المعرفات والسياق والنسخة والصلاحية؛ اقتراح المساعد ليس تفويضًا. لا تنفيذ فعلي أو أثر مالي أو اختبار هاتف فعلي.

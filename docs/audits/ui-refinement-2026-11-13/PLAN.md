## قواعد القبول

- Light وعربي RTL والهاتف أولًا، مرجع360×780 CSS px؛320 عند ضيق مثبت وLTR عند تأثير الاتجاه. لا نسخة منفصلة لكل عرض ولا مصفوفة واسعة أو zoom جديد.
- أحجام اللمس وفق العقد48 حيث ينطبق، الحقول52 حد أدنى؛ الرسم المرئي لا يجب أن يملأ مساحة اللمس. لا تغيير توكنز لحل تركيب ضعيف.
- المعلومات المرتبطة مجموعة واحدة، والتباعد بين المجموعات أوضح من داخلها؛ كل بطاقة أو إطار أو ظل له وظيفة. لا تحويل جميع الشاشات إلى جداول.
- الرقم والوحدة والفترة واضحون؛ لا قص أو اختصارات مبهمة. نسبة فقط حيث تعبر عن معنى فعلي. لا إزالة عملة تسبب التباس المبلغ مع العدد.
- النص يساعد على فهم القيمة أو الإجراء أو تجنب الخطأ. التفاصيل التقنية في التوثيق. تبقى عاقبة الإجراء والمنع وعدم التأكد ظاهرة عند الحاجة.
- الصور والمعاينة والملفات الفاشلة والفراغ والخطأ والتحميل والنجاح والرفض والتعطيل والجلسة والاتصال والصلاحيات المنقوصة ضمن الحالات ذات الصلة؛ لا فرض كل حالة على مكوّن لا ينطبق عليه معناها.
- ضغط وتركيز ولوحة مفاتيح وتقليل حركة؛ لا حركة زخرفية مستمرة أو progress وهمي أو swipe حساس. متصفح Chromium ليس اختبار S25 Chrome فعليًا.

## سياق المنتج الثابت

Micro تطبيق واحد بحساب مشترك: Manage وMarket وDelivery وAsk. البيانات والصلاحيات حسب الدور وWorkspace؛ الأدوار لا تُدمج تلقائيًا. سياق السائق Delivery/Ask فقط. المراجعة لا تمنح بيانات Manage المالية. لا أثر مالي تلقائي لـMarket/Delivery. المكتبة لا تحل محل تحقق الخادم. لا قواعد تجارية مخترعة لمهل العروض أو موافقة التعديلات أو الإثبات.

Ask المطلوب: أزرار متابعة، عرض/تنقل، وتغيير بيانات بتأكيد. تربط بالرسالة والسياق والمعرّف والنسخة؛ انتظار ومنع تكرار ونجاح وفشل وإبطال اقتراح قديم. لا تنفيذ كود مولد ولا منح صلاحية من الرسالة. النسخة الحالية لا تحقق ذلك كاملًا بعد.

الهوية: v2 وIBM Plex والألوان والتوكنز الحالية. قواعد assets/brand/micro-logo/USAGE.md لا تسمح مؤثرات لأجزاء الشعار. اقتراح Ask مؤشر منفصل هادئ وحالة صادقة؛ «بحث» فقط عند بحث فعلي. الشخصية المستقلة/3D أو تغيير الشعار يحتاج اعتمادًا منفصلًا، ولم يُنفذ. المرجع Claude Code إلهام للحضور الوظيفي؛ لم تُنفذ مقارنة مباشرة حديثة ولا نسخ هويته.

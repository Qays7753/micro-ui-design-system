أُعيد تشغيل **اختبارات العزل نفسها** بمصدر navigation.js من commit البداية للقراءة فقط: **10 نجاح/4 إخفاق**، موثقة في [الدليل قبل الإصلاح](before-isolation-verification.json). الإخفاقات الأربع مظاهر للعيب الواحد: الشقيق الجديد، قدرته على أخذ التركيز، دورة فتح ثانية، وشقيق داخل سلف متداخل. لا تبديل فرع أو تعديل توقعات لقبول الفشل.

الإصلاح في [navigation.js](../../../components/navigation/navigation.js) ومواصفته فقط من مصادر المكونات. المراقب لا يتابع السمات، ولا يعالج تحديثات النص داخل الطبقة أو محتوى الشقيق المعزول بإعادة عزل غير لازمة. يبقى استثناء live-region/toast، وinert السابقة، وتكديس الطبقات، وقفل التمرير واستعادة التركيز. يطبّق العزل الجديد عند تسليم MutationObserver؛ ليس اعتراضًا متزامنًا لكل كتابة DOM. يظل disconnect قبل إزالة الجذر واجب المستهلك.

أُعيد توليد standalone حتميًا من المصدر، واختُبر العيب والإصلاح داخل JavaScript المضمّن فيه أيضًا. الكتالوج لم يحتج تغييرًا؛ العائلات14 والمتغيرات6 والتراكيب3 ونضجها باقية. **207 ملفات assets/shared و36 من37 ملفات CSS/JS المكونات السابقة مطابقة للبداية**؛ الفرق التشغيلي الوحيد navigation.js. لا تغيير شعار أو خط أو قيمة لون أو توكن.

## الحدود والقرارات الباقية

- أثبتنا عقود تركيب مستقلة وحراسها؛ لم نثبت أن متطلبات Micro كلها مغطاة أو أن سلوكه القديم صحيح. هذا يحتاج مطابقة المستهلك والمنصة عند مرحلة تركيب منفصلة، دون نقل مشكلاته أو إصلاحه الآن.
- CSS m-* ليس Shadow DOM. إطار الحاوية وcascade وportal وربط البيانات وdirty/طلبات/History/Back ملك المستهلك. الدليل يحدد الفحص عند التركيب بدل نسخ إصلاحات لكل شاشة.
- **D01 لا يزال غير منفذ** ويحتاج موافقة منفصلة. Navigation في F03 قراءة غير محمية؛ قرار dirty يخص native المثال فقط. Menu وmetadata التقويم الداخلية مؤجلتان وفق القرار السابق.
- لا اختبار Safari/WebKit أو Android/iOS فعلي أو قارئ شاشة أو لوحة نظام أو safe areas فعلية. HTML native dialog لا يجعل التطبيق Native.
- الرسوم الجديدة لم تبدأ. المرحلة6 تبدأ **بمقترح بصري للمراجعة قبل التنفيذ**، يركز على المشاريع الصغيرة، الأرقام الفعلية والوحدات والمساحة الصغيرة؛ النسب عند معناها فقط.

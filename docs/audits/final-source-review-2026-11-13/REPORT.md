## نطاق المراجعة والنتيجة

رُوجعت فروق المصدر عن main وعقود التحميل والتهيئة/التحديث/التنظيف، وإتاحة الأفعال والتركيز والنسخ وإعادة التركيب، والتواريخ والأحداث والوحدات والإشارات والجداول. فُحص الكتالوج والمواصفات والتراكيب والمخرجات المولدة؛ أمثلة Showcase أدوات تحقق، وليست شاشات منتج أو بديلًا عن قراءة المصدر.

رُوجعت لقطات فعلية حديثة للأفعال والقراءات والحقول والاختيار والرسائل والتقويم، إلى جانب قياسات واختبارات تفاعل مستقلة. لم يظهر عيب مانع آخر في نطاق الفحوص المسجلة. ليس هذا اختبار قابلية استخدام ميدانيًا أو إثباتًا لزمن فهم محدد.

لم يُسقط أي خيار موثق: **donut، main-metric-featured، bubbles، metric-circles، packed-circle، info-strip-peek، data-readable، metric-readable**. أمثلتها ظاهرة ومُرسومة في مراجعة العائلة، مع جداول/حالات/اتجاه حيث ينطبق العقد. donut وbubbles والدوائر بدائل opt-in؛ لا تُفرض لقراءة دقيقة يناسبها bar/row/table. Packed يبقى Proposed وdata-readable/metric-readable يبقيان Draft. نجاحها لا يعني ملاءمتها لكل معلومة.

**C01–C03:** نجحت فحوص وصفات القيمة/الصف/النموذج وحدودها. **C04:** أُصلح عيب مطابقة الوحدة أدناه؛ يبقى Draft مثل سائر التراكيب. [الكتالوج المرجعي14/8/4](../../COMPONENT-INVENTORY.md)، و[جرد استهلاك الأفعال](../shared-actions-2026-11-12/ACTION-INVENTORY.md).

## عيب جديد مؤكد وإصلاحه

كان `reading-context.js` يقبل ظهور الوحدة كجزء من كلمة أو وحدة أخرى في العنوان، ثم يخفي الوحدة بجانب القيمة. مثال: `g` ضمن `Weight (kg)`، أو «م» داخل «المخزون»/«كم». هذا يخالف اشتراط سياق ظاهر يذكر الوحدة نفسها، وقد يلتبس بسببه تفسير الرقم. العيب في المساعد العام للمكوّن؛ ليس مشكلة مضيف أو بيانات.

- [قبل الإصلاح13 نجاحًا و9 إخفاقات](evidence/unit-before.json)، بوضع capture-only لتوثيق الإخفاق، لا بوابة نجاح. [مثال kg قبل](evidence/unit-before-4.png)، [ومثال كلمة عربية](evidence/unit-before-0.png).
- أضيفت مطابقة حرفية بحدود Unicode للوحدة في المصدر؛ لا تُقبل حروفها ضمن كلمة/وحدة أخرى. عند الشك تبقى الوحدة بجانب الرقم. لا تحويل عملة أو وحدة أو بيانات، ولا تغيير لون أو حجم.
- [بعد الإصلاح22 نجاحًا و0 إخفاق](evidence/units.json)، وتشمل بقاء الرقم والوحدة وعدم الفيض وdisconnect وأخطاء المتصفح. [kg بعد مع بقاء g بجانب القيمة](evidence/unit-after-4.png)، [العربية بعد](evidence/unit-after-0.png)، و[سياق د.أ صحيح ما زال يختصر التكرار](evidence/unit-after-10.png).

الملفات: `components/compositions/reading-context.js`، والاختبار الجديد `tools/unit-context-check.py`، والعقد في [READABLE-SOURCE](../../READABLE-SOURCE.md). أُعيد توليد standalone وملفات مراجعة المصدر بالطريقة المعتمدة، دون تحريرها يدويًا. وحدات النص تُكتب بفاصل واضح في العنوان مثل «الوزن (g)»؛ السياق الملتصق/الملتبس يبقي الوحدة ظاهرة افتراضيًا.

## ما يبقى وما يسمح به الدمج

- **هاتف المالك النهائي:** مؤجل، غير محسوم؛ الإصدار وCSS viewport/DPR غير مقاسة على S25. لا تدّعي هذه المراجعة نجاح Android الفعلي أو Safari/WebKit أو قارئ شاشة أو safe areas. موافقة الدمج لا تُسجل هذه الأمور PASS.
- **D01 / UX-06:** طلب إغلاق Navigation قابل للاعتراض؛ لم يُنفذ. يُراجع قبل نموذج قابل للتحرير يحتاج حماية تعديلات/طلب معلق. التطبيق يملك dirty والحفظ.
- **UX-07:** قائمة أوامر عامة، مؤجلة حتى استخدام مثبت لا تغطيه المكونات الحالية.
- **UX-08:** معلومات إضافية للتقويم، مؤجلة حتى تحديد محتوى وموضع وملكية حقيقية. الملخص خارج الشبكة أولًا.

هذه مؤجلات مسجلة وليست عيوبًا أُغلقت أو وعدًا بتكامل التطبيق؛ [الشروط ومعايير الإغلاق](../../UI-DECISIONS.md) باقية. لا قرارات جديدة لتغيير الهوية أو إعادة تصميم الرسوم في هذه المراجعة.

طريقة الدمج المعتمدة: رفع commit المراجعة على فرع Feature نفسه، ثم إعادة التحقق من الرأسين والبنية، وتحديث main بتقدم مباشر فقط مع شرط رأسه المتوقع041c5a1 و`force=false`. إذا تغير main يُعاد فحصه قبل المحاولة. التأكيد الفعلي للدمج يكون برأس GitHub بعد العملية؛ هذا التقرير لا يستبق نجاح الكتابة البعيدة. يبقى فرع Feature محفوظًا. لا PR أو نشر أو تغيير في Micro.

## النتيجة

نُفذت C01/C02/C03 كوصفات HTML/CSS مشتركة، بحالة **Draft للمراجعة**، مع سياقين مستقلين لكل وصفة. لها مصدر ثابت قابل للاستهلاك، ولا تحتاج CSS المعرض. لم نضف عائلة خامسة عشرة أو API JavaScript للمكونات، ولم نبن منطقًا تجاريًا داخلها.

جُرّبت التراكيب فعليًا في المتصفح مع التفاعل ولوحة المفاتيح والقياسات وفحص اللقطات. النتيجة النهائية **511 فحص Runtime ناجحًا/0 إخفاق**:91 خاصًا بالتراكيب و420 للحراس الحاليين. السجلات الفعلية وبصمات الملفات في [verification.json](verification.json)، وتغطية الخانات والحالات والملكية في [coverage.json](coverage.json).

## C01 — قيمة صادقة مع سياقها

- الإشارة والفواصل والدقة والوحدة والفترة من المستهلك، دون parse/rounding أو حساب مال/نسبة أو استنتاج حالة من الرقم.
- الصفر مختلف عن الغياب. الحالة الأولية والملاحظة والمصدر/الإجراء اختيارية، وغيابها لا يجعل البطاقة زرًا.
- الانتظار والفشل قد يبقيان القراءة السابقة مع وصف صريح. لا استبدالها بصفر أو إعلان تحديث لم يحدث. hidden يزيل الخانات فعليًا.
- المصدر امتداد اختياري لـInfo Strip، لا بطاقة رقم جديدة أو تنفيذ حالة محاسبية. compact/basic والاختيار featured يستعملون التوكنز القائمة.

## C02 — القراءة قبل الأفعال

- قراءة كاملة تلتف قبل الحالة والأفعال دون قص أرقام أو تقليص أهداف48px. القائمة دلالية، والفواصل هادئة، والارتفاع يتبع المحتوى.
- الصف الساكن ليس زرًا. الوجهة الواحدة رابط حقيقي، والأفعال المتعددة أشقاء مستقلون دون أهداف متداخلة أو row-click proxy.
- الإفصاح أصلي، وزره الداخلي لا يطوي التفاصيل. اتجاه شيفرون الفتح يتبع RTL/LTR الموروث. لا JS أو سجل بيانات/ترتيب/ترقيم صفحات جديد.
- مثال0 مختلف عن حالة قائمة فارغة؛ الفشل والانتظار يميزان الصفوف السابقة بدل حذف معناها. وصفة previews القديمة لم تُنسخ إلى كل موضع؛ الأمثلة تستورد مصدر Organization نفسه.

## C03 — سطح مشترك وسياسات عند المستهلك

- المصدر ينسق head/body/feedback/actions، ويستهلك عائلات الحقول والأزرار والرسائل. لا parser مالي أو validation engine أو dirty store أو خدمة حفظ.
- مستهلك المثال فقط يملك raw/validity/dirty وcallbacks والانتظار وتعريف النتيجة. prefill صامت ولا يصير dirty؛ النص غير الصالح لا يُمسح أو يُرفض بصمت.
- Promise المثال تُحل أو تُرفض صراحة من أدواته، ومنها أدوات داخل الحوار لتظل قابلة للاستعمال أثناء modality. لا مؤقت نجاح، وundefined/false أو اكتمال callback ليست نجاحًا.
- فُحص تبديل handlers دون مضاعفة، ومنع الإرسال المكرر، والتعديل أثناء pending، والرفض والنتيجة المحايدة والمؤكدة، والتنظيف والرد المتأخر، وعدم توريث إعلان انتظار قديم عند إعادة التهيئة.

**الطبقة في المثال الثاني يملكها dialog الأصلي عند المتصفح**. showModal/close/cancel واجهات منصة، وليست Micro* API جديدة. سياسات قبول/رفض الإغلاق والخلفية وdirty وقفل التمرير موجودة في مستهلك المعاينة، لا في CSS المكوّن. المصدر يوفر carrier اختياريًا بالتوكنز والخط القائمين؛ لا يفرضه على المضيف المستقبلي.

**D01 لم يُنفذ:** navigation.js وCSS الخاص به بلا تغيير. لا requestClose أو close-request event عامة جديدة، ولا تعديل لسياسة Escape/الفلاتر/Picker القائمة. لا يُربط محرك Navigation إلى native dialog نفسه. إذا اختيرت طبقة Navigation عند استهلاك الوصفة لاحقًا تُحسم حراستها ضمن عقدها الموافق عليه، لا باستيراد controller المثال.

## ما كشفه التطوير وكيف عولج

هذا إنشاء وصفات جديدة، وليس ادعاء عيوب قديمة في Fields أو Navigation:

1. صياغة selector داخل الفاحص أوقفته مبكرًا؛ صُحح الاقتباس مع بقاء التوقعات.
2. close الأصلي المؤجل قد يصل بعد إعداد controller جديد؛ أصبح تنظيف مستهلك المثال متعلقًا بجلسة الحوار المفتوحة، مع منع تمزيق جلسة أعيد فتحها.
3. pattern المرجع احتاج هروب الشرطة وفق v flag في المتصفح الحديث. سجل التطوير الكامل كان84 نجاحًا/1 إخفاق بسبب خطأ console: [الدليل](evidence/development-pattern-check.json). صُحح markup وأضيف اختبار رفض مباشر لمرجع غير صالح مع بقاء raw.
4. إنهاء/إعادة تهيئة المستهلك لا يترك رسالة pending سابقة؛ أضيف تحقق صريح من ذلك ومن تجاهل نتيجة Promise القديمة.

لم تُضعف بوابة أو تُبدل قيمة اختبار لإخفاء عيب؛ الفاحص النهائي يحوي91 فحصًا ناجحًا، ومنها قيد المرجع والاتجاه والردود المتأخرة. لا تُجمع نتائج التطوير مع نتائج التسليم.

## الحدود وما بقي

- جميع207 ملفات الأصول/المشترك، بما فيها الشعار والخطوط والأيقونات والتوكنز، مطابقة للبداية. وجميع34 ملفات CSS/JS التشغيلية الموجودة أصلًا تحت components مطابقة أيضًا؛ التراكيب إضافات مستقلة فوقها.
- لا وصول أو تعديل أو اختبار في Micro، ولا استبدال بيانات أو واجهات خلفية أو منطق منتج. لا اعتماد شكل Micro القديم مرجعًا بصريًا.
- لا محرك form/modal/dirty عام أو API JS جديدة. متحكم الأمثلة وCompositionPreview للاختبار المحلي فقط. لا حسم تلقائي لصحة سلوك مضيف مستقبلي.
- لا Android/iOS أو Safari/WebKit أو قارئ شاشة/لوحة نظام/safe areas فعلية. native dialog هنا يعني عنصر HTML الأصلي، وليس تطبيق Native.
- Menu وmetadata التقويم الداخلية دون توسعة. الرسوم الجديدة وملاءمة بدائلها للمشاريع الصغيرة لم تبدأ؛ الأرقام والوحدات بقيت فعلية في الأمثلة، والنسب عند معناها فقط.

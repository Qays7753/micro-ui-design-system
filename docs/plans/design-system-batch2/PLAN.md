## قرارات المالك في هذه الجولة (نهائية)

- **كل المقترحات في الملفين معتمدة:** م-ر1–م-ر21، وم-أ1–م-أ16، وم-خ1–م-خ3، وم-م1–م-م5، و«م-ك». مع تعديل واحد سبق اعتماده: `kind` تصير `mode`.
- **رموز `sim.*` (م-ر20، وم-ر21) للمحاكاة فقط،** ولا تدخل `tokens.json` ولا حزمة `@micro/ds`.
- **الوحدة «د»،** والأسبوع يبدأ بالأحد، والفلوس ثلاث خانات، وعارض الصور بملء الشاشة مع التكبير، والتسجيل الصوتي دقيقة واحدة.
- **الطلب الجديد:** «مؤكد» افتراضيًا، أو «اتفاق مبدئي» باختيار المستخدم، و«مسودة» إن نقص السعر أو الموعد (الملحق §1.5).

## قواعد الجولة

- كل ثوابت `AGENTS.md` سارية: لا قيمة خارج الرموز، ولا إضعاف لأي بوابة، ولا تعديل على `BRIEF.md` أو الملحقات أو ملفات المواصفات.
- **وحدة واحدة = commit واحد = push واحد،** بالترتيب أدناه. لا وحدة تبدأ قبل وصول push السابقة.
- **دورة كل وحدة:** اقرأ مواصفتها ← ابنِ (الملفات السبعة لكل مكوّن) ← صفحتها في المختبر، **وكل عنصر تفاعلي فيها يعمل فعلًا** ← ds typecheck ← lint ← test ← build ← build:standalone ← البوابات كلها على Chromium وWebKit وعلى العرضين ← **صوّر وانظر بعين مصمم** (قائمة الفحص في ملاحظات المالك §5) ← manifest ← commit ← push ← سطر «✓ <الوحدة> <sha> — نُظر: نعم».
- **نهاية كل مرحلة:** مراجعة بصرية للمرحلة كلها، ثم check-all كاملة، ثم commit للمراجعة.
- وحدة كبرت (أكثر من 3 محاولات إصلاح، أو ملفات كثيرة خارج مجلدها)؟ قسّمها فورًا.
- ما لا تحسمه المراجع: الأقرب لنصها، ويُسجّل تحت «يحتاج قرار المالك»، وتابع. **لا أسئلة ولا انتظار.**
- لا خلاصات ولا جداول بين الوحدات. سطر قصير بالعربي قبل كل أمر طويل وبعده.
- بعد أي إعادة تشغيل للبيئة: fetch، وحاذِ مع origin/design-system، وأعد تجهيز المحركين وnode_modules (الجذر وds/)، ثم تابع من «نقطة الاستكمال».

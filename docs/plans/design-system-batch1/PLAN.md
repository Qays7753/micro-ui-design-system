# خطة الدفعة الأولى: نظام التصميم الجديد لـ Micro (React + TypeScript)

## 0. دورك وطريقة العمل

**دورك:** أنت فريق هندسة أنظمة تصميم بمستوى Apple وStripe وShopify (Polaris). معاييرك:
- لا تقبل الحل الشائع حين يحدد الموجز غيره.
- تكتب كوداً يقرؤه مهندس آخر بعد سنة ويفهمه فوراً.
- تراجع عملك كناقد قبل أن تسلّمه.
- تقول «لا أعرف» أو «فشل» بدل أن تدّعي النجاح.

**المهمة:** بناء **الدفعة الأولى** من نظام التصميم الجديد لـ Micro كما يحددها **`docs/design-system/BRIEF.md`** (الموجز، الإصدار 1.5)، **كمكتبة React + TypeScript** قابلة للاستيراد في تطبيق Micro، من المرحلة S0 حتى S12، دون أسئلة، ثم **التوقف الإلزامي** لمراجعة المالك.

- **المستودع:** `Qays7753/micro-ui-design-system`، **فرع `design-system` فقط**. لا تعمل على أي فرع آخر، ولا تدمج منه أو إليه (خاصة `feature/integration-readiness-2026-11-21` المجمَّد، و`main`).
- **اقرأ أولاً:** `AGENTS.md`، ثم `docs/design-system/BRIEF.md` **كاملاً** (الأقسام 0–29)، ثم هذه الخطة.
- **الموجز هو المرجع الأعلى في كل قرار تصميم أو قيمة.** هذه الخطة تحدد التقنية والبنية والأدوات والبوابات ومؤشرات القبول فقط. عند أي تعارض في التصميم يغلب الموجز.
- **بعد كل مرحلة:**
  - البوابات (القسم 6).
  - commit بالإنجليزية بصيغة `type(scope): summary`.
  - `git push` إلى `design-system`.
  - تحديث التقرير (القسم 7).
- **ممنوع إعلان أي مؤشر أو مكوّن «ناجح» بلا دليل** (رقم مقيس، أو ملف من أداة، أو لقطة). كل شيء سيُراجع على نسخة نظيفة وبلقطات.
- **لا تعديلات آلية جماعية** على المصدر دون مراجعة كل موضع وتشغيل lint.

## 1. حقائق تطبيق Micro (المستهلك)

هذه حقائق مؤكدة من فريق Micro، وتحدد شكل المكتبة:

| البند | القيمة |
|---|---|
| الإطار | React 19.2.8 + react-dom 19.2.8 |
| البناء | Vite 7.3.7، تطبيق متصفح بلا SSR |
| الأنماط | Tailwind CSS 4.3.3 مع CSS عادي |
| TypeScript | 5.6.3 |
| مدير الحزم | pnpm |
| PWA | موجود (`vite-plugin-pwa`)، ويُثبَّت على iOS وAndroid ويعمل بلا شريط المتصفح |
| الأيقونات في Micro حالياً | `lucide-react` (ممنوعة في الموجز؛ المكتبة لا تستخدمها) |
| الورقة السفلية في Micro | `vaul` |
| الحفظ المالي | يتطلب اتصالاً بالخادم، بلا كتابة محلية ولا طابور |

**مبدأ أساسي:** المكتبة **طبقة واجهة مستقلة**:
- لا تعتمد على Vite وقت الاستخدام.
- لا توجيه، ولا تخزين، ولا شبكة، ولا قاعدة بيانات، ولا صلاحيات، ولا حسابات مالية.
- التطبيق يمرر البيانات والأفعال وحالة الاتصال والحفظ.

## 2. الأجهزة المستهدفة

المستخدمون قد يملكون هواتف متوسطة أو أقدم قليلاً. الحد المعتمد منطقي وحديث، لا دعم للأجهزة القديمة جداً:

| البند | القيمة |
|---|---|
| iOS | Safari **16.4 فما فوق** (iPhone 8 وX وما بعدهما)، في المتصفح وفي وضع التطبيق المثبّت |
| Android | Chrome **116 فما فوق**، وSamsung Internet **23 فما فوق** |
| الاتجاه | **عمودي فقط** على الهاتف والتابلت. لا تصميم ولا فحص للوضع الأفقي |
| أجهزة المالك للفحص الحقيقي | iPhone 13 وSamsung Galaxy S25 |
| الهاتف المتوسط | محاكاة: CPU أبطأ 4 مرات، وشاشة 360×780، و320×640 للشاشات الصغيرة |

- يُكتب `browserslist` في `ds/package.json`: `iOS >= 16.4, Chrome >= 116, ChromeAndroid >= 116, Samsung >= 23`.
- البناء (JS وCSS) يستهدف هذه الإصدارات. أي خاصية CSS أو JS غير مدعومة فيها إما تُحوَّل آلياً، أو لها بديل صريح موثق، أو لا تُستخدم.

## 4. البنية الإلزامية للمكتبة

```
ds/
  package.json            # @micro/ds، peerDependencies، exports، sideEffects (CSS فقط)، browserslist
  tsconfig.json           # strict
  vite.config.ts          # وضع المكتبة (library mode)، targets من browserslist
  README.md               # التثبيت، والاستيراد، وترتيب CSS، وقائمة المكوّنات
  CHANGELOG.md            # SemVer
  src/
    index.ts              # المدخل العام الوحيد: يصدّر كل المكوّنات والأنواع
    styles.css            # يجمع: الخطوط + الرموز + أنماط كل المكوّنات
    tokens/               # مولّدة من tokens.json: tokens.css، tokens.ts، tailwind-theme.css
    fonts/                # woff2 + fonts.css + الترخيص
    icons/                # مكوّنات أيقونات مولّدة + index.ts + قائمة العكس
    i18n/                 # ar.ts، plural.ts، time.ts
    lib/                  # أدوات مشتركة: تنسيق المبلغ، usePress، useVisualViewport، سياق إخفاء المبالغ، الطبقات
    components/
      Button/
        Button.tsx        # المكوّن
        Button.css        # أنماطه (رموز فقط)
        Button.types.ts   # أنواع الخصائص بالأسماء الموحدة (23.18)
        Button.states.ts  # قائمة حالاته من 9.0 (يستخدمها المختبر والبوابات)
        Button.test.tsx   # اختبارات السلوك والوصول
        index.ts          # تصدير المكوّن وأنواعه
        README.md         # متى يُستخدم، ومتى لا، والخصائص، والحالات، ومثال
  lab/                    # تطبيق المختبر (Vite)، يستورد من '@micro/ds' فقط
  consumer-test/          # تطبيق بنفس إعداد Micro بالضبط
```

قواعد الكود:
1. **مكوّن واحد = مجلد واحد** بنفس الملفات السبعة. الاسم PascalCase للمكوّن والمجلد.
2. **الاستيراد من الخارج عبر `@micro/ds` فقط.** ممنوع على المختبر وتجربة الاستهلاك الاستيراد من داخل `src/` مباشرة.
3. **الخصائص الموحدة (23.18):** `size`، و`variant`، و`tone`، و`state`، و`saveState`، و`density`… بنفس الأسماء والقيم في كل المكوّنات. ممنوع المرادفات (`color` بدل `tone` مثلاً).
4. **كل مكوّن:**
   - يقبل `className` ويمرر باقي خصائص HTML لعنصره الأساسي.
   - يدعم `ref` (أسلوب React 19).
   - يستخدم عناصر HTML الحقيقية.
5. **المكوّنات المركبة** (مثل `ObjectRow` و`ContextBar`) تُبنى من مكوّنات أصغر من المكتبة نفسها، لا بتكرار أنماطها.
6. **لا منطق أعمال، ولا جلب بيانات، ولا حالة عامة** داخل أي مكوّن. الحالة المشتركة الوحيدة المسموحة: سياق إخفاء المبالغ، وسياق الطبقات.
7. **لا تكرار كود:** أي نمط أو سلوك يتكرر في مكوّنين يُنقل إلى `lib/`.

## 5. فريق العمل: خمسة وكلاء

| الوكيل | المسؤولية | يملك (يكتب فيه فقط) | يبدأ |
|---|---|---|---|
| **1. القائد** | الوحيد الذي يعمل commit ويرفع إلى الفرع. يوزع العمل، ويدمج، ويحسم أي خلاف **بالرجوع للموجز**، ويكتب التقرير | `docs/plans/design-system-batch1/REPORT.md`، و`ds/package.json`، و`ds/src/index.ts`، و`CHANGELOG.md` | S0 |
| **2. الأساسات** | الرموز، والخطوط، والأيقونات، والنصوص، وملف Tailwind، و`lib/` | `ds/src/tokens/`، و`fonts/`، و`icons/`، و`i18n/`، و`lib/`، وأدوات توليدها | S1، **وحده** |
| **3. الفحوص** | كل البوابات الآلية ومؤشرات القبول، ويثبت أن كل بوابة تكشف المخالفة | `tools/ds-*`، وإعدادات lint وstylelint وvitest | S2، بعد اكتمال S1 |
| **4. البنّاء** | المكوّنات، مجموعة بعد مجموعة، كل مكوّن في مجلده فقط، وصفحاته في المختبر | `ds/src/components/`، و`ds/lab/`، و`ds/consumer-test/` | S3، **بعد** اكتمال S1 وS2 |
| **5. الناقد** | **لا يكتب كوداً.** يراجع كل مكوّن ولقطاته مقابل الموجز (خاصة الأقسام 23 و26 و28.2) ومؤشرات القبول، ويكتب «مقبول» أو «مرفوض + السبب» | ملاحظاته في التقرير فقط | بعد كل مجموعة من S3 |

قواعد الفريق:
1. **لا يبدأ البنّاء قبل اكتمال الأساسات (S1) والفحوص (S2) ورفعهما.**
2. **لا يعدّل وكيلان نفس الملف.** الملكية في الجدول أعلاه.
3. **لا يرفع القائد مكوّناً لم يقبله الناقد،** ولم تنجح بواباته.
4. **عند خلاف بين الوكلاء:** الموجز يحسم، ثم هذه الخطة. لا يحسمه الرأي.
5. **الوكلاء يعملون بالتوازي فقط داخل نفس المرحلة،** وعلى مجلدات منفصلة.

## 9. المراحل

### S0 — تجهيز (القائد)
1. `git fetch --tags`، `git checkout design-system && git pull --ff-only`، وتحقق أن `v0.3.0` سلف لـ`HEAD`. إن لم يكن الفرع `design-system` فلا تعدّل شيئاً.
2. اقرأ الموجز كاملاً. اكتب في التقرير:
   - قائمة مكوّنات الدفعة الأولى مع أرقام أقسامها في الموجز (9، 23، 29.2).
   - توزيع العمل على الوكلاء.
3. تحقق أن `docs/design-system/tokens.json` مطابق حرفياً للملحق أ في الموجز. أي اختلاف = توقف وتسجيل.
4. شغّل البوابات القديمة وسجّل أرقام الأساس.

### S1 — الأساسات (وكيل الأساسات، وحده)
1. هيكل `ds/` كاملاً (القسم 4)، و`package.json` بالـpeers وbrowserslist وexports.
2. **الرموز:** أداة توليد من `tokens.json` إلى `tokens.css` و`tokens.ts` و`tailwind-theme.css`، بوضع `--check`.
3. **الخطوط (D8):** 3 ملفات woff2 مقتطعة، وقياس مقاييس الخط الاحتياطي.
4. **الأيقونات (D5):** فقط ما في 23.23، بأوزانه، وقائمة العكس.
5. **النصوص (D9):**
   - دالة الجمع تعطي «لا طلبات / طلب واحد / طلبان / 3 طلبات / 11 طلب».

6. **`lib/`:** تنسيق المبلغ (القسم 8 بالكامل)، وسياق إخفاء المبالغ، و`usePress` (23.2، وإلغاء الضغط بحركة > 8px)، و`useVisualViewport`، وسياق الطبقات (23.15).

# UX-F01 — بطاقة العينة والحالات وفحوص القبول

نسخة R1 /2026-10-04. **جاهز للتنفيذ كعينة محاكاة للمراجعة**، لا سياسة أعمال معتمدة. هذا الملف يحسم اختيارات F01 فقط؛ القواعد العامة لا تفرض هذه الاختيارات على المنتج.

## 1. بطاقة المهمة المحسومة

- الغرض: اختبار قدرة المنفذ على تركيب مصدر UI قائم مع سلوك مستهلك واضح. مثال «تحرير سجل تجريبي»، دون شاشات نظام أو خدمة حقيقية.
- المدخلان: الاسم التجريبي مطلوب؛ الملاحظة اختيارية. القيمة المؤكدة أولًا `{name: 'عينة', note: ''}`؛ القيم الحالية نسخة مستقلة منها.
- dirty هو اختلاف أي قيمة خام عن النسخة المؤكدة. الكتابة ثم العودة إلى القيم نفسها تعيد clean دون حفظ. الاسم يقبل إذا `trim()` غير فارغ؛ نفحص دون تغيير القيمة المكتوبة. لا قواعد طول أو تحويل أخرى مخفية.
- حفظ صريح؛ محاولة clean لا تستدعي الموصل ولا تعلن حفظًا جديدًا، بل تقول «لا تغييرات للحفظ». الإرسال الناقص يبقى متاحًا لاكتشاف الخطأ؛ لا تعطيل مبكر لزر حفظ بسبب حقل مطلوب فارغ.
- النموذج يستخدم `novalidate` كي تصل محاولة الإرسال إلى سياسة التحقق المحددة هنا؛ تبقى `required`/التسمية أصلية لأجل المعنى. الوصول إلى أول حقل خاطئ ورسالة مرتبطة، والقيم الأخرى باقية.
- لا سياسة حذف أو صلاحيات أو أموال أو مصادقة، ولا مخزن متصفح أو network أو analytics. البيانات والمثال والموصل SIMULATION.

## 2. مصدر الحقيقة والحالات

لا تبنِ حالة واحدة تخلط dirty بنتيجة العملية. مصدر المستهلك يحتفظ بقيم حالية، نسخة مؤكدة، نسخة إرسال ثابتة، معرف محاولة متزايد، وحالة العملية:

`idle | saving | failed | unknown | checking | saved`

هذه أسماء F01 المحلية؛ dirty/invalid/عرض قراءة/حوار مغادرة محاور منفصلة. وجود نص النجاح أو تغير DOM ليس مصدر الحقيقة. مثلًا يمكن أن تكون العملية failed بينما تعديل الاسم يعود clean. عند تعديل قيمة بعد saved تزول رسالة النجاح القديمة وتصبح العملية idle.

| الحدث | القيم/النتيجة | السلوك المطلوب |
|---|---|---|
| إدخال في حالة قابلة للتعديل | احسب dirty من القيم الخام | لا تمس النسخة المؤكدة؛ حدّث الخطأ المعروف فقط؛ امسح رسالة عملية سابقة لا تصف الإدخال الجديد |
| حفظ clean | لا عملية جديدة | لا calls ولا loading ولا «تم الحفظ» |
| حفظ بمدخل غير صالح | لا عملية جديدة | عرّف خطأ الاسم نصيًا؛ حافظ على الملاحظة وركّز الاسم |
| حفظ dirty صالح | `saving` ونسخة إرسال ثابتة | دعوة موصل واحدة بمعرف المحاولة؛ منع التكرار يشمل submit من أي طريق |
| نتيجة saved مؤكدة | النسخة المؤكدة = نسخة الإرسال | `saved` وclean، ورسالة باقية واحدة؛ لا نجاح قبل هذه النتيجة |
| نتيجة not-saved مؤكدة | النسخة المؤكدة لم تتغير | `failed`، القيم الحالية باقية؛ تحرير/محاولة جديدة متاحان |
| نتيجة unknown | النتيجة غير محسومة | `unknown`؛ لا نص «لم يُحفظ»، ولا إعادة حفظ أو تخلي أو مغادرة تلقائية |
| تحقق من محاولة unknown | `checking` لنفس attemptId | استعلام حالة فقط؛ لا استدعاء حفظ جديد؛ منع تكرار التحقق |
| تحقق saved/not-saved | طبق النتيجة على نسخة إرسال المحاولة نفسها | saved يحدث النسخة المؤكدة؛ not-saved يعيد failed مع بقاء التعديل |
| تحقق unknown أو خطأ فحص | عودة `unknown` | القيم كما هي؛ «تعذر تأكيد النتيجة، تحقق مجددًا»؛ لا تحويله إلى رفض حفظ مؤكد |
| رد بمعرف قديم | لا يخص المحاولة النشطة | لا يغيّر القيم أو الرسالة أو التركيز؛ تجاهله وسجّل ذلك في دليل الفحص فقط |

في saving/unknown/checking حقول هذه العينة **readonly** لمنع التحرير مع حفظ النسخ والوصول، وليست fieldset معطلة. حالة busy على زر الحفظ فقط أثناء saving، وعلى زر التحقق فقط أثناء checking باستخدام `MicroButtons.setLoading`، دون تبديل الافتراضي B أو جعل الزر busy معطلًا أصلًا. عند unknown يمنع الحفظ سلوكيًا ويتاح التحقق؛ شرح السبب يبقى متاحًا. الحراسة في مستهلك النموذج لازمة إضافة إلى حراسة الزر، لأن submit لا يلزم أن يأتي من click عليه.

## 3. الموصل التجريبي القابل للاستبدال

واجهة محلية مقترحة للعينة، ليست API جديدة للمكتبة:

- `save({attemptId, values})` يعيد Promise بنتيجة `{attemptId, outcome: 'saved'|'not-saved'|'unknown'}`.
- `check({attemptId})` يعيد Promise بالصيغ نفسها، ويستعلم عن المحاولة نفسها دون تغيير قيمها أو حفظ جديد.
- رفض Promise أثناء save يعامل unknown إن لم يؤكد عقد الموصل عدم الحفظ؛ رفض check يبقى unknown. إن أردت رفضًا معلومًا اختر نتيجة not-saved الصريحة.
- احتفظ بعدّادي دعوات save/check وسجل النسخة المرسلة/معرف المحاولة للفحص. تغيير السيناريو في أدوات SIMULATION يطبق على **الدعوة المقبلة**؛ لا يعدّل Promise جارٍ أو نتيجته بعد انطلاقه.
- وسيلة إنهاء/تأخير حتمية في أدوات المحاكاة أو موصل اختبار قابل للتحكم؛ لا نجاح من مجرد مؤقت UI. لا sleeps طويلة لتأكيد الحراسة.
- تجاهل الردود القديمة شرط مسؤولية المستهلك. يختبر بموصل اختبار يعيد ردًا لمعرف قديم، دون إضافة زر debug داخل واجهة العينة.

## 4. المغادرة والحوار

المغادرة هنا زر «رجوع» إلى قراءة محلية للنسخة المؤكدة فقط، مع فعل «تعديل» للعودة. لا `history.back`، ولا حراسة beforeunload أو ادعاء ربط Android Back في هذه العينة.

- clean: انتقل للقراءة دون حوار.
- dirty في idle/failed: افتح حوار B07 بـ«البقاء» و«التخلي عن التعديل». **البقاء/Escape/الإغلاق الظاهر/الخلفية كلها بقاء**: لا تمس القيم ولا تنتقل للقراءة. التخلي وحده يستعيد النسخة المؤكدة ثم يغادر.
- saving/unknown/checking: المغادرة محجوبة في سياسة SIMULATION هذه، مع رسالة محلية موجزة. لا حوار تخلي أو وهم إلغاء طلب جارٍ. ليست سياسة عامة لكل نظام.
- النموذج نفسه خارج طبقة؛ الحوار يحتوي قرار المغادرة فقط. لذلك لا تحتاج اعتراض closeLayer أو hook مفقود لحراسة تعديل داخل modal.
- في حالة البقاء يعيد B07 التركيز إلى مشغّل رجوع صالح. عند التخلي تنتظر `micro-navigation:closed` قبل إخفاء منظر التعديل، ثم تنقل التركيز إلى عنوان القراءة القابل للتركيز برمجيًا. لا تركيز في BODY أو عنصر hidden/inert؛ لا تغيير focus أثناء خفوت الحوار يخفي المشغّل مبكرًا.

## 5. الرسائل والإتاحة

نتيجة/انتظار العملية لهما قناة إعلان واحدة. اختر رسالة B06 ثابتة ذات role مناسب ولا تضف `MicroMessages.announce` لنصها نفسه؛ أو اختر منطقة إعلان موحدة مع رسالة بصرية بلا قناة حية ثانية. أعلن اختيارك واختبر المسار. خطأ الاسم مرتبط بـaria-describedby/aria-invalid، ولا تضف له عدة مصادر إعلان تلقائية. لا Toast في F01 ولا لون نجاح لكل حقل ممتلئ.

سياسة نقل التركيز: محاولة إدخال غير صالح → الاسم؛ فتح الحوار → عنصر مناسب داخله؛ إغلاق بقاء → المشغّل؛ تخلي/رجوع clean → عنوان القراءة؛ إعادة تعديل → الاسم. حفظ/رفض/تحقق غير حواري لا ينقل التركيز بلا سبب. محتوى تقني مثل attemptId/counters في أدوات SIMULATION أو تقرير الفحص فقط، لا رسائل المستفيد.

## 6. مصفوفة القبول القابلة للقياس

كل صف تجربة موثقة، لا عدد فحوص مُفترض. المعرفات ثابتة ويمكن أن يضم الصف عدة assertions مفيدة.

| ID | المسار | ما يثبت فعليًا |
|---|---|---|
| F01-01 | فتح ثم محاولة حفظ clean | لا خطأ؛ القيم الأصلية؛ saveCalls=0؛ لا نجاح جديد |
| F01-02 | تعديل ثم إرجاع القيم إلى الأصل | dirty true ثم false؛ لا calls ولا إعلان حفظ |
| F01-03 | اسم فارغ/مسافات مع ملاحظة | خطأ مرتبط؛ الاسم هو التركيز؛ الملاحظة باقية؛ saveCalls=0 |
| F01-04 | تصحيح الخطأ ثم حفظ صالح | الخطأ يزول؛ نسخة الإرسال تطابق الخام دون trim؛ saveCalls=1 |
| F01-05 | تكرار pointer/Enter/Space/submit أثناء saving | دعوة واحدة؛ pending لا يغير العرض أو يفقد الاسم/التركيز؛ الحقول readonly |
| F01-06 | saving→not-saved→تصحيح→saved | نسخة مؤكدة لم تتغير عند الرفض؛ حفظ ثانٍ بالقيم الجديدة؛ النجاح يحدث snapshot وclean |
| F01-07 | saved ثم تعديل جديد | dirty true؛ رسالة النجاح القديمة لا تدعي حفظ التعديل الجديد |
| F01-08 | saving→unknown ومحاولة حفظ/مغادرة | لا call جديد ولا فقد ولا ادعاء رفض؛ القيم مقروءة والسبب ظاهر |
| F01-09 | unknown→checking مع تفعيل متكرر→saved | checkCalls=1؛ saveCalls ثابت؛ snapshot من محاولة الإرسال نفسها |
| F01-10 | unknown→checking→not-saved | القيم الجارية باقية؛ التحرير/الحفظ ممكنان؛ لا نجاح |
| F01-11 | check unknown ورفض Promise للتحقق | unknown باقية وإعادة تحقق ممكنة؛ لا إعادة save |
| F01-12 | Promise save مرفوض بلا نتيجة عدم حفظ مثبتة | unknown، لا failed مؤكد أو retry-save تلقائي |
| F01-13 | رد قديم من موصل اختبار | حالة وقيم ورسالة المحاولة الحالية لا تتغير |
| F01-14 | رجوع clean ثم إعادة تعديل | لا حوار؛ قراءة النسخة المؤكدة؛ عنوان القراءة ثم الاسم أهداف التركيز |
| F01-15 | dirty→حوار ثم بقاء/Escape/close/backdrop | كل طريقة تحفظ المدخلات وdirty وتبقي التعديل؛ تركيز صالح بعد حدث الإغلاق |
| F01-16 | dirty→حوار→تخلي | يعود snapshot وclean؛ يغادر بعد الإغلاق؛ عنوان القراءة مركّز؛ لا save |
| F01-17 | رجوع أثناء saving/checking | المحاكاة لا تغادر أو تتخلى؛ الطلب الواحد يستمر بنتيجته |
| F01-18 | Tab/Shift+Tab داخل الحوار + نتيجة برسالة | لا تركيز خارج modal؛ الإعلان واحد دون نقل غير لازم؛ DOM ليس إثبات قارئ شاشة فعلي |
| F01-19 | 320/360/390/430 وتكبير نص 200% | لا قص أو تداخل/هدف محجوب؛ الآلية والقيم قبل/بعد التكبير موثقة |
| F01-20 | reduced-motion ونص طويل عربي مختلط | الوظيفة محفوظة؛ النص والأرقام والاتجاه مقروءة؛ لا قيم بصرية جديدة |

لا نتيجة نجاح مجملة تغلق FAIL أو NOT RUN في صف. الصور أدلة شكل فقط؛ save/check counts والقيم والتركيز والأحداث أدلة السلوك. لا تُنقل نتائج فحص العائلات القديمة إلى F01.

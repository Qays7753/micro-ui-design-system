# UX-F02 — بطاقة الاختيار والفلاتر والإعداد

2026-10-05. **READY TO EXECUTE كعينات محاكاة؛ التسليم DRAFT FOR REVIEW.** هذه قرارات عينات محددة لا سياسات أعمال أو رحلات Micro. لا نعيد تصميم الواجهة المعتمدة. [الفحص المسبق](../../reviews/UX-F02/PREFLIGHT.md) يحدد الأخطاء المأذون إصلاحها قبل التركيب.

## 1. النتيجة والنطاق

ثلاث عينات مستقلة بسيطة، يمكن تشغيل كل منها دون لوحة معرض أو العينة الأخرى:

| العينة | ما تثبته | ما لا تعنيه |
|---|---|---|
| `choice-lifecycle` | اختيار محلي، قراءة خيارات قابلة للبحث، تحديث بياناتها، checkboxes/radio/segmented في مجموعات صغيرة مستقلة | اختيار مورد/طلب فعلي أو حفظ على خدمة |
| `filter-lifecycle` | draft/applied داخل طبقة B07، بحث وقائمة محلية ومطابقة الملخص/العداد/النتائج | تصميم صفحة سوق أو هندسة بحث إنتاجية |
| `switch-lifecycle` | تحديث إعداد تجريبي، انتظار ونتيجة مؤكدة أو مجهولة ثم تحقق | صلاحيات، تفعيل خدمة أو إلغاء معاملة حقيقية |

الطبقات والرسائل والتركيز تُختبر **داخل هذه العينات**؛ لا تنشئ معرضًا رابعًا يعرض الشكل فقط. القواعد المنطبقة UX-12..15، UX-17..20، UX-25/26/28، مع مبادئ النتائج المؤكدة UX-05..07 حيث تنطبق. لا تصف F02 بأنه يغطي كل 28 قاعدة أو كل UX. F03 اختبار فهم Agent آخر، وF04 تركيب المنتج، خارج هذا التكليف.

## 2. بيانات مرجعية قابلة للتعديل

كل fixture في مصدر واحد لكل عينة، لا تكرار قيم البداية في HTML والموصل. أسماء تركيبية بلا بيانات حقيقية:

```js
CHOICES_INIT = [
  {value: 'alpha', label: 'عينة A'},
  {value: 'beta', label: 'عينة B'},
  {value: 'gamma', label: 'عينة C'}
];
PICKER_SELECTED_INIT = null;
FILTER_ITEMS_INIT = [
  {id: 'a', label: 'عينة A', active: true, marked: false},
  {id: 'b', label: 'عينة B', active: false, marked: true},
  {id: 'c', label: 'عينة C', active: true, marked: true}
];
FILTER_APPLIED_INIT = {q: '', active: false, marked: false};
SWITCH_CONFIRMED_INIT = false;
```

صيغة أسماء الثوابت اختيار تنظيمي؛ المعنى والقيم أعلاه أساس الفحص. لا وحدات مالية أو تاريخ أو rules أعمال مخترعة. تُختبر أيضًا بداية بديلة (اختيار beta، مفتاح true، تسميات مختلفة)، دون تعديل HTML يدويًا. الفلاتر تبدأ بلا شروط؛ دعم إعداد فلتر ابتدائي غير فارغ خارج F02 حتى لا تُفترض API تهيئة غير موجودة.

## 3. عينة الاختيار

### 3.1 تحكمات قصيرة معزولة

- مجموعة checkbox ب«تحديد الكل»: خياران مفعّلان وخيار ثالث معطل محدد أصلًا. تحديد الكل/إلغاء الكل يخص المفعّل فقط؛ المعطل وقيمته لا يتغيران. حالة صفر/جزئي/كل تستنتج من المفعّل. fixture ثانٍ بلا خيارات مفعلة يكشف P01.
- radio أصلي باسم مجموعة واحد وتسمية لكل input؛ اختيار واحد فقط. لا كتابة أحداث حفظ أو نجاح لمجرد الاختيار.
- segmented من زرين وثالث معطل بـaria-disabled. تبديل **وضع محلي** بين «موجز» و«تفصيلي» مع محتوى مطابق؛ ليس navigation أو tabs أو إعداد دائم. حراسة المعطل تشمل المؤشر ولوحة المفاتيح. لا تصميم أزرار جديد.
- هذه مجموعات أمثلة صغيرة بفصل العنوان والمسافة، لا صفوف ضخمة ولا بطاقة لكل عنصر. لا تجعل تبديلها يغيّر المنتقي أو المفتاح الآخر.

### 3.2 منتقي في طبقة B07

فتح «اختيار عينة» يعرض منتقي B03 داخل طبقة B07. الاختيار **فوري ومحلي**: `micro-picker:change` يحدّث قيمة وعرضًا خارجيًا متطابقين، ثم يغلق الطبقة. زر «مسح الاختيار» خارج الطبقة يمسح القيمة والعرض. لا حفظ/نجاح خدمة، لا Apply ثانٍ للمنتقي.

الإغلاق الظاهر/Escape/الخلفية يُغلق العرض دون تغيير اختيار سابق؛ لا تسمّه «إلغاء تعديل» لأنه لا يوجد draft منتقي أو تعديل غير محفوظ. لا حركة Back خاصة بنظام الهاتف. فتح الطبقة يعيد التركيز داخلها، إغلاقها يعيد التركيز إلى المشغّل الصالح بعد `micro-navigation:closed`.

القراءة عبر mock: `loading → ready | empty | error`. الاستعلام حالة مستقلة؛ no-results لا يساوي empty-source. عند loading/error لا تعرض خيارات قديمة قابلة للتفعيل؛ يمكن إبقاء الاختيار المحلي السابق خارج الطبقة مع وصف موجز أنه آخر اختيار، دون ادعاء توفره في قراءة جديدة. عند ready:

- `setOptions` يحتفظ باختيار ما زال موجودًا بالمعرف ويزامن التسمية الجديدة والعرض الخارجي، **حتى لو لم يُطلق change بسبب بقاء المعرف**؛ المستهلك يقرأ `getSelected()` بعد setOptions.
- إذا زال المعرف يمسح الاختيار والعرض مع رسالة «الخيار السابق لم يعد متاحًا. اختر مجددًا». لا يختار أول خيار تلقائيًا.
- إذا كانت قائمة المصدر فارغة، استدعِ حالة empty صراحة بعد setOptions؛ لا تعتمد على قائمة بيضاء. إذا لم تطابق عبارة البحث أي خيار، تظهر no-results ومسح العبارة يعيد ready الموجود دون طلب قراءة جديد.
- مصدر بحث محلي حرفي `trim()` + مطابقة label بالاحتواء؛ لا افتراض بحث عربي ذكي/تطبيع. النص مدخل نصي لا HTML.
- كل قراءة لها readId؛ الرد الأقدم لا يستبدل نتيجة أحدث، ولا رسالة أو اختيارًا أو تركيزًا. إغلاق الطبقة لا يعني إلغاء القراءة؛ النتيجة المقبولة تُزامن العرض ولو كانت الطبقة مغلقة. لا إعادة فتح تلقائية.
- قبل إخفاء/استبدال عنصر عليه التركيز داخل منتقي مفتوح، انقل التركيز إلى حقل بحث ثابت؛ إذا كان المستخدم خارجها لا تسرق التركيز. في إغلاق الطبقة اترك B07 يدير الإعادة.

## 4. عينة الفلاتر

قائمة قراءة محلية من 3 عناصر. لوحة B07 تستخدم `data-filter-panel` الحالي:

- checkbox بمفتاح `active` وتسمية `data-filter-label="النشطة"`، checkbox بمفتاح `marked` وتسمية «المعلّمة»، search بمفتاح `q` وتسمية «البحث». لا radio أو select أو مدى تاريخ في لوحة الفلاتر لهذه الدفعة.
- `draft` يتغير داخل اللوحة؛ `applied` والقائمة والعداد الخارجي لا تتغير قبل تطبيق. فتح اللوحة يعيد draft من applied. تطبيق يأخذ نسخة من event.detail.applied؛ لا تعتمد في عقد المستهلك على خاصية داخلية `__microApplied`.
- التصفية AND: active/marked يقيدان الخصائص، q غير فارغ يطابق label بالاحتواء. البحث المطبّق مشذب الأطراف حسب عقد B07 الحالي؛ لا يحول case أو يحذف أحرفًا. عداد **عدد الشروط الفعالة**: كل checkbox محدد وq غير فارغ = شرط، وليس عدد النتائج. النتائج لها عدد منفصل.
- «مسح» يمسح draft فقط؛ «تطبيق» وحده يُقر المسح. «إلغاء»/الإغلاق/Escape/الخلفية لا يغيرون applied أو القائمة أو العداد؛ عند الفتح التالي يعود draft من applied. لا حوار فقد تعديل لهذه الفلاتر القابلة للتراجع.
- لا فلاتر → badge مخفي فعليًا بلا مساحة أو وصول؛ النتائج الثلاث. مع شرطين → badge=2، حتى لو النتيجة عنصرًا واحدًا أو صفرًا.
- no-results رسالة موجزة مع فعل «تعديل الفلاتر» يعيد فتح اللوحة؛ ليست خطأ قراءة أو empty-source. لا تخبئ أدوات الوصول إلى التصحيح.
- أسماء المفاتيح والتشخيص والكلام عن إخفاء الصفر لا تظهر في الملخص المرئي؛ تفاصيل الفحص في SIMULATION فقط. التسميات قابلة للتعديل مستقلة عن أسماء المفاتيح.
- التطبيق المحلي لا يستدعي save ولا يعرض «تم الحفظ». لا انتظار شبكة وهمي أو toast مهم.

## 5. عينة المفتاح غير المتزامن

«إعداد تجريبي» input checkbox بدور switch واسم متاح. تبديله يرسل **تحديثًا واحدًا** للموصل مع النسخة المقصودة ومعرف محاولة. هذا حفظ تلقائي لهذا الإعداد التجريبي فقط؛ لا زر حفظ نموذج إضافي.

| الحالة أو النتيجة | القيمة والسلوك |
|---|---|
| idle | checked يطابق confirmed؛ نتيجة قديمة تزول عند بدء محاولة أخرى |
| pending | checked يعرض القيمة المقصودة؛ نص «جارٍ تحديث الإعداد» ظاهر؛ confirmed لا يتغير، `setSwitchPending(true)` يمنع تكرار التبديل |
| saved | confirmed يساوي قيمة الإرسال؛ يخرج الانتظار، checked متزامن؛ نص «تم تحديث الإعداد» فقط بعد النتيجة المؤكدة |
| not-saved | confirmed لم يتغير؛ checked يُسترجع إلى confirmed؛ نص «لم يُحدّث الإعداد. حاول مجددًا» ثابت، والتبديل متاح |
| unknown أو رفض Promise | لا ادعاء رفض/نجاح؛ confirmed القديم لا يتغير؛ checked يبقى القيمة المقصودة بوصفها غير مؤكدة، والمفتاح يبقى محجوبًا؛ «تعذر تأكيد التحديث. تحقق من النتيجة» وزر تحقق ظاهر |
| checking | استعلام عن attemptId نفسه، check واحد رغم التكرار؛ لا update ثانٍ؛ انتظار B01 على زر التحقق فقط |
| check saved / not-saved | نفس قواعد الحسم على **قيمة إرسال المحاولة**؛ ثم إخفاء زر التحقق فعليًا |
| check unknown / رفض Promise | عودة unknown مع إتاحة تحقق جديد، دون إرسال تلقائي أو rollback يوهم الرفض |
| رد قديم | لا قيمة أو رسالة أو تركيز جديد؛ الموصل يمكنه تسوية الطلب الحالي بعده دون reload |

### سياسة التركيز المحددة لهذه العينة

المصدر الحالي يعطّل switch input أثناء الانتظار. إذا كان input هو التركيز عند بدء العملية، انقل التركيز **قبل التعطيل** إلى وصف انتظار ثابت قابل للتركيز برمجيًا (`tabindex=-1`) ومربوط بالتسمية؛ لا تركيز BODY أو عنصر معطل. الوصف نفسه يبقى موجودًا بعد الحسم وإن تغير النص، فلا تنقل التركيز تلقائيًا إلى المفتاح حين يعود متاحًا. إذا انتقل المستخدم إلى عنصر آخر فلا تسرق التركيز.

زر التحقق عند الحسم: إذا كان التركيز عليه، انقله إلى المفتاح بعد تفعيله وقبل إخفاء الزر. إذا كان في موضع آخر لا تنقله. لا aria-disabled وحدها بدل حراسة المصدر، ولا تعطيل fieldset يحجب زر تحقق. اختبار false قبل true/false مكرر/مفتاح معطل أصلًا يحافظ على العقد.

## 6. الموصلات والمحاكاة

ملف mock-adapter.js مستقل لكل عينة تحتاجه، دون framework عام. واجهة موثقة ومقترحة:

- اختيار: `read({readId}) → {readId, outcome:'ready'|'empty'|'error', items}`؛ Promise رفض = error قراءة معروف (ليس unknown حفظ). التحديثات المحاكاة يمكنها أن تتداخل لتثبت الرد القديم.
- مفتاح: `update({attemptId,value})` و`check({attemptId}) → {attemptId,outcome:'saved'|'not-saved'|'unknown'}`. رفض update لا يثبت عدم الحفظ، ورفض check يبقي النتيجة مجهولة.
- كل طلب مستقل؛ لوحة SIMULATION تختار سيناريو الدعوة **التالية** وتُسوي Promise المعلق صراحة. لا مؤقت UI يدّعي نتيجة خدمة، لا الشبكة/localStorage/auth أو بيانات حقيقية.
- تسليم رد بمعرف قديم **عبر معالج المستهلك نفسه** للتأكد من الحراسة، دون استهلاك التسوية الحالية؛ سجل readCalls/updateCalls/checkCalls/staleIgnored/النسخ المرسلة. هذا فحص فلتر نتائج، لا دليل شبكة إنتاجية.
- الفلاتر محلية؛ لا موصل ولا calls مطلوبة لها. لوحة SIMULATION واضحة خارج واجهة المثال، لا أزرار تقنية داخل طبقة المستخدم. يسمح في الفحص استدعاء أداة SIMULATION دون تحريك التركيز لتسوية الطلب، مع توثيق ذلك؛ أفعال المستخدم الحقيقية تُنفذ بالنقر/لوحة المفاتيح.

## 7. الرسائل والإتاحة والشكل

قناة واحدة لكل حدث حالة: حالة المنتقي المرئية عادية، وإعلان موحد داخل نطاق الطبقة المفتوحة كي لا يقع في خلفية inert؛ لا role حي + announce لنفس النص. يمكن أن تكون لكل عينة منطقة حالة ثابتة خاصة بها، لكن لا تعلن حدثًا واحدًا في منطقتين. اختبر البنية والتحديثات، لا تدّعِ نجاح TalkBack/VoiceOver من DOM.

رسالة الفشل/unknown تبقى مع فعل المعالجة، لا toast يختفي. لا success لحقل مليان، لا لون وحده لتمييز pending/unknown/المعطل. الأسماء/أدوار input أصلية، checkbox/radio/switch في أدوارها؛ لا combobox ادعائي للمنتقي الحواري. أحداث تغيير اختيار لا تثبت حفظًا. التركيز يحصر داخل B07 مع Tab/Shift+Tab، وفتح/إغلاق لا يعيد body overflow خطأً.

نفس tokens/fonts/icons/الانحناءات/24px والتحميل B. تجميع بالعناوين والمسافات؛ لا تغيير بصري لتخطي فشل سلوك. كل hidden مستخدم يُختبر بـdisplay/المستطيل/ترتيب التركيز، لا السمة وحدها. صور حالات مستقرة بعد اكتمال انتقال B07، لا لقطة mid-transition توهم عيبًا أو مرورًا.

## 9. التسليم وحدود الإثبات

المصدر HTML/CSS/JS الكامل، كل CSS جديد لتركيب العينة فقط لا إعادة تعريف مكونات UI؛ mock منفصل، README لكل عينة، أداة `tools/ux-f02-check.py` قابلة للتكرار وJSON لكل صف، صور للحالات ذات المعنى. لا جدول مصوّر بدل المصدر. راجع قائمة الملفات في [التكليف](../../prompts/UX-F02-ZAI.md).

ثبّت المصدر والأدوات قبل الأدلة، ثم checkout نظيف للرأس المثبت وتوليد الأدلة منه. يذكر السجل نسخة المتصفح/المحرك/Playwright وبصمة الشجرة ونطاق القياس؛ رمز خروج غير صفري عند فشل أو تعذر بيئة إلزامية. لا تغيير هذه البطاقة لإخفاء فشل. الأدلة السابقة تبقى تاريخية؛ لا تكتب نتائج جديدة فوقها دون تسمية جولة.

WebKit/Safari وAndroid/iOS الفعليان، TalkBack/VoiceOver، native zoom/keyboard/safe areas/زر الرجوع: **NOT RUN حتى تُنفذ فعليًا**. أعرض ما تمكنت منه فقط. سياسات هذا الملف اختيارات عينات P وفق SOURCES.md، ليست قوانين دولية أو شهادة مطابقة شاملة. لا تجبر نموذجًا أو لوحة هاتف غير متاحين لإغلاق الحالة كتابيًا.

إذا ظهر خطأ جديد، فرّق بين خطأ في مستهلك العينة (يُصلح ضمن التنفيذ) وخلل عقد core خارج P01–P03 (NEEDS REVIEW وإعادة إنتاج). لا توقف الدفعة كاملة إذا أمكن إكمال بقية العينات؛ لا تعلنها كاملة إن بقي صف محجوب.

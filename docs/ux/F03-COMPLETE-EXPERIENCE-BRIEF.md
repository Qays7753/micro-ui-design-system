## 1. النطاق

تطبيق تجريبي واحد بهوية Micro، بيانات محلية مشتركة من مصدر واحد، تنقّل رئيسي مختصر: **الرئيسية / العناصر / التقارير / الحساب** عبر navbar B07، والتفاصيل والإضافة/التعديل وجهات فرعية برجوع واضح، وبوابة الوصول محليًا بمعالج محاكاة وطريق سهل للدخول. كل فعل ظاهر يعمل على البيانات أو يظهر سبب تعطيله. **خارج النطاق:** مصادقة حقيقية أو شبكة أو صلاحيات، قواعد مالية أو عمليات إنتاجية، أرقام منفصلة عن البيانات أو رسوم مضللة، تعديل الهوية/tokens، F04، نشر. العارض (carousel) والدوائر المتراصة (packed) امتدادان DRAFT/PROPOSED opt-in لم يذكرهما التكليف في قائمة العائلات الإضافية — يُوثَّق استبعادهما من التركيب حفاظًا على الاقتصاد البصري (§6) ولا يُبنى منهما شيء جديد.

## 3. مصدر البيانات الواحد (demo-store.js — مخطط موسّع)

`F03Store` يبقى المصدر الوحيد؛ كل الصفحات والملخصات والرسوم تُشتق منه ولا رقم ثابت في HTML. مخطط العنصر يوسّع بما طلب التكليف (أسماء/فئات/قيم/كميات/تواريخ/حالات/ملاحظات):

```js
{ id, name, category, note,            // كما كانت (name وcategory مطلوبتان)
  value: number|null,                  // مبلغ د.أ — null = قيمة مجهولة (لا صفر)
  quantity: number>=0,                 // كمية صحيحة
  date: string|null,                   // 'YYYY-MM-DD' — null = بلا تاريخ (فجوة الخط)
  status: 'draft'|'ready'|'stopped',   // قيد الإعداد/جاهز/متوقف — شارات محايدة
  updatedAt: number }                  // ترتيب «الأحدث» حتمي في البذرة
```

- **البذرة:** العناصر التسعة نفسها (`it-01..it-09`، 3 لكل فئة، «عنصر ألف…عنصر ياء») مدوّنة بالحقول الجديدة بقيم حتمية تشمل حالات القبول: قيمة صفرية صريحة (`it-04`)، قيمة مجهولة (`it-06`)، حالات الحالات الثلاث، تواريخ موزعة على أربعة أسابيع للخط، وملاحظات كما كانت. عنصران بصورة رمزية (`it-01`، `it-05`) والباقي بديل أحرف.
- **الإعدادات:** `{ includeStoppedInReports: true, showHomeComparison: true }` تُحفظ مع العناصر في مفتاح تخزين موحّد `micro-f03-mobile-record-v2` (تغيير المخطط يوثَّق هنا؛ المفتاح القديم v1 يُقرأ ويُهجر بأمان إن وُجد ثم يُستبدل).
- **التخزين:** نفس عقد الجولة السابقة — حفظ محلي حقيقي عند توفره، وتدهور آمن إلى جلسة عند التعذر، بلا ادعاء دوام خارج المتصفح. **(R2-05)** `persist()` يزامن الوصف مع **آخر نتيجة كتابة**: نجاح → `persistent=true` ووصف الدوام؛ فشل متأخر (حصة/حجب) → `persistent=false` ووصف «جلسة فقط» يُحدَّث فورًا في التذييل ولوحة وضع المراجعة عند فتحها، ويُطلق حدث `f03:storage-changed`؛ نجاح لاحق يعيد الوصف الصحيح. البيانات تبقى صالحة داخل الجلسة بلا انهيار.

## 4. الموصل التجريبي (mock-adapter.js — عقد محدث بإصلاح R2-01)

نفس واجهة الجولة السابقة (`save/check/readCategories/cancel/setNext*/settle/counters/readout`) مع التزام محكم:

- **(R2-01) التزام المحاولة الأصلية:** دخول `save` يحمل snapshot قيمه وموضعه (`mode`/`itemId`) منذ الدعوة. عند حسم `save` بنتيجة `saved` يُلتزم العنصر **مرة واحدة** (`entry.committedItem`)؛ وعند unknown/not-saved لا يوجد التزام. `check({attemptId})` استعلام حتمي عن دخول المحاولة الأصلية: حين تُحسم بنتيجة `saved` **يلتزم دخول التحقق snapshot المحاولة الأصلية ذاتها** idempotent — إعادة تحقق أو رد مكرر يعيد **العنصر الملتزم نفسه** بلا upsert ثانٍ وبلا عنصر جديد. لا يستدعي زر التحقق `save` جديدًا ولا يستخدم قيم النموذج الجارية. النتيجة الناجحة تحمل دائمًا `item` = العنصر الملتزم.
- **سياسة المستهلك الموثقة عند عقد ناقص:** إن وصلت نتيجة `saved` بلا `item` (عقد ناقص) لا يعرض المستهلك نجاحًا ولا تفاصيل فارغة — يعود إلى حالة «غير مؤكدة» مع بقاء التحقق متاحًا، ويُسجَّل الحدث. (يُختبر هذا المسار من وضع المراجعة.)
- كل ما عدا ذلك محفوظ: snapshot قراءة عند الدعوة (R1-03)، مؤقت مرتبط بالدخول وإلغاء صريح (R1-04)، حسم تلقائي حتمي 600ms، وسيناريو مسلح بحسم 2000ms لا يعلق أحدًا (R1-07).

## 5. الإعدادات ذات الأثر التجريبي الفعلي

| المفتاح (switch) | الأثر الفوري القابل للملاحظة | الاستعادة |
|---|---|---|
| «تضمين العناصر المتوقفة في التقارير» | التقارير والبطاقات تُشتق من جديد بغياب/حضور عناصر `stopped` — الأرقام والتسميات تتطابق مع البيانات | إعادة المفتاح |
| «إظهار المقارنة في الرئيسية» | قسم المقارنة العددية والدوائر في الرئيسية يظهر/يختفي | إعادة المفتاح |

تُطبَّق فور التغيير من حدث `micro-account-settings:change`، وتُحفظ في مخزن الإعدادات (لا `data-demo-only` لأن الأثر والحفظ فعليان — توثيق انحراف عن مثال المكوّن في المصفوفة)، وتُستعاد مع «استعادة البيانات التجريبية الأصلية» في وضع المراجعة. «تسجيل الخروج» يعيد إلى بوابة الوصول دون مسح بيانات، والدخول مجددًا لا يعيد البذرة.

## 6. قرارات التركيب

1. **navbar للوجهات الأربع الرئيسية فقط**؛ التفاصيل والنموذج وجهات فرعية بشريط تطبيق ورجوع (بلا navbar) — تقليل التنافس البصري وأهداف رجوع واضحة. Gateway بلا navbar قبل الدخول.
2. **بوابة الوصول وجهة إقلاع واحدة** ثم لا تعود إلا بالخروج من الحساب — الدخول ضغطة واحدة («دخول تجريبي مباشر») والنموذج يعمل بمحاكاة حتمية تُظهر حالات التحقق والفشل الصيغي محليًا.
3. **شريط المعلومات بنمطيه:** النمط الكامل على الرئيسية (بطاقات مثبتة بتحكمات وأسهم)، ونمط peek على التقارير (ملخصات متقاربة تتبدل مع المقياس) — كلاهما بأفعال بديلة عن السحب.
4. **الرسوم لا تُكرر:** الرئيسية مقارنة عددية + دوائر عد، والتقارير أعمدة/خط/دوائر توزيع للمقياس المختار؛ كل رسم له عنوان ومفتاح وقيم مطابقة، والمجهول «—» والصفر صريح، وسالب أو مقام غير صالح يطبق رفض العقد الصادق بلا تجميل.
5. **حذف بتأكيد يوضح الأثر:** «الحذف لا يمكن التراجع عنه في هذه التجربة» (UX-04 — لا تراجع مزيف)؛ والاستعادة المرجعية هي أدوات وضع المراجعة («استعادة البيانات التجريبية الأصلية»/«تفريغ») وهي ليست وظيفة مستخدم عادية.
6. **الاختيار المتعدد بأهداف منفصلة:** خانة لكل صف بلا تداخل مع هدف الفتح (UX-24)، وشريط أفعال ثابت يظهر عند التحديد فقط، وعدّاد المحدد مطابق.
7. **العارض والدوائر المتراصة خارج التركيب** (DRAFT/PROPOSED opt-in غير مذكورَين في قائمة العائلات الإضافية للتكليف) — قرار موثق في المصفوفة لا نقص غير مُعلن.

## 8. التنقل والتركيز والإتاحة

- عربي RTL وأرقام 0–9 وفاتح وخطوط وأيقونات HugeIcons الأصلية بـ`fill="none"` مع حماية البناء، ومنحنيات المعتمد، والحركة من التوكنات مع احترام `prefers-reduced-motion`.
- التركيز: كل تبديل وجهة إلى عنوانها (أو هدف موثق: حقل الاسم في النموذج، زر تعديل بعد التجاهل)؛ الطبقات بعقد B07 كاملة (inert/حصر/استعادة) دون تعطيل؛ Escape: طبقة → B07، نموذج dirty → الحوار، pending → حجب، غير ذلك لا فعل.

# UX-F03 — بطاقة العينة ومعايير القبول: «عنصر تجريبي» على هاتف

نسخة V1 /2026-10-06، مستخرجة من تكليف المالك الأحدث (بدء F03 بعد مرور مراجعة F02) **قبل التنفيذ**. هذه البطاقة تحسم اختيارات F03 فقط كعينة محاكاة للمراجعة؛ لا سياسة أعمال معتمدة ولا شاشات منتج. المصادر: تكليف المالك في المحادثة، عقد [UX-AGENT-CONTRACT](UX-AGENT-CONTRACT.md)، القواعد [UX-RULES](UX-RULES.md)، وقرار «نموذج داخل modal» المؤجل من [F01-ACCEPTANCE](F01-ACCEPTANCE.md) وخريطة [UX-COMPONENT-MAP](UX-COMPONENT-MAP.md).

## 1. بطاقة المهمة المحسومة

- **الهدف**: تجربة عربية صغيرة تبدو جزءًا من تطبيق حقيقي لمهمة واحدة: عرض عنصر تجريبي، تعديل بياناته، ثم حفظها. هدف واضح وفعل أساسي واضح؛ لا لوحة مؤشرات ولا صفحات تسويقية ولا قائمة استعراض مكونات.
- **البيانات (تركيبية فقط)**:
  - الاسم: مطلوب، قيمة البداية «عنصر تجريبي».
  - الفئة: اختيار واحد من ثلاث فئات تركيبية عبر **المنتقي المعتمد** (`MicroPicker` داخل طبقة B07).
  - الملاحظة: اختيارية.
- **قواعد التحقق — قرارات تجريبية لهذه العينة لا منتج**: الاسم صالح إذا كان `trim()` غير فارغ؛ تُفحص دون تغيير القيمة المكتوبة. لا قواعد طول أو تحويل مخفية.
- **الشكل**: هاتف أولًا، عربي RTL، أرقام 0–9، الهوية المعتمدة نفسها (IBM Plex Sans Arabic + IBM Plex Sans · HugeIcons Stroke Rounded · توكنات `shared/tokens.css` كما هي). إعادة استخدام المكونات والتوكنات والخطوط والأيقونات الأصلية؛ لا تغيير core أو الهوية.
- **التجميع**: بالمسافة والمحاذاة والعنوان؛ ليست كل حقل بطاقة. نصوص قصيرة بشرية. لا مصطلحات اختبار أو أسماء حالات أو شرح تنفيذ في واجهة الاستخدام؛ تفاصيل المحاكاة والفحوص في قسمها الموسوم وفي أدوات الفحص.
- **الملف الواحد**: `standalone.html` يعمل محليًا دون إنترنت أو خادم أو CDN أو ملفات جانبية؛ دون اعتماد على fetch/import. الخطوط مضمّنة وتراخيصها محفوظة في المصدر. viewport مناسب دون تعطيل التكبير؛ دون إطار هاتف مرسوم أو تصغير بـtransform؛ لا افتراض أن دقة S25 المادية هي عرض CSS.
- **الجهاز المستهدف للتجربة اليدوية**: Samsung Galaxy S25 العادي. محاكاة المتصفح **ليست** اختبار S25؛ ما يحتاج جهازًا فعليًا يبقى NOT RUN حتى التجربة عليه.
- **الحركة**: المعتمدة من المكتبة (MOT-01/B07) مع احترام `prefers-reduced-motion`.

## 2. تركيب الشاشات (قرار المستهلك الموثق)

- **منظر العرض**: صفحة عينة تعرض النسخة المؤكدة فقط (الاسم/الفئة/الملاحظة) وزر «تعديل» أساسي واحد.
- **نموذج التعديل «الصغير» = لوحة سفلية B07** (`.m-layer` الافتراضية): هذا هو «نموذج كامل داخل modal وحراسة مغادرته» المؤجل صراحة من قرار F01 بعد مراجعة R1 إلى تطبيق لاحق، وهو ما تختبره F03. الحقول الثلاثة والرسالة والأفعال داخل اللوحة؛ `m-layer__body` تتمدد وتتمرر داخليًا وفق عقد B07.
- **منتقي الفئة = طبقة B07 ثانية تُركَّب فوق لوحة التعديل** (نمط F02 المعتمد): قراءة من الموصل (loading→ready/empty/error)، بحث يصفّي بلا مساس بالحالة، اختيار فوري يغلق الطبقة، رسالة زوال الاختيار ظاهرة داخل الطبقة بنمط B06 (`m-note--warning` + `role=alert`) وهي القناة الوحيدة لهذا الحدث (درس F02-R2-01).
- **حوار التغييرات غير المحفوظة = حوار B07 موسط** (نمط F01 المعتمد): «البقاء في التعديل» أساسي محسوب و«التخلي عن التعديل» ثانوي متلف النص؛ كل إغلاق غير التخلي = بقاء.
- **حراسة مغادرة اللوحة (تطبيق لا تغيير core)**: زر «رجوع» وزر الإغلاق الظاهر في الرأس يمرّران عبر حراسة المستهلك (بدون سمة `data-layer-close` الجاهزة كي لا يُغلق مباشرة). الضغط بالخلفية `data-backdrop="keep"` (بقاء ضمني). **Escape**: مستهلك العينة يسجّل مستمع `keydown` بطور الالتقاط على المستند يوجّه Escape عندما تكون اللوحة مفتوحة: dirty → يفتح حوار البقاء/التخلي (UX-17: لا Escape صامت للتخلي)؛ أثناء pending → حجب برسالة موجزة؛ clean → يُمرَّر إلى B07 ليعمل كما هو. هذا قرار مستهلك موثق بلا تعديل على عقد B07.
- **بعد نجاح مؤكد**: اللوحة تُغلق والعودة لمنظر العرض المحدَّث مع رسالة النجاح هناك — دورة المهمة تكتمل (تعديل → حفظ → عرض محدَّث).

## 3. مصدر الحقيقة والحالات

مصدر المستهلك يحتفظ بـ: نسخة مؤكدة `confirmed` (من `RECORD_INIT` أدناه)، قيم جارية خام، نسخة إرسال ثابتة، `attemptId` متزايد، وحالة العملية:

`idle | saving | failed | unknown | checking | saved`

- **`RECORD_INIT = { name: 'عنصر تجريبي', category: {value:'cat-a', label:'فئة أ'}, note: '' }`** — مصدر وحيد يُبث إلى منظر العرض وحقول اللوحة عند الإقلاع (درس F01-R1-04)؛ لا قيم مكررة في HTML. الفئات الثلاث من مصدر وحيد يمرر إلى الموصل: «فئة أ»/«فئة ب»/«فئة ج».
- **dirty محور مستقل**: اختلاف أي قيمة خام (الاسم/قيمة الفئة/الملاحظة) عن المؤكدة؛ الكتابة ثم العودة لنفس القيم تعيد clean دون حفظ. invalid محور مستقل. لا تُعد `rendered` أو `change` أو زوال pending دليل حفظ.
- **قراءة المنتقي**: `readSeq` متزايد؛ كل فتح للمنتقي قراءة جديدة بمعرف جديد؛ الرد بمعرف أقدم يُتجاهل كليًا (لا قيمة/رسالة/تركيز). حالة القراءة عبر `MicroPicker.setStatus` (loading/error/empty تخفي الخيارات القديمة)، والبحث لا يلغي الحالة ولا يزيل صفها؛ «لا نتائج مطابقة» نتيجة تصفية بحث فقط. empty المؤكدة تطبق مصدرًا فارغًا وتُسقط قيمة الفئة الجارية برسالة الزوال الظاهرة (لا اختيار تلقائي بديل).
- **تزامن محاور**: نجاح/رفض/مجهول لا يمنع عودة القيم إلى الأصل يدويًا؛ رسالة سابقة انتهى سببها بتغير القيم تزال (درس F01-R1-03)؛ `failed` يبقى سجل محاولة دون عرضها كرفض للقيم الحالية.

### سلوك الأحداث المطلوب

| الحدث | السلوك المطلوب |
|---|---|
| فتح التعديل | لوحة B07 تُفتح والتركيز على الاسم (`data-autofocus`)؛ القيم = المؤكدة؛ dirty=false؛ لا قراءة منتجقي |
| حفظ clean | لا دعوة ولا loading ولا نجاح جديد — رسالة «لا تغييرات للحفظ» |
| حفظ باسم غير صالح | لا عملية — خطأ مرتبط بالحقل (`aria-describedby`/`aria-invalid`)، القيم باقية، التركيز إلى الاسم |
| حفظ dirty صالح | `saving` + نسخة إرسال ثابتة + دعوة واحدة بمعرف المحاولة؛ الحقول readOnly (ليست fieldset معطلة)؛ busy على زر الحفظ فقط عبر `MicroButtons.setLoading`؛ منع تكرار يشمل submit من أي طريق |
| نتيجة saved مؤكدة | المؤكدة = نسخة الإرسال؛ اللوحة تُغلق ومنظر العرض يعرض القيم الجديدة ورسالة نجاح باقية واحدة (قناة سياق العرض)؛ dirty=false |
| نتيجة not-saved مؤكدة | المؤكدة لم تتغير؛ `failed` برسالة باقية داخل اللوحة، القيم الحالية باقية قابلة للتصحيح، إعادة المحاولة متاحة |
| نتيجة unknown | `unknown` — لا نص «لم يُحفظ»، لا إعادة حفظ تلقائية؛ الحقول readOnly وزر «التحقق من النتيجة» يظهر ظهورًا فعليًا |
| تحقق من المحاولة | `checking` بنفس attemptId — استعلام فقط؛ تكرار التفعيل محروس؛ busy على زر التحقق فقط |
| نتيجة تحقق saved/not-saved | تُطبق على نسخة إرسال المحاولة نفسها؛ إن كان زر التحقق مركزًا ينتقل التركيز قبل إخفائه إلى زر الحفظ (درس F01-R1-02)؛ saved يغلق اللوحة ويعرض النجاح، not-saved يبقي اللوحة بالقيم |
| تحقق unknown أو رفض | عودة `unknown` — «تعذر تأكيد النتيجة، تحقق مجددًا»؛ إعادة التحقق متاحة دون حفظ جديد |
| رد بمعرف قديم (حفظ/تحقق/قراءة) | لا يغيّر القيم أو الرسالة أو التركيز؛ يُسلَّم عبر مسار معالجة النتائج لدى المستهلك بذات الفلتر دون استهلاك الطلب المعلق (درس F01-R1-05) |
| اختيار فئة | فوري ومحلي ثم إغلاق طبقة المنتقي؛ الملخص والقيمة يتزامنان؛ dirty يتبع المقارنة |
| مغادرة clean | إغلاق مباشر بلا حوار؛ تركيز صالح بعد الإغلاق (مشغّل «تعديل») |
| مغادرة dirty (رجوع/إغلاق ظاهر/Escape) | حوار البقاء/التخلي؛ البقاء وكل طرق الإغلاق الأخرى تحفظ الإدخال والتركيز؛ التخلي وحده يستعيد المؤكد ثم يغادر بعد اكتمال الإغلاق |
| مغادرة أثناء saving/checking/unknown | محجوبة برسالة محلية موجزة — لا حوار تخلي ولا وهم إلغاء عملية جارية |

## 4. الموصل التجريبي القابل للاستبدال

واجهة محلية مقترحة للعينة (`mock-adapter.js`)، **ليست API جديدة للمكتبة**:

```js
save({ attemptId, values })            // → Promise<{attemptId, outcome: 'saved'|'not-saved'|'unknown'}>
check({ attemptId })                   // → Promise بالصيغة نفسها — استعلام للمحاولة نفسها بلا حفظ جديد
readCategories({ readId })             // → Promise<{readId, outcome: 'ready'|'empty'|'error', items: [{value,label}]}>
```

- **الوضع الافتراضي حتمي وينجح تلقائيًا**: بلا سيناريو مسلّح تُحسم كل دعوة تلقائيًا بعد زمن ثابت معلن (700ms) بالنتيجة الافتراضية (`saved`/`saved`/`ready` بالفئات الثلاث) — المسار الافتراضي للمستخدم يعمل بسهولة وينجح. هذا زمن خدمة محاكاة داخل الموصل، **لا مؤقت واجهة يقرر نجاحًا**: الواجهة تنتظر Promise المستهلك دائمًا.
- **السيناريو المسلح** (`setNextSave`/`setNextCheck`/`setNextRead` من قسم SIMULATION أو برمجيًا) يطبق على **الدعوة المقبلة فقط** ويجعلها معلقة حتى أمر `settle(kind)` الصريح — بلا sleeps واجهة ولا نجاح من مؤقت.
- رفض Promise أثناء save يعامل unknown إن لم يؤكد العقد عدم الحفظ؛ رفض check يبقى unknown؛ ولرفض معلوم صريح استخدم `not-saved`.
- عدادات الدعوات (`save/check/read`) وسجلها للفحص فقط — لا تدخل رسائل المستفيد.
- تسليم رد بمعرف قديم يتم عبر `deliverTestResponse(kind, payload)` الذي يستدعي معالِج النتائج نفسه لدى المستهلك (نفس فلتر attemptId/readId) **دون استهلاك Promise المعلق** — ما يثبته: فلتر المستهلك وتجاهله الكامل؛ **لا يثبت** وصولًا شبكيًا فعليًا (حد موثق).
- لا localStorage ولا شبكة ولا مصادقة ولا تحليلات؛ الحفظ تجريبي داخل الجلسة ولا يُدّعى تخزين دائم.

## 5. الرسائل والإتاحة

- **قناة واحدة لكل سياق (حدث = قناة واحدة)**: أثناء فتح لوحة التعديل، رسالة العملية (انتظار/رفض/مجهول/تحقق/لا تغييرات) هي ملاحظة B06 ثابتة `role=status` داخل اللوحة — بلا `MicroMessages.announce` لنصها. بعد إغلاق اللوحة بالنجاح، قناة سياق منظر العرض `role=status` هي المالكة للحدث (نمط توجيه F02-R2-01 بين داخل الطبقة وخارجها). خطأ الاسم عبر رسالة الحقل `aria-describedby`/`aria-invalid` بلا مصدر ثانٍ. رسالة زوال الفئة داخل طبقة المنتقي `role=alert` ظاهرة بنمط B06، ونصها لا يُكرر في قناة أخرى. لا Toast في F03 ولا لون نجاح لكل حقل ممتلئ.
- **تركيز**: فتح التعديل → الاسم؛ فتح المنتقي → حقل بحثه (`data-autofocus`)؛ حوار البقاء → زر البقاء؛ إغلاق بقاء → المشغّل؛ تخلي/إغلاق نظيف → مشغّل «تعديل» (يديره B07)؛ خطأ إدخال → الاسم؛ إخفاء زر تحقق مركز → زر الحفظ قبل الإخفاء (ما لم ينقل المستخدم تركيزه). لا تركيز في BODY أو عنصر hidden/inert.
- **لوحة مفاتيح**: Tab/Shift+Tab محصورة في أعلى طبقة (عقد B07)؛ الأسهم في المنتقي وفق عقده؛ دورة كاملة (عرض→تعديل→فئة→حفظ→نجاح) ممكنة بلوحة المفاتيح وحدها.
- **أهداف اللمس**: من توكنات المكتبة (48px للأزرار وصفوف المنتقي) — سياسة المشروع، لا ادعاء حد WCAG.
- **الأرقام والاتجاه**: 0–9 غربية معزولة، RTL بخصائص منطقية، لا قلب لأيقونات غير اتجاهية.

## 6. مصفوفة القبول القابلة للقياس

كل صف تجربة موثقة بالمتوقع/المقاس/النتيجة. المعرفات ثابتة ويمكن أن يضم الصف عدة assertions. لا نتيجة نجاح مجملة تغلق FAIL أو NOT RUN في صف. الصور أدلة شكل من المصدر نفسه؛ العدادات والقيم والتركيز والقياسات أدلة السلوك.

| ID | المسار | ما يثبت فعليًا |
|---|---|---|
| F03-01 | إقلاع منظر العرض | صفر أخطاء JS؛ القيم من `RECORD_INIT` وحدها؛ dirty=false؛ `saveCalls=0` و`readCalls=0`؛ لا رسالة نجاح مبكرة |
| F03-02 | «تعديل» تفتح اللوحة | لوحة B07 ظاهرة فعليًا؛ التركيز على الاسم؛ القيم = المؤكدة؛ لا قراءة مبكرة للمنتقي |
| F03-03 | حفظ clean | لا دعوة ولا loading؛ رسالة «لا تغييرات للحفظ»؛ لا ادعاء حفظ |
| F03-04 | dirty يم ويحسب | تعديل الاسم → dirty=true؛ العودة للأصل → dirty=false؛ لا دعوات |
| F03-05 | اسم غير صالح ثم تصحيح | خطأ مرتبط بالحقل والتركيز للاسم والقيم باقية (`saveCalls=0`)؛ عند التصحيح يزول الخطأ؛ ثم حفظ صالح يبدأ عملية واحدة |
| F03-06 | فتح المنتقي وقراءته | قراءة واحدة بمعرف جديد؛ loading ثم ready بثلاث فئات؛ الملخص يعرض فئة اللوحة الحالية |
| F03-07 | اختيار فئة | الحدث يزامن القيمة والملخص وعرض اللوحة؛ الطبقة تغلق؛ التركيز داخل لوحة التعديل؛ dirty=true بعد التغيير |
| F03-08 | بحث المنتقي | استعلام بلا مطابقة → صف «لا نتائج مطابقة» ورسالة منسجمة؛ مسحه يعيد الخيارات؛ الحالة المخزنة لا يتغيرها البحث |
| F03-09 | فشل قراءة وempty للمنتقي | سيناريو error → صف خطأ + إعادة محاولة وخيارات قديمة مخفية؛ retry (سيناريو ready) يعيد العرض؛ empty يطبق مصدرًا فارغًا ويسقط القيمة برسالة الزوال الظاهرة داخل الطبقة |
| F03-10 | رد قراءة بمعرف قديم | يُتجاهل كليًا (لا خيارات/رسائل/تركيز) ثم يُحسم الطلب الصحيح |
| F03-11 | دورة نجاح افتراضية | تعديل → حفظ → `saving` (busy واحد، حقل readOnly) → حسم تلقائي `saved` → إغلاق اللوحة → عرض محدَّث ورسالة نجاح واحدة وdirty=false وتركيز صالح |
| F03-12 | تفعيل متكرر أثناء الحفظ | pointer وEnter وSpace وsubmit المتكرر أثناء pending → دعوة واحدة؛ ثم الحسم يعمل بنتيجته |
| F03-13 | رفض معروف وتصحيح | `not-saved` → رسالة باقية داخل اللوحة والقيم باقية قابلة للتعديل؛ تصحيح وحفظ جديد (سيناريو saved) → نجاح |
| F03-14 | نتيجة غير مؤكدة | `unknown` → لا «لم يُحفظ» ولا إعادة إرسال تلقائية؛ الحقول readOnly وزر التحقق ظاهر فعليًا؛ الحفظ محروس |
| F03-15 | التحقق (تفعيل متكرر) → saved/not-saved | `checkCalls=1` رغم التكرار؛ saved يغلق بالنجاح على نسخة الإرسال نفسها؛ not-saved يبقي القيم في اللوحة |
| F03-16 | تحقق unknown/رفض | عودة unknown وإمكان إعادة التحقق دون حفظ جديد |

## 7. حدود الإثبات وNOT RUN المعلن

- بيئة الفحص: Chromium headless فعلي (Playwright) — DOM ولوحة مفاتيح محاكاة وقياسات مقاسات وتكبير نص 200% بالآلية المعلنة (مضاعفة أحجام الخط المحسوبة بتمريرين، لا native zoom) ومحاكاة reduced-motion بالتفضيل الحقيقي في البيئة.
- **NOT RUN حتى تنفيذ فعلي**: Samsung Galaxy S25 الحقيقي وأي جهاز فعلي؛ TalkBack/VoiceOver وقارئ شاشة فعلي؛ native zoom/تكبير النظام؛ اللمس الحقيقي ولوحة مفاتيح النظام وsafe areas الفعلية؛ WebKit/Safari؛ لوحة مفاتيح الهاتف الفعلية وتغطية المدخلات عند الفتح؛ سلوك «رجوع النظام» في تغليف Android. محاكاة المتصفح لا تُسمّى اختبار S25.
- ما يثبته فلتر الردود القديم موثق في §4 — لا يثبت وصولًا شبكيًا.
- لا تنسب نتائج فحص عائلات UI القديمة إلى هذه العينة، ولا تعمم قراراتها التجريبية على المنتج؛ البطاقة نفسها قرارات عينة للمراجعة.

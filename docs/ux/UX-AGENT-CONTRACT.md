# عقد استخدام UX وUI لأي Agent

الحالة DRAFT FOR REVIEW؛ تطبيق على عينة محايدة أولًا. هذا مكمل لـAGENTS.md ومواصفات UI، لا بديل عن معرفة المهمة. دليل القواعد لا يكفي وحده لاختراع رحلة منتج.

## 1. ترتيب القراءة والقرار

1. AGENTS.md وCURRENT-STATE، ثم docs/ux/README والقواعد وخريطة الربط.
2. مواصفات كل مكوّن تستخدمه ومصدره؛ لا تنسخ board.js أو بيانات المعرض كمصدر إنتاج.
3. بطاقة المهمة أدناه. أحدث قرار صريح للمالك يحكم؛ لا تفسّر عينات PROPOSED كاعتماد.
4. لا تغيّر colors/tokens/fonts/icons/curves/24px/تحميل B أو قواعد A05 ضمن UX. سجل التعارض إذا تعذر تطبيق سلوك مع عقد قائم.

## 2. بطاقة المهمة قبل تركيبها

المطلوب مختصر، لا استبيان لكل زر. املأ ما يؤثر فعليًا:

| المدخل | السؤال المطلوب |
|---|---|
| الهدف | ما النتيجة التي يحاول الشخص الوصول إليها؟ |
| الحد | نموذج/قراءة/اختيار/إعداد/إجراء، وما خارج هذه المهمة؟ |
| البيانات | الحقول اللازمة، مصادرها، الوحدة/الفترة/الدقة إن انطبقت |
| القرار | معنى الفعل الأساسي وما الشرط الذي يثبت نجاحه؟ |
| التعديل | قيم مؤكدة وقيم جارية؛ تعريف dirty وهل الحفظ صريح أم تلقائي؟ |
| الأثر | قابل للتراجع؟ فقد/التزام محتمل؟ صلاحية لازمة؟ |
| الحالات | ما حالات الفشل أو الانتظار المعقولة؟ هل نتيجة timeout معلومة أم غير مؤكدة؟ |
| المغادرة | وجهة الرجوع وحكم الإغلاق أثناء dirty/pending |
| التحقق | قاعدة قبول قابلة للملاحظة، والبيئة اللازمة لإثباتها |

NEEDS PRODUCT INPUT للمدخل المؤثر المجهول؛ لا تفترض قيمًا افتراضية من الصور القديمة. للتجربة المستقلة يحدد التكليف بيانات تركيبية وقواعد محاكاة كاملة ويضع SIMULATION، ولا تتحول إلى قواعد المنتج.

## 3. ملكية السلوك

- UI: البنية والشكل والتركيز والعرض وواجهات المكوّن الموثقة.
- المستهلك: البيانات والتحقق ونقطة الحفظ وحراسة المغادرة والتزامن. ضعها في مصدر مستقل قابل للتعديل، لا في مكوّن الحقل أو board الخاص بالمعرض.
- المنتج/الخدمة: الصلاحيات والأثر الحقيقي والمصادقة ومنع تكرار معاملات الشبكة والحسابات. لا اتصال بها في الأمثلة.
- إذا احتجت hook عامًا جديدًا: وثق السبب ومسارًا مقترحًا، وأوقف الجزء الذي يحتاج تغيير عقد UI حتى المراجعة؛ استمر في الأجزاء المستقلة.

## 4. الحالات تُختار بحسب النمط

| النمط | الحالات التي تحتاجها العينة عادة |
|---|---|
| حقل | empty/filled/focus/invalid/readonly/disabled؛ success فقط حين معنى تحقق مثبت |
| نموذج | clean/dirty/invalid/pending/succeeded/failed-known/unknown-outcome |
| قراءة | loading/ready/empty/error؛ no-results ناتجة عن بحث، stale قرار مستهلك |
| اختيار | unselected/selected/disabled + read states للخيارات القادمة من مصدر |
| إجراء | available/unavailable/pending + نتيجة، لا green/success تلقائي لكل ضغط |

dirty/invalid ونتيجة العملية محاور قد تتزامن، لا enum عالميًا واحدًا. لاحظ مثلًا أن رفض عملية لا يمنع المستخدم من إعادة القيم إلى الأصل دون حفظ. لا تفرض جميع الحالات على كل مكوّن. لا تعتبر `rendered` أو `change` أو زوال pending دليل حفظ أو نتيجة أعمال.

## 5. تسليم قابل للمراجعة

- مصدر HTML/CSS/JS/SVG كامل محلي، مع إعادة استعمال أصول UI؛ أي JS سلوكي جديد في ملف مستقل.
- README تشغيل وتبعيات ونقطة تعديل البيانات والقواعد والنصوص والموصل.
- قائمة UX IDs المستعملة وتفسير اختيار المكونات وقرارات المستهلك.
- فحوص سيناريوهات كاملة، تشمل نتيجة الفعل والقيم والتركيز وليس وجود النص فقط.
- تقرير من commit مصدر مثبت: المتوقع/المقاس/الحالة/PASS أو FAIL أو NOT RUN؛ صور من المصدر نفسه.
- سجل gaps/NEEDS PRODUCT INPUT. مصدر كامل أو محاكاة قابلة للتعديل؛ صورة أو build وحده غير مقبول.
- لا اعتماد ذاتي، ولا تحديث أرقام قديمة لتبدو كفحص جديد. كل أثر اختبار له رأس مصدر ومحرك ونطاق.

## 6. سيناريوهات قبول عامة

1. فتح جديد: لا أخطاء مبكرة، التسمية موجودة، لا ادعاء حفظ.
2. إرسال ناقص: الأخطاء مفهومة والقيم محفوظة والوصول للتصحيح متاح.
3. تصحيح وإرسال: pending ثابت الوظيفة؛ repeated activation لا يكرر المحاكاة.
4. رفض معروف: لا نجاح، القيم تبقى، إمكانية التصحيح/إعادة المحاولة واضحة.
5. نتيجة غير معروفة: لا ادعاء «لم يحفظ»؛ لا إعادة إرسال تغير البيانات تلقائيًا. التحقق من حالة العملية مسؤولية الموصل، لا مؤقت واجهة.
6. نجاح مثبت: القيمة المؤكدة/dirty/الرسالة تتزامن مع النتيجة.
7. مغادرة clean/dirty/pending: السلوك مطابق للسياسة؛ البقاء لا يفقد الإدخال؛ إغلاق العرض لا يثبت إلغاء عملية بدأت.
8. تركيب طبقة ورسالة: التركيز والإعلان صحيحان؛ الإغلاق لا يترك عنصرًا نشطًا في inert.

اختبارات pointer/keyboard و320/360/390/430 ومحاكاة تكبير 200% وفق المكتبة وreduced-motion للأجزاء المستخدمة. native zoom/keyboard/TalkBack/VoiceOver/WebKit منفصلة وNOT RUN حتى تنفيذها. الاختبارات الوظيفية لا تثبت أن لغة المنتج أو رحلة المستخدم مناسبة دون مراجعة المهمة.

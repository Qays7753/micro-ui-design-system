# التراكيب المشتركة — العقود والوصفات والقواعد (C01–C14)

## نظرة عامة على التراكيب C01–C14

التراكيب وصفات HTML/CSS عامة تستهلك المصدر المشترك فوق العائلات القائمة؛ لا framework ولا عائلة جديدة. C01/C02/C03 وصفات منفذة بحالة Draft للمراجعة، وC04 إطار قراءة مع مساعد اختياري للوحدات `MicroReadings`، وC05/C06 قدرات الهاتف، وC07–C12 وC14 سياق المنتج، وC13 شاشات بوابة الدخول. [الكتالوج الحالي](COMPONENT-CATALOG.json) هو المرجع لأعداد العائلات والمتغيرات والتراكيب؛ لا تُقرأ الأعداد التاريخية الواردة في هذا الملف كحصر حالي.

CSS وبنية DOM الدلالية جزء من المكوّن. صفحات المعاينة ومتحكمها لا تنتقل إلى المنتج. عند اختيار إطار المضيف لاحقًا يُعرّف markup مرة في غلاف مشترك ثم تمرر الصفحات البيانات والأفعال؛ لا نسخ CSS لكل شاشة أو نقل controller الأمثلة. [واجهات المصدر](../docs/API.md) و[SOP الاستهلاك](../docs/API.md) مكملان لهذا الدليل.

### C07–C12 وC14 — سياق المنتج

سبعة تراكيب Draft تستخدم `MicroProduct` المشترك وrenderers مستقلة، لا عائلات بديلة. [API والتحميل والأبعاد وحالات الاتصال](../components/product-context/specification.md)، [جدول التغطية](product-context/COVERAGE.md)، [المختبر](../previews/product-context/index.html). حمّل Fields JS وNavigation/C05 قبل core، وCarousel عند وجود الصور؛ لا تحمل متحكم المختبر في المنتج. تأكيد الحسّاس من C05، وعرض الصور من Carousel، واللمس من Fields/B01.

الملكية: المستهلك يمرر نموذجًا كاملًا وصلاحيات وscope/dataContext، ويستقبل intent ويرد برمز resolve نفسه أو replace موثوق. لا network/store/auth/AI/قيد مالي. تغيير السياق أو انتهاء الجلسة يبطل الطلبات القديمة وينظف المسودات والمرفقات. دور السائق لا يمنح Manage/Market؛ واجهة المراجعة لا تجلب بيانات مالية. الخادم يظل مالك التفويض الحقيقي.

### C13 — شاشات بوابة الدخول

وصفات UI-only منفصلة عن API العام للبوابة وعن `m-session`: Splash، وGoogle sign-in، وترحيب مستخدم جديد أو عائد، عبر `auth-screens.css` بأصناف `.m-auth-screen--*`. المضيف يملك اختيار الشاشة وتركيبها والحالة والانتقالات وcredential callback؛ لا onboarding ولا نموذج اعتماد يدوي ولا تغيير في مزودي API العامة. التحميل والحدود في [عقد بوابة الدخول](../components/access-gateway/specification.md).

### C14 — سجل عمليات Manage

تركيب سياق المنتج (المرحلة 8، D15/D16) فوق `MicroProduct` بrenderer مستقل `components/product-context/manage.js`: صفوف عمليات على مبنى C02، نموذج إدخال بB02/B01، وملخص فترة بقيم يمررها المضيف حصريًا. **قاعدة صارمة: المكتبة لا تحسب أي مجاميع مالية** — لا جمع ولا صافٍ؛ الوحدة من المضيف دائمًا. Online-only: offline يعطل الإرسال بنص واضح، لا طابور مزامنة ولا تخزين على الجهاز (R-D11)، ولا نجاح قبل resolve من المضيف. العقد الكامل وحالاته وأحداثه في [مواصفة سياق المنتج](../components/product-context/specification.md).

### مصدر واحد والتحميل

حمّل الخطوط وtokens مرة، وCSS العائلة قبل امتداد التركيب. الأصول وJavaScript للأجزاء المستخدمة فعلًا فقط. لا يلزم CSS أو JS من previews، ولا ملف row-composition.css القديم.

| العقد | مصدر التركيب | أساس CSS | اعتماد اختياري |
|---|---|---|---|
| C01 | [value-context.css](../components/info-strip/value-context.css) | info-strip.css | organization للشارة، buttons للإجراء، messages إن استعملت رسالة. |
| C02 | [operational-row.css](../components/organization/operational-row.css) | organization.css | buttons للأفعال، messages للفراغ/الفشل. |
| C03 | [form-surface.css](../components/compositions/form-surface.css) | fields.css وbuttons.css عند استخدام عناصرهما | messages للحالة، selection للاختيار، Navigation فقط إذا اختير مالك طبقة مستقل. carrier الحوار الأصلي لا يحتاج Navigation. |

لا JavaScript خاص بالتراكيب الثلاثة. النصوص والحالات والبيانات للمستهلك. init/sync/disconnect للأبناء عبر [واجهاتهم الحالية](../docs/API.md)؛ لا توفر الوصفة تنظيفًا شاملًا تلقائيًا.

### حدود النضج والتحقق

التراكيب Draft ولا تغير نضج العائلات أو المتغيرات القائمة. الأساس360×780 RTL Light، و320 لأفعال الصف الطويل فقط، وLTR حيث يؤثر الاتجاه. `tools/composition-recipes-check.py` يختبر المصدر دون CSS المعاينة أيضًا؛ إثبات استقلال محدود، وليس حاضنات المضيف الأوسع. لا Dark أو zoom أو ادعاء اختبار جهاز/قارئ شاشة حقيقي.

حد التسليم: اكتمال هذه العقود لا يعني أن المكتبة اجتازت التدقيق البصري اللاحق أو اختبارات الهاتف الحقيقي، ولا أنها مركبة أو مقبولة داخل Micro.

## قواعد التكوين

مرجع الاستخدام فوق Geometry B والتوكنز الحالية دون استبدالها؛ نطاقه مرجع استخدام، وليس اعتمادًا بصريًا لكل حالة.

### الأولوية

لكل تركيب معلومة رئيسية وإجراء متوقع؛ الثانوية أقل بروزًا، والتفاصيل عند الحاجة. الإجراء الخطر منفصل ومعروف؛ لا يحوَّل فعل حساس إلى حركة بلا تأكيد. يحدد المستهلك الأفعال المسموحة؛ الشكل لا يمنح صلاحية ولا يختار سياسة منتج.

### المساحات والأشكال

مجموعة المعنى تأتي قبل البطاقة. فجوة العنوان/القيمة أصغر من الفجوة بين مجموعتين. المواضع الاختيارية لا تحجز فراغًا عند غيابها. لا إطار لكل مستوى متداخل؛ السطح البارز لإبراز مقصود. القراءة القصيرة لا تحتاج ارتفاع وصف طويل. لا تملأ الفراغ بمعلومات مصطنعة، ولا تصغر الخط أو اللمس لإخفاء ضعف التجميع. القياسات المتكيفة لا تعني نسخ تصميم لكل عرض.

### الهوية المحدودة

الأزرار الرئيسية الحالية بترولية. التراكوتا #D97757 من التوكن الحالي يظهر في m-btn__counter للفلاتر المفعّلة فقط وفي m-info-card--accent لملخص مختار لسبب واضح. لا تحويل primary إلى تراكوتا، ولا تعميم الحافة على كل بطاقة، ولا تغيير الشعار أو نشاط Ask. حالات النجاح/الخطأ/التحذير والبيانات مستقلة؛ لا تغيير لون سلسلة مالية لمجرد إظهار الهوية. نص العدّاد الداكن من المصدر الحالي، ولا كتابة بيضاء صغيرة فوق التراكوتا.

### المحتوى والقراءة

كل نص يشرح قيمة أو إجراءً أو يمنع خطأ؛ توثيق المكتبة خارج المكوّن. الصفر/المفقود/السالب/عدم التأكد متمايزة. المبلغ والعدد بوحدات واضحة. الالتفاف مسموح للبيانات الحقيقية؛ يعالج الالتفاف غير الضروري دون قص رقم/وحدة أو عنوان أساسي. لا يُفرض عدد كلمات جامد أو نجاح غير مؤكد.

### السلوك والراحة

الأهداف حسب عقود المكونات، لا توسعة الرسم حتى يملأ هدف اللمس. لا ضغط مجاور سهل لإجراء مدمر. تحديث لا يحرك فعلًا مهمًا أو يمحو المدخلات. احترام التركيز وتقليل الحركة. تتحقق المحادثة من استمرار موضع القراءة وتتعامل مع الجديد دون سحب القارئ. تحتاج راحة الإمساك ولوحة الهاتف إلى تحقق حقيقي لاحقًا.

### الإثبات

تستخدم المعاينة مصدر المكوّن نفسه؛ لا CSS بديل يخفي عيب المصدر. سيناريوهات المهمة تكشف تنافر الأجزاء، وتبقى مستقلة عن التطبيق. الخاصية/المتغير الجديد لا يُضاف إلا لحاجة لا يغطيها الموجود، مع عقد وتوافق واختبار سلوك عند تغيّره. فحص التكوين بصري مستقل عن فحصAPI وعن فحص المنصة. لا ترقية Draft/Proposed آلية.

### ترتيب الإجراءات — وصفة B01

تتبنى مجموعات النصوص وصفةB01 صراحة: عمود واحد، أو زوج متساوٍ، ثم صف إضافي. لا نعيد ترتيب DOM بالـCSS. يتبع الارتفاع التفاف المحتوى، والعرض الكامل للفعل المنفرد لا يترك حجزًا لفعل لا يملك المستخدم صلاحية له. لا تُفرض هذه الوصفة على أزرار الأيقونات أو أشرطة التنقل.

## قاعدة البناء والملكية

التراكيب وصفات عامة تستهلك المصدر المشترك، لا شاشات Showcase ولا نسخ CSS لكل شاشة. قبل إضافة abstraction نثبت سياقين مستقلين يحتاجان التشريح نفسه؛ إن كفى markup موثق لا نضيف JS. نربط كل تعديل لاحقًا بمالك واحد داخل العائلة المناسبة أو مصدر تركيب مشترك واضح، ولا ننقل ملف previews كما هو دون مراجعة. لا تغيير في توكنز الهوية أو نضج العائلات والمتغيرات القائمة. [واجهات المصدر الحالية](../docs/API.md) منفصلة عن سياسات مستهلك الأمثلة. موضع العمل الوحيد مستودع UX؛ لا إصلاح Micro أو اختبار داخله كشرط قبول.

كل خانة أدناه وصف دلالي لا API إطار عمل. أسماء CSS المنفذة موثقة في وصفات العقود أدناه؛ واجهات D01/C05 ووصفة C06 مفصلة في هذا الملف. للمستهلك بياناته ونصوصه ومعنى الأفعال والتحقق التجاري؛ للمكتبة القراءة والتخطيط والحالات الدلالية والموارد التي تُنشئها. القيم المعروضة أرقام فعلية؛ النسبة فقط لحصة/تقدم لهما مقام ومعنى معلنان.

## العقود والوصفات — C01–C06

### C01 — قراءة قيمة بسياق

**الأساس:** Info Card/Info Strip الحالي، وOrganization للحالة والإجراء. لا إنشاء بطاقة رقم ثانية تنافس الموجود. الجذر هو Info Card نفسها: `.m-info-card.m-info-card--context`، مع compact أو featured عند وجود سبب؛ لا بطاقة رقم موازية أو محلل مال.

#### العقد

| الخانة | العقد |
|---|---|
| تسمية | مطلوبة وواضحة؛ لا اعتماد على أيقونة وحدها. |
| القيمة والوحدة | قيمة عرض يقدمها المستهلك، والوحدة ظاهرة عند الحاجة. صفر يختلف عن مفقود؛ المفقود له وصف صريح ولا يتحول إلى0. |
| السياق | فترة أو مصدر أو نطاق اختياري؛ مطلوب عندما لا يُفهم الرقم بدونه. |
| الحالة/المؤهل | تسمية ونبرة معتمدتان، وعلامة provisional/estimated مثلًا فقط إذا قدمها المصدر؛ لا استنتاج من علامة الرقم أو لونه. |
| الملاحظة | توضيح قصير اختياري لا ينافس الرقم؛ لا إخفاء معلومة أساسية فيه. |
| الإجراء/المصدر | رابط أو زر مستقل ذو اسم وهدف واحد؛ غيابه لا يجعل البطاقة تفاعلية. |

#### التحديث والشكل

**التحديث:** مصدر واحد للقيمة والسياق والحالة. لا parser أو حساب جمع/رصيد/نسبة/تقريب داخل التركيب. لا تبديل وحدة أو فترة بصمت. isolate للجزء الرقمي فقط، والوحدة العربية خارج جزيرة LTR؛ لا قلب الإشارة أو قص الخانات الطويلة. التحميل حالة يصرح بها المستهلك؛ إن ظهرت قراءة سابقة تميز بصراحة عن الجديدة.

**الشكل:** basic/compact الافتراضي حسب السياق، وfeatured اختيار ذو سبب، لا مربع ضخم لكل قراءة. الالتفاف قبل قص القيم؛ لا ارتفاع ثابت يخفي الملاحظة. توزيع أكثر من قراءة لا يوحي بجمع وحدات غير متجانسة.

**معايير القبول:** سياقان عامان بقيمة/وحدة/فترة مختلفتين، صفر ومفقود وقيمة طويلة وموقعة، حالة/مؤهل وإجراء غائب/حاضر، انتظار/خطأ دون نسبة مختلقة،360 RTL وعدم قص أو فيض. لا أحداث تغيير تجاري للقراءة الساكنة، وتنظيف الأطفال حسب API كل عائلة.

#### الوصفة المنفذة

```html

    <span class="m-info-card__label">قراءة يقدمها المستهلك</span>
    <span class="m-badge m-badge--info">حالة معلنة</span>
  </div>
  <p class="m-info-card__context">الفترة أو المصدر</p>
  <span class="m-info-card__reading">
    <bdi class="m-info-card__number" dir="ltr">−1,250.750</bdi>
    <span class="m-info-card__unit">د.أ</span>
  </span>
  <div class="m-info-card__meta">
    <span class="m-info-card__qualifier">قراءة أولية</span>
  </div>
  <div class="m-info-card__footer">
    <p class="m-info-card__note">توضيح المصدر</p>
    <a class="m-btn m-btn--secondary" href="#source">مصدر القراءة</a>
  </div>

```

التسمية والقراءة أساس، وcontext لازم إذا لم تُفهم القراءة بدونه. الشارة والمؤهل والملاحظة والإجراء اختيارية؛ احذف الخانات غير المستخدمة أو أخفها بـhidden دون بديل وهمي. القيمة المفقودة ليست0؛ المصدر يضع وصفًا صريحًا مع reading--unavailable. الرقم معزول داخل bdi، والوحدة العربية خارجه. لا parse أو تقريب أو تحويل إشارة/عملة أو حساب نسبة.

التحديث في source DOM الذي يملكه المستهلك؛ لا init أو event للبطاقة الساكنة. انتظار التحديث عبر aria-busy مع عبارة صريحة إذا بقيت قراءة سابقة. الفشل لا يعيد القيمة إلى0 ولا يختلق نجاحًا. featured يستعمل التوكنز القائمة؛ الإجراء secondary ذو أرضية أنسب إن أُضيف على السطح البارز.

[المثال](../previews/compositions/summary-example.html): سياق عدد طلبات وسياق مبلغ نصي بدقة وإشارة، مع0/مفقود/موقع/طويل/انتظار/فشل. الأرقام كما في مصدر العينة؛ لا استنتاج لرصيد/ربح، والنسب عند معنى يحتاجها فقط.

### C02 — صف وقائمة تشغيلية كثيفة

**الأساس:** Organization `.m-row` وامتداد المصدر `components/organization/operational-row.css`. الأمثلة تستهلك المصدر مباشرة. مسار CSS القديم باقٍ كمدخل معاينة يستورد المصدر؛ composition-row كان صنف معاينة خاصًا وليس API إنتاجية. لا تنسيق خاص منسوخ لكل موضع.

**الوصفة:** الجذر `.m-row.m-row--operational`. القراءة تأخذ سطرها قبل الحالة والأفعال. `.m-operational-list` على ul/ol بعناصر li حقيقية، أو list/listitem دلالية؛ فواصل هادئة دون بطاقة وظل لكل صف.

```html
<ul class="m-operational-list" role="list" aria-label="عناصر المصدر">
  <li class="m-row m-row--operational">
    <div class="m-row__text">
      <a class="m-row__primary" href="#record">
        <span class="m-row__text">
          <span class="m-row__title">اسم العنصر</span>
          <span class="m-row__subtitle">سياق اختياري</span>
        </span>
      </a>
      <span class="m-row__reading">
        <bdi class="m-row__value" dir="ltr">0</bdi><span>وحدة</span>
      </span>
    </div>
    <span class="m-badge">حالة المصدر</span>
    <span class="m-row__action">
      <button class="m-btn m-btn--secondary" type="button">إجراء مستقل</button>
    </span>
  </li>
</ul>
```

| الخانة | العقد |
|---|---|
| الاسم والوصف | اسم أساسي ووصف اختياري، يعرضان كامل المعنى دون حجم ثابت. |
| القيمة والوحدة | قراءة اختيارية مستقلة عن الاسم؛ الصفر/المفقود/الإشارة كما في C01. |
| الحالة/التاريخ | نص قابل للفهم مع نبرة اختيارية؛ لا تاريخ أو حالة مشتقان دون مصدر. |
| الأفعال | صفر أو فعل رئيسي وأفعال ثانوية لازمة فقط؛ أسماء صريحة وأهداف مستقلة. |
| الإفصاح | اختياري بمشغّل واحد وaria-expanded/controls؛ الأفعال داخله لا تفعّل الصف مرة ثانية. |

**السيمانتيكس:** قائمة فعلية عند تعدد السجلات. صف أحادي الوجهة يمكن أن يكون رابطًا؛ الصف متعدد الأفعال حاوية مع رابط وأزرار أشقاء، بلا زر داخل رابط أو تداخل أهداف. العرض الساكن لا يتظاهر بأنه زر. لا action-on-row-click مخفي ينافس أزرارًا داخله.

**الضيق:** القراءة أولًا، ثم التفاف الحالة والإجراء عند الحاجة؛ لا تصغير خط أو قص مبلغ أو ضغط الأهداف تحت48px حيث ينطبق العقد. لا فرض ارتفاع موحد بين صفين مختلفي المحتوى. ترتيب القراءة والتركيز منطقي في RTL وLTR. المقصود كثافة مفيدة، لا وضع كل معلومة في صف واحد.

**الحالات:** فراغ القائمة حالة Messages أو نص معلن مع فعل اختياري، ليس صفًا وهميًا بقيمة0. خطأ/انتظار على مستوى القائمة أو فعل محدد حسب مصدر الحالة، ولا يجعلان كل الصفوف معطلة دون سبب. الاستبدال بالمفتاح لا يكرر التفعيل؛ لا record-store أو sorting تجاري أو pagination هنا.

**معايير القبول:** سياقان مستقلان ببيانات معلنة، صف ساكن وآخر برابط وأفعال وإفصاح، نص عربي/لاتيني طويل وقيم طويلة، صفر/فراغ/خطأ/تعطيل فعل، لوحة المفاتيح وعدم تضاعف الحدث،360 RTL و320 فقط لإثبات الالتفاف عند الحاجة. روابط المصدر وأسماء الأفعال ليست مسارات Micro.

#### قواعد الوصفة

- الصف الساكن لا يتظاهر بزر. الوجهة الواحدة يمكن أن تكون a.m-row؛ الأفعال المتعددة روابط وأزرار أشقاء دون هدف متداخل أو مستمع يعيد تمرير كل نقرة للصف.
- reading للقيمة والوحدة، وmeta لتاريخ أو سياق اختياري من المصدر. لا توليد تاريخ/حالة أو record store أو sorting أو pagination.
- details.m-row__details وsummary.m-row__primary يعطيان إفصاحًا أصليًا. الجسم m-row__disclosure خارج summary؛ أفعاله لا تطوي التفاصيل. المتصفح يملك expanded ودورة المفاتيح دون JS أو aria-expanded يدوي ينافسه. IDs وaria-controls، عند استعمالهما، فريدة عند المستهلك.
- empty حالة Messages/نص خارج القائمة، لا صف برقم0. الانتظار والفشل قد يبقيان الصفوف السابقة مع وصف واضح. hidden محترم. لا تعطيل شامل للأفعال دون سبب مصدر.
- الالتفاف يحفظ القراءة وأهداف48px دون ارتفاع ثابت أو قص رقم أو تصغير خط.

[المثال](../previews/compositions/row-example.html): قائمة استلام وقائمة مواد، صف ساكن ورابط وجهة واحدة وأفعال أشقاء وإفصاح،0 وقيمة طويلة وفراغ/انتظار/فشل؛ لا مسارات Micro.

### C03 — سطح نموذج وطبقة قابلة للتحكم

**الأساس:** Fields/Selection/Buttons/Messages داخل سطح CSS مشترك؛ Navigation خيار مستقل حين يختاره المضيف. المثال الثاني يستخدم `<dialog>` الأصلي وcancel القابل للمنع عند المتصفح، بمستهلك محلي يملك سياسة الإغلاق؛ لا يرتبط بمحرك Navigation ولا ينفذ D01، ولا مالكا طبقات للجذر نفسه. D01 منفذ في Navigation بعقد طلب منفصل (أدناه)، دون تغيير معنى closeLayer الأمر المباشر. ليست Access Gateway عامة لكل نموذج، وليست محرك نموذج أعمال أو حالة draft.

**الوصفة:** `.m-form-surface` على form ثم head/title/description/body/feedback/actions. labels وhint/error فريدة ومربوطة، ونوع button صريح. الأطفال من Fields/Buttons/Messages، دون Access Gateway مستنسخة أو form engine جديد.

```html
<form class="m-form-surface" aria-labelledby="form-title" novalidate>
  <header class="m-form-surface__head">
    <h2 class="m-form-surface__title" id="form-title">عنوان المستهلك</h2>
    <p class="m-form-surface__description">سياق النموذج</p>
  </header>
  <div class="m-form-surface__body">
    <!-- حقول ورسائل العائلات بعقودها، دون CSS خاص بكل شاشة -->
  </div>
  <footer class="m-form-surface__actions">
    <button class="m-btn m-btn--primary" type="submit">إجراء المستهلك</button>
    <button class="m-btn m-btn--secondary" type="button">إغلاق</button>
  </footer>
</form>
```

novalidate في هذا المثال يعني أن المستهلك يقدم واجهة التحقق ورسائلها؛ ليس إذنًا بإرسال مدخل غير صالح. اختيار تحقق المتصفح بديل يحدده المضيف صراحة. لا parser مال أو validation عام مفروض.

#### العقد

- **المصدر:** form دلالي؛ label/hint/error مرتبط بكل حقل، ونوع زر submit/button صريح. القيم الخام والصحة وdirty والنسخة المعتمدة ونتيجة الحفظ مملوكة للمستهلك التجريبي الخارجي. لا مالية أو مسودة أو تخزين أو مصادقة داخل التركيب.
- **التحديث:** prefill عبر source + sync الصامت حيث ينطبق. لا يصنف كل حدث Picker/Carousel أو كل rerender تعديلًا من المستخدم. النص غير الصالح لا يختفي لإخفاء dirty؛ تطبيع quantity المقصود يبقى بعقده الخاص، ولا نفرض سياسة raw واحدة على كل نوع.
- **الإرسال:** انتظار مرتبط بوعد/حالة يقدمها المستهلك، منع الإرسال المكرر أثناءه، وخطأ بشري دون مسح الحقول أو إخفاء الخطأ الحرج في Toast مؤقت. لا مؤقت نجاح ولا اعتبار undefined/false أو اكتمال callback نجاحًا. العقد التجاري للنتيجة يحدده المستهلك؛ لا مخطط authenticated لكل نموذج.
- **الطبقة:** مالك واحد للتركيز/inert/scroll. إغلاق نية المستخدم يختلف عن أمر إغلاق بعد حفظ مؤكد أو إزالة الجذر. حارس dirty، إن وجد، عند المستهلك، وHistory/Back عند المضيف. لا نموذجان يديران التركيز على الطبقة نفسها.
- **التنظيف:** يفصل مستمعي التركيب ويوقف تحديث UI المتأخر وينظف كل طفل يملكه. لا يمنع disconnect بسبب اعتراض الإغلاق. إلغاء الشبكة مهمة مالكها، لا أثر ضمني لتنظيف DOM.

**معايير القبول:** نموذج inline وآخر في طبقة مستقلان، صالح/فارغ/غير صالح وreadonly/disabled/pending/خطأ، prefill لا يولد تعديلًا زائفًا، كتابة خام غير صالحة تبقى مرئية، تغيير callback لا يكرر الربط، Promise بعد إزالة الجذر لا تكتب فيه، إغلاق عادي/مرفوض/مقبول وتنظيف أثناء pending. قياس360 RTL، مع خطأ طويل وتركيز صالح ودون محتوى محجوب؛ لا خدمات أو History حقيقية.

#### الملكية

| المسؤولية | المالك |
|---|---|
| raw/committed/validity/dirty والنتيجة والحفظ والأخطاء | المستهلك؛ لا توجد هذه الحالة في CSS المصدر. |
| clear/step/count/sync وتحميل Button | العائلة نفسها؛ prefill يتبعه sync الصامت. quantity يحتفظ بتطبيقه المقصود. |
| aria-busy ومنع الإرسال المكرر ورد نتيجة قديمة | المستهلك؛ undefined/false أو اكتمال callback ليست نجاحًا. |
| التركيز وmodal inert/scroll والإغلاق | مالك طبقة واحد، أو المتصفح مع مستهلك native dialog في المثال. |
| تنظيف مستمعي المستهلك وإيقاف UI المتأخر وإلغاء الشبكة | المستهلك، مع تنظيف أطفال العائلات التي هيأها؛ الوصفة لا تلغي خدمة. |

#### carrier حوار HTML الأصلي

`.m-form-dialog` على dialog يوفّر قياسًا وسطحًا بالتوكنز وغشاء Petrol40% مماثلًا لغشاء Navigation القائم. showModal/close/cancel واجهات **المتصفح**، لا Micro* API جديدة. لا تربط MicroNavigation إلى العنصر نفسه. Native dialog يملك التركيز وinert، ومستهلك المثال يملك قفل التمرير وإعادته. إذا اختيرت طبقة Navigation لاحقًا، توضع form-surface داخلها دون carrier native؛ حراسة إغلاقها تحتاج عقد المالك الموافق عليه.

المثال يستعمل native cancel وباب الإغلاق والخلفية لسياسة dirty/pending محلية. dirty يحسب raw حتى إن كان غير صالح. التنظيف إجباري أثناء pending، ولا تكتب Promise قديمة في UI بعده. لا History أو URL أو storage.

[المثال](../previews/compositions/form-example.html): نموذج inline وآخر داخل dialog بقواعد تحقق مختلفة معلنة. Promise محلية تُحل/تُرفض من أدوات صريحة، ومنها أدوات داخل الحوار لتبقى قابلة للاستعمال أثناء modality. لا timer نجاح أو خدمة. `CompositionPreview` في previews أدوات مستهلك/اختبار فقط، ليست حزمة منتج. يغطي prefill الصامت، callbacks دون مضاعفة، invalid raw، الرفض/الحياد، الرد المتأخر والإغلاق.

### D01 / UX-06 — طلب إغلاق قابل للاعتراض

قدرات الهاتف D01/C05/C06 منفذة في مكتبة UI المستقلة، وMicro **للهاتف فقط حاليًا**؛ لا نسخة ديسكتوب أو popover/hover خاصة بها، ولا وصول إلى مستودع التطبيق. [مختبر الهاتف](../previews/mobile-capabilities/index.html).

`MicroNavigation.requestClose(layer,{reason?,trigger?})` قناة طلب خروج للمستخدم، قبل أي تغيير تقوم به المكتبة للمكدس أو focus أو hidden أو inert أو scroll. تقبل الطبقة المفتوحة العليا فقط؛ الطبقة السفلية أو المغلقة أو التي بدأت الإغلاق والطلب المتداخل لنفس الطبقة no-op تعيد false.

يرسل `micro-navigation:close-request` على الطبقة، bubbles=true وcancelable=true، والتفصيل `{reason,trigger}`. reason أحد escape أوclose-button أوbackdrop أوprogrammatic-request؛ القيمة الغائبة/غير المعروفة تعود إلىprogrammatic-request. trigger عنصر DOM أوnull. لا dirty أو بيانات نموذج أو URL في الحدث.

- `preventDefault()` **متزامن** يمنع الطلب. false تعني عدم بدء الإغلاق بهذه الدعوة؛ true تعني قبول بدء الإغلاق، وليست Promise أو إثبات انتهاء الانتقال. `micro-navigation:closed` هو إشعار الانتهاء الحالي.
- Escape غير المعالج، وdata-layer-close، والخلفية ذاتdata-backdrop=close تمر من الطلب. الخلفية keep لا ترسل طلبًا. Escape يخص أعلى طبقة فقط.
- `closeLayer` يبقى أمرًا صريحًا متوافقًا؛ بعد نتيجة حفظ مؤكدة يمكن للمستهلك استعماله دون تأكيد مكرر. `disconnect` تنظيف قسري لا يمكن منعه. استدعاءات Picker/Settings/الفلاتر الحالية لم تتحول تلقائيًا إلى خروج نموذج dirty.
- إعادة الفتح أو التنظيف أو تغيير الطبقة العليا داخل dispatch يبطل الطلب القديم؛ لا يسمح إغلاق أصل بتجاوز تأكيد أعلى.
- القرار غير المتزامن: امنع الطلب أولًا، ثم افتح تأكيدًا بمالك الطبقات نفسه، واستدعِ closeLayer بعد القبول. لا تعِد إرسال الطلب الذي يعيد السؤال نفسه، ولا تنتظر Promise من dispatchEvent.

المستهلك يملك معرفة التعديلات والانتظار والتحقق والحفظ ونص التأكيد. إذا استعمل مستمعًا على حاوية، يفحص `event.target` حتى لا يمنع خروج طبقة ابن بالخطأ. [مثال محلي](../previews/mobile-capabilities/protected-form.html) يثبت متابعة التعديل أو تجاهله، دون خدمة حفظ. لا يربط Navigation بحوارHTML أصلي في الجذر نفسه.

**حد النطاق:** لا History/URL أو اعتراض لرجوع Chrome/Android بين الصفحات أو إغلاق المتصفح. هذه مسؤولية تكامل التطبيق لاحقًا، ولا تُستنتج من حماية dismissal داخل الطبقة.

امتداد مصدر اختياري Draft مع إطار CSS ومساعد MicroReadings؛ C01/C02/C03 باقية دون JS خاص بها. لا عائلة إضافية أو محرك أعمال. العقد الكامل — المدخلات والتحديث والإفصاح والتنظيف — في قسم «القراءات المنظمة من مصدر المكونات» أدناه.

### C05 / UX-07 — قائمة إجراءات للهاتف

تركيب Navigation/B01 بأزرار HTML أصلية ومالك طبقات واحد، بنفس اللون والمقاسات والـsafe-area الحاليين؛ دون role=menu أو menu/listbox roles أو نمط ديسكتوب. [المصدر والعقد](../components/navigation/action-sheet.md). [سياقا الصف والبطاقة](../previews/mobile-capabilities/actions.html) يستعملان قائمة مصدر واحدة.

`MicroActionSheet.init/open/close/disconnect` يملك lifetime التركيب فقط. `open(sheet,{trigger,contextKey})` يمرر مفتاح سياق معتمًا؛ المستهلك يملك التسميات والمعرّفات والإتاحة والتعطيل والحالة الفارغة وبيانات الأوامر والصلاحيات وتنفيذها. `micro-actions:request` يحمل `{id,contextKey}` **بعد closed**؛ يسمح للمستهلك فتح واجهة لاحقة دون تداخل مالكي تركيز، والنية تصدر بعد اكتمال الإغلاق. لا ينفذ نسخًا أو حذفًا أو صلاحيات أو شبكة. لا تحويل Picker إلى قائمة أوامر، ولا API إجراءات إضافية داخل Picker.

رفض الإغلاق لا يرسل أمرًا. إعادة الفتح أو التنظيف أثناء الحركة تلغي النية القديمة؛ التكرار لا يكرر التنفيذ. يجب تنظيف التركيب قبل إزالته عبر MicroActionSheet.disconnect، مع غشاء مخصص لكل قائمة.

### C06 / UX-08 — ملخص تقويم خارجي

وصفة C01 خارج الجذر، تميز اليوم المحدد عن الشهر المعروض وتتزامن من getState/state-change، ومن مالك setters الصامتة. [وصفة الاستهلاك](../components/compositions/calendar-context.md) و[المثال](../previews/mobile-capabilities/calendar-summary.html) يعيدان استخدام C01 خارج جذر Order Schedule. لا تعديل في مصدر التقويم أو حقول الطلب أو توسيع DOM التقويم، ولا حسابات مالية أو سعة أو تكرار.

اختر صراحة «اليوم المحدد» أو «الشهر المعروض»؛ getState يعيدهما مستقلين. مستمع state-change يزامن أفعال المستخدم، ومالك setter البرمجي أو تحديث البيانات يزامن الملخص صراحة لأن setters صامتة. الانتظار لا يعرض قراءة قديمة لفترة جديدة؛ الغياب والخطأ ليسا صفرًا، والفراغ المعلوم يُعرض0 مع الوحدة. أوقف المستمعات والنتائج المتأخرة قبل destroy.

هذه إغلاق لقرار **التركيب الخارجي**، وليست تنفيذًا لحقول metadata داخل الطلب. لا حاجة محددة لتلك الحقول حاليًا؛ أي توسعة لاحقة تُراجع بمحتواها واستخدامها، دون حقن HTMLعام.

### التحقق لقدرات الهاتف

`python3 tools/mobile-capabilities-check.py --out /tmp/mobile-capabilities` يفحص360×780 RTL بمحاكاة لمس هاتف، و320 لضيق الأوامر و360 LTR للاتجاه، وحركة عادية/مخففة، دون Dark أو desktop layout أو zoom. لوحة المفاتيح ضمن إتاحة الهاتف؛ لا نسخة واجهة مكتبية.

يبقى المصدر14 عائلة و8 متغيرات وفق [الكتالوج](COMPONENT-CATALOG.json). C05/C06 Draft، وسائر النضج محفوظ؛ معاينة Galaxy S25/Chrome الفعلية النهائية مؤجلة. نجاح Chromium لا يساوي تحقق اللمس أو قارئ الشاشة أو لوحة مفاتيح الجهاز الفعلية.

### ما يُحمّل مرة

C04 ليس عائلة جديدة. C01/C02/C03 باقية. يمكن وضع `data-reading-unit` على وحدة C01 أو قيمة C02 واستخدام سياق C04 نفسه، دون نسخ تنسيقات الصف أو البطاقة. `.m-reading-group__amount` للقراءة الرئيسية36؛ عنوان المجموعة18؛ النص16؛ تسمية14؛ سياق13. الزوج `.m-reading-group__pair` لقيمتين مستقلتين، وليس بديلًا عامًا لكل بطاقة أو جدول. لا تُحشر فئات كثيرة في الزوج.

### الوحدات: أمان افتراضي

الوحدة ظاهرة افتراضيًا: **150 د.أ** تختلف عن **149 قطعة**. لا اختصار K/ألف تلقائي، ولا نسبة بدل المقدار. `data-display` في Data و`data-display-value` في Metric بالعرض الجديد لتنسيق الرقم نفسه؛ الوحدة منفصلة في `data-unit`، فلا تُضمّن مرة ثانية داخل النص المنسق. تبقى القيم الخام في الجدول، ولا يُستنتج نوعها من حجمها.

الاختصار الموضعي اختياري عبر تحميل `reading-context.js` مع CSS السابق:

```html
<section class="m-reading-group" data-reading-context="money-context" data-unit="د.أ" aria-describedby="money-context">
  <p id="money-context">هذا الأسبوع · د.أ</p>
  <span><bdi dir="ltr">150</bdi> <span data-reading-unit="د.أ">د.أ</span></span>
</section>
```

`MicroReadings.init(root?)` و`sync(root?)` يقبلان الجذر وأبناءه؛ `disconnect(root?)` يعيد الوحدات إلى الظهور. لا مستمعات أو مراقب أو مؤقت لكل مجموعة. المستهلك يستدعي sync بعد تغيير النص/الوضوح/السياق، بما فيه تغييرات responsive خارج رندر العائلة، وdisconnect عند التنظيف. Data وMetric يستدعيان sync بعد رندرهما إن كان المساعد محمّلًا. غيابه يعني إبقاء الوحدات ظاهرة.

لا يختصر المساعد إلا إذا عرّف الجذر `data-unit` أو `data-common-unit`، وطابقت الوحدات كلها هذا السياق، وكان المعرّف يشير إلى نص ظاهر كامل غير مقصوص يذكر الوحدة حرفيًا كوحدة مستقلة، لا كجزء من كلمة أو وحدة أخرى: g داخل kg و«م» داخل «المخزون» لا يكفيان. اكتب الوحدة بفواصل واضحة مثل «الوزن (g)» أو «هذا الأسبوع · د.أ»؛ عند الالتباس تبقى بجانب القيمة. المجموعات المتداخلة تملك سياقها. الاختصار بصري فقط: تبقى الوحدة في DOM وشجرة الإتاحة، ولا يُحذف metadata. لا تكتب `.m-reading-unit--contextual` يدويًا. المجموعة المختلطة أو العنوان الغائب/المخفي/المقصوص تستعيد الوحدات عند sync. لا تستخدم label محجوبًا أو سياقًا لا يستطيع المستخدم ربطه بصريًا بالقيم. يشمل التحقق قصّ العنوان من حاوية أب؛ لا تكفي عملة داخل ابن hidden/شفاف/مقصوص بصريًا لإخفاء الوحدة. يبقى تحقق sync صريحًا عند تغيير السياق، ولا يضاف مراقب أو مؤقت.

### Data: قراءة مباشرة واختيار مستقل

`data-presentation="readable"` يفعّل سياقًا موجزًا، مفاتيح دونات بصفوف كاملة وقيم بوحداتها، وجدولًا بقيم خام ووحدات. عند اختلاف وحدة أو فترة العناصر لا يرسم مقياسًا نسبيًا مضللًا؛ يعرض كل قراءة ووحدتها وفترتها، مع `data-reading-state="mixed-context"` وتعطيل اختيار المقارنة (`data-selection-state="mixed-context"`)؛ لا إجمالي أو نسبة مشتركة بين وحدات مختلفة. لا تُستنتج فترات أو عملات. في هذه الحالة يحتوي الجدول عمود «الفترة» لكل صف، مع «(فترة غير محددة)» إذا غابت، ويحتفظ caption باسم الرسم. يعود الجدول للبنية المعتادة عند تجانس السياق. سمات العنصر `data-unit`/`data-period` تتقدم على الجذر في هذا المتغير فقط. السلوك القديم بلا العلمين باقٍ.

`data-selection="single"` مستقل عن readable ويدعم bars/line/donut فقط. كل `li` في مصدر البيانات يحتاج `data-key` نصيًا فريدًا غير فارغ؛ `data-series` هو لون الفئة وليس هوية العنصر. لا اختيار افتراضي مخترع. `data-selected-key` اختيار أولي صريح من المستهلك؛ وبلا اختيار يختار زر «التالي» أول عنصر فعليًا. لا يفتح الجدول أو الإفصاح تغييرًا للاختيار.

```js
MicroData.init(chart);                       // API التهيئة الحالي
MicroData.setSelection(chart, 'stable-key'); // صامت
const selection = MicroData.getSelection(chart);
MicroData.setSelection(chart, null);         // مسح صامت
chart.addEventListener('micro-data:selection-change', event => {
  // استجابة المستهلك لاختيار المستخدم فقط، دون حفظ أو شبكة من المكتبة.
  console.log(event.detail);
});
MicroData.render(chart);                     // رسم واحد بعد تحديث source DOM
MicroData.disconnect(chart);                 // إلغاء الحراس والمراقبين قبل الإزالة
```

نص aria-valuetext يتبع القيمة والحالة والوحدة المرئية نفسها؛ data-display قديم لا يغلب المفقود أو الخام غير الصالح، والسالب غير المرسوم يبقى موصوفًا. هذا تحقق للنص المتاح، وليس إثبات نطق قارئ شاشة فعلي.

النتيجة نسخة جديدة أو null: `{key,label,value,rawValue,display,invalid,unit,period,share}`؛ `share` كسر0..1 فقط لتوزيع دونات بمقام صالح وإلا null. المعطيات الخام محفوظة، والمفقود null وليس0. مفتاح غير موجود في setter يُتجاهل. الحدث يتصاعد مرة واحدة لتغير اختيار المستخدم فعليًا؛ setters وinit/render لا يطلقونه. حدث `micro-data:rendered` القديم يبقى مستقلًا.

إعادة ترتيب البيانات تحفظ الهوية بالمفتاح؛ حذف المحدد يمسحه صامتًا دون اختيار بديل. مفاتيح مكررة/فارغة أو مصدر فارغ تعطل الاختيار وحده (`data-selection-state=invalid-keys|empty`) وتحفظ القراءات. لا تستخدم ترتيب li كهوية. تحديث البيانات والسياق يتبعه render؛ لا يراقب المكوّن كل تعديل source DOM. disconnect يحتفظ بالبيانات/المفتاح ويوقف التفاعل؛ init يعيد ربط نسخة واحدة. لا تكتب في العقد المولدة من إطار المضيف والـrenderer معًا.

الأعمدة والخط يملكان range أصليًا وزري B01 secondary بارتفاع أدنى48px وخط16 تحت الرسم، وقراءة محددة حية وعلامة على العنصر. مفتاح الدونات أزرار48px مع aria-pressed واسم/قيمة واضحين؛ النسبة ثانوية وتظهر للفئة المحددة فقط. لا نضيف هدف لمس صغيرًا إلى كل SVG. التركيز يبقى في range عند التحديث، أو يرجع إلى زر الفئة بمفتاحه بعد إعادة بناء المفتاح؛ عند حذفها ينتقل إلى تحكم متاح في الرسم. إذا تعطّل زر الحدود ينتقل التركيز إلى range المتاح؛ وإذا أزيلت أدوات التحديد أثناء render ينتقل إلى تحكم باقٍ، مثل إفصاح البيانات. لا يغير render التركيز الموجود خارج الرسم. disconnect عند إزالة التركيب يترك إرجاع التركيز لمالك التركيب.

**اتجاه المحور لم يتغير:** الأعمدة غير الموقعة الحالية ترتب مصدرها من اليسار إلى اليمين في SVG، فيتبعها range. الخط والأعمدة الموقعة يتبعان `data-axis-dir` الحالي، وافتراضيه RTL؛ وقت الخط من `data-axis-type="time"` و`data-x` وفق العقد الحالي. لا تغيير محور تلقائي بسبب لغة الصفحة.

الدونات خيار متخصص لتركيب أجزاء من إجمالي، والخط فقط إذا كانت علاقة الزمن مفيدة ومفهومة. البداية البسيطة bars/rows + المقدار الحقيقي. لا نسبة من سالب أو مقام غير صالح، ولا تحويل غياب إلى صفر. لا تغيير للخيارات المتخصصة الموجودة أو حذفها أو ترقية نضجها.

### MetricComparison: صفوف متراصفة

`.m-main-metric--readable` يضع اسم الفئة والمسار والقيمة في ثلاثة أعمدة مشتركة، مع وحدات منفصلة وأرقام معزولة. الأسماء والقيم الطويلة تلتف كاملة، ولا يصبح مسار صف أقصر لمجرد طول تسميته. المحركات بلا subgrid تحتفظ بالصفوف الأصلية كاملة العرض. ارتفاع المسار الحالي12، أو8 فقط عند اختيار compact الموجود؛ لا تصغير عام.

التحقق الحالي من الوحدة والفترة والمقياس يبقى. الصفر والمفقود والخطأ والسالب مميزون؛ الخام غير الصالح ظاهر في المتغير الجديد مع تشخيصه. API الحالي `init/render/disconnect` لا يتغير. ليست الأعمدة الثلاثة جدولًا إجباريًا لكل شاشة أو لكل عائلة.

### تقدم عام، لا محرك فواتير

Progress يبقى CSS فقط. المستهلك يوفّر القيمة والهدف والمتبقي والنسبة والتجاوز وحالة الهدف المفقود/الصفر. الشريط يحدّ قصّ الرسم، لكن النص يحتفظ مثلًا بـ130% عند التجاوز؛ aria-valuenow لا يتجاوز max، وaria-valuetext يذكر القيمة الحقيقية. عند غياب/عدم صلاحية المقام لا تعرض0% مخترعة؛ اذكر الحالة وأزل aria-valuenow عند النسبة غير المحددة. صفر الهدف حالة موصوفة لا قسمة على صفر. الربط بين فواتير وحسابات أو عمليات دفع ليس مسؤولية هذا المستودع.

### وضوح الأفعال

السابق/التالي وأفعال الجدول تستخدم مكوّن الأزرار المشترك. صفوف فئات الدونات وrange تحكم اختيار متخصص وليست أزرار CTA. إفصاح C04 يحافظ على marker الأصلي لـsummary، مع هدف48px؛ لا يخفيه flex من دون بديل. [الأدوار والتحميل](../docs/API.md).

### ترتيب CSS وحدود الضمان

F01 يعلن `@layer host, micro, fixture`، ثم يستورد CSS المصادر داخل micro. reset المضيف الافتراضي أدنى أولوية: خط serif19 وcontent-box للمدخلات والأزرار لا يلغي خصائص المصدر الصريحة. framing الحاضنة محصور بأسماء fixture، دون إعادة تعريف m-* أو !important أو تغيير توكنز. عند اعتماد cascade layers لاحقًا يجب إدراج قواعد المكتبة في ترتيب المضيف الحقيقي؛ القواعد العادية غير المدرجة في layer تتقدم على القواعد العادية المدرجة فيه.

الزر «reset متعارض» حالة سلبية مقصودة: يضيف قاعدة button عامة غير مدرجة في layer فتخفض الهدف وتبدل الخط. «تصحيح نطاق reset» يحصرها بعناصر المستهلك، فتعود الخصائص الصحيحة دون تعديل المكوّن. هذه مخالفة عقد استهلاك؛ لا تعالجها المكتبة برفع specificity أو !important. لا يوجد ضمان ضد أي CSS مضيف اعتباطي.

الحاضنة الضيقة ليست حدًا أدنى جديدًا لكل العائلات. عقود Calendar وPeek والرسوم واستثناءاتها تبقى حسب مواصفاتها. لا نفرض عرض296 على كل مكوّن أو نثبت صلاحية تركيب لم يُختبر.

### الطبقات

transform/contain/overflow في الحاوية السلبية يحصر fixed ويقصّه؛ النقل المحلي للطبقة وغشائها إلى body يثبت مسارًا صالحًا لهذا المثال. يجب الاحتفاظ بالاتجاه والثيم والعلاقات الدلالية عند اختيار portal فعلي، وتنظيف الجذور قبل إزالتها. رفع z-index وحده ليس علاجًا.

Navigation يتابع الأشقاء المضافة على سلسلة أسلاف الطبقة العليا أثناء فتحها فقط؛ ينظف المراقب عند تحرير العزل. لا يكتشف إزالة مضيف مهمل للتنظيف ولا يملك كل mutations التطبيق. تستبقي live-region/toast استثناءاتها الحالية، وinert السابقة تستعاد بدقة.

لا يجمع المثال native dialog وNavigation على طبقة واحدة. يمنع مستهلك F03 فتح المحرك البديل حتى إغلاق طبقات Navigation. نموذج native وقراره المحلي لا يضيفان requestClose إلى Navigation؛ عقد D01 المنفذ موثق في قسمه أعلاه، وطبقة Navigation في الحاضنة للقراءة غير المحمية فقط.

## C15 — حالة خطأ مع إعادة محاولة (error-retry)

الحالة `draft-for-review` (الجولة الثالثة T5). وصفة عرض فوق عائلة `screen`: شريط علوي بعنوان السياق، ومحتوى خطأ مركزي (علامة دائرية بلون الخطأ + عنوان + وصف قصير بما يجب فعله — نص المستهلك)، وشريط إجراءات سفلي بزر **إعادة المحاولة** أساسي (B01 بحالة تحميل أثناء الانتظار) وزر ثانوي للبديل. المصدر: `components/compositions/error-retry.css`؛ المثال: `previews/compositions/error-retry-example.html`.

- **الحدث:** النقر على إعادة المحاولة يطلق `micro-error:retry` (bubbles) — فعل المستهلك؛ لا منطق شبكة ولا تخزين في المكتبة.
- **بلا skeleton** عمدًا: حركة تزيينية مستمرة تتعارض مع عقد الحركة؛ الانتظار يعرض بحالة التحميل على الزر.
- الحواف الآمنة ولوحة المفاتيح من عائلة screen؛ تحليل التغطية الكامل في [SCREEN-PATTERNS.md](SCREEN-PATTERNS.md).

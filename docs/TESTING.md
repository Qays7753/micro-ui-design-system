# الفحص الآلي — التغطية والحدود

هذا الدليل هو المرجع الحالي لفحص مكتبة Micro UI: ما تغطيه البوابات الآلية وكيف تُشغَّل، وماذا يعرض المعرض للفحص اليدوي والآلي، وما الذي يبقى خارج التغطية الآلية. لا يوجد هنا سجل جولات ولا أرقام تشغيل؛ النتائج تُقرأ من تشغيل الفحوص نفسها في كل مرة، وعند تغيير المصدر أعد تشغيلها من الرأس الجديد ولا تنقل نتائج تشغيل سابق إلى تعديل لاحق.

## نطاق التغطية

- **مصدر الحقيقة:** فرع `main` الحالي. **الهدف:** [`previews/ui-system-showcase/`](../previews/ui-system-showcase/). **النطاق:** مكونات UI فقط.
- العائلات المشمولة (من `components/` مع fixtures محلية حتمية): surfaces، buttons، fields، selection، organization، info-strip، data، metric-comparison، messages، navigation، access-gateway، account-settings، order-schedule، carousel.
- عرض packed-circle في المعرض أُبدل بأعمدة من المصدر نفسه، ويبقى الملحق PROPOSED اختياريًا في المكتبة؛ ودوائر المقاييس استُبدلت ببطاقات قراءة مدمجة.
- [`previews/concepts/`](../previews/concepts/) و[`previews/compositions/`](../previews/compositions/) عينات تركيب من المصدر، وليست عائلات جديدة ولا شاشات منتج.
- المعرض ليس تطبيق Micro الإنتاجي: بياناته fixtures محلية، ولا شبكة ولا مصادقة ولا حفظ ولا منطق أعمال.

## الفحوص الآلية

1. **تدقيق كل عائلة** — [`tools/component-audit-check.py`](../tools/component-audit-check.py): تدقيق بصري/تفاعلي يقوده الكتالوج لكل العائلات الـ14 وكل المتغيرات الاختيارية (opt-in)، Light فقط، على 360×780 RTL مع حركة مخفّضة. يتحقق أن منتقي المراجعة يغطي كل عائلة في الكتالوج مرة واحدة بالضبط، وأن كل عائلة معزولة ومُصيَّرة داخل 360px، وأن مثال كل متغير اختياري ظاهر ومرسوم فعلاً من المصدر، وأن جداول المقاييس تعرض قيم المصدر.
2. **فحوص سياق المنتج** — [`tools/product-context-check.py`](../tools/product-context-check.py): عقود واجهة C07–C12 وC14 على هاتف Light RTL، مع فحوص ضيقة/LTR محدودة، بلا خدمات.
3. **مصفوفة الإصدار الخفيف** — [`tools/light-release-check.py`](../tools/light-release-check.py): مراجعة Light-only مستقلة للمعرض من المصدر الحي وعقود الحقول عبر Chromium حقيقي على العروض 320/360/390/430. مستوى الطباعة المفحوص هو تكبير نص CSS مرئي (ليس zoom المتصفح)، والفحص لا ينفّذ Dark ولا يحاكيه. وضع `--review-scope` يضيّق المصفوفة إلى 360×780 RTL بنص عادي وDPR1، وهو ما يشغّله المشغّل الموحّد أدناه.
4. **فحوص تجربة الهاتف** — [`tools/mobile-experience-check.py`](../tools/mobile-experience-check.py): فحوص مركزة لتجربة الهاتف، Light فقط، بمنفذ عرض أساسي واحد.
5. **البوابات الثابتة** — [`tools/light-static-check.py`](../tools/light-static-check.py): بوابات ثابتة قابلة للتكرار لإصدار Light-only دون تنفيذ Dark؛ قيم الهوية من `tools/baselines/identity.json`، والمقارنة مقابل `origin/main` افتراضيًا (تُغيَّر بـ`--base`)، ومنع حذف المصدر القابل للتعديل (`components/` و`shared/` و`assets/` و`previews/`).
6. **فحص بناء standalone الحتمي** — `python3 tools/build-ui-system-showcase-standalone.py --check`: يعيد توليد `standalone.html` ويتحقق أن الملف المولّد مطابق للمصدر حرفيًا.
7. **فحوص الكتالوج والبيان** — `python3 tools/component-catalog-build.py --check` يشتق جرد المكونات من كتالوج النضج الوحيد دون طلبات شبكة، و`python3 tools/manifest-build.py --check` يتحقق من بصمات sha256 لملفات التسليم في `MANIFEST.json`.
8. **المشغّل الواحد** — `uv run python tools/check-all.py` من جذر المستودع (بعد `uv sync`): يشغّل كل البوابات أعلاه، وبوابات المرحلة 4 الإضافية (`light-calendar-check.py` و`light-data-check.py` و`component-consumption-contract-check.py` و`integration-boundaries-check.py` و`clone-lifecycle-check.py` و`numeric-geometry-check.py` و`ui-system-showcase-check.py` و`preview-runtime-check.py`)، وأدوات البناء بوضع `--check`، و`link-check`، و`git diff --check`؛ يبدأ خادم المعاينة تلقائيًا على المنفذ 5000 للبوابات التي تحتاجه، يطبع ملخصًا لكل بوابة، ويفشل عند أي إخفاق. الوضع `--quick` يكتفي بالبوابات الثابتة وبوابات البناء، و`--skip-visual` يتخطى بوابة التطابق البصري (تشخيص يدوي فقط — CI يشغّلها أيضًا).
9. **التطابق البصري (D12/R-D12)** — `uv run python tools/visual-regression-check.py --out <مجلد-مؤقت>`: يلتقط 360×780 RTL Light لكل صفحة (بإعادة استخدام `visual-baseline-capture.py`) ثم يقارن بكسل-بكسل مع مرجع **يُولَّد آليًا من git ref** (الافتراضي `v0.1.0` عبر `--baseline-ref`، أو `--baseline <dir>` لمرجع جاهز) داخل worktree مؤقت يُحذَف دائمًا بعد الفحص — لا صور مرجعية في المستودع ولا مسارات آلة خارجية (إصلاح F6). إن كانت نسخة الـref تحتاج بناءً (لا `dist/` فيها) تبنيه الأداة داخل الـworktree تلقائيًا. الصفحة تنجح عندما يكون اختلاف البكسلات ≤ 0.1% من مجموعها (قرار D12)، واختلاف المقاس فشل للصفحة دائمًا. الصفحات المدرجة في [`tools/baselines/visual-allowlist.json`](../tools/baselines/visual-allowlist.json) (بسبب وقرار) تُبلَّغ «اختلاف مسموح» ولا تُفشل البوابة، إلا إذا اختلف المقاس أو تجاوز الاختلاف 15% فيُفشلان دائمًا (R-D13). الصفحات الجديدة بلا مرجع والمحذوفة تُبلَّغ ولا تُفشل البوابة.
10. **CI** — [`tools/ci/ci.yml` (يُركّب في `.github/workflows/`)](../tools/ci/ci.yml) يعمل على `push` و`pull_request` على Ubuntu: checkout كامل بالوسوم، Python 3.12 عبر uv، Node 20، `npm ci`، تثبيت Chromium لـPlaywright، ثم `uv run python tools/check-all.py` كاملة (تشمل البوابة البصرية: مرجعها يُولَّد من git ref داخل CI نفسه — R-D12)، و`npm run typecheck`. تركيب الملف في `.github/workflows/` بيد المالك (R-D14) لأن التوكن الحالي بلا نطاق `workflow`.
11. **جرد الأدوات** — تصنيف كل ملف في `tools/` (بوابات حالية / أدوات بناء / محذوفة مع التغطية البديلة) موثق في [tools/README.md](../tools/README.md).

مخرجات الفحوص التفصيلية مؤقتة (تُمرَّر عبر `--out` إلى مجلد خارج الشجرة) ولا تُحفظ في المستودع.

## ما يتحقق منه الفحص

تحميل الأصول المحلية، RTL (مع LTR مسار مقارنة)، العروض 320/360/390/430 في مصفوفة الإصدار، تكبير نص CSS، النصوص الطويلة، الحالات المفقودة والسالبة، الرسوم — ومنها حالة «لا بيانات» الصادقة مقابل الصفر الحقيقي وجدول إفصاح كامل (وحدة/فترة/مقام) لكل رسم كمّي — والتركيز والطبقات حيث ينطبق، والحركة المخفّضة، وعدم وجود أخطاء JavaScript أو overflow في المسارات المفحوصة.

## أسطح المعرض

المعرض ثلاثة أسطح فحص تُفتح بروابط العمق وتُستخدم في أدوات التحقق الآلي، ولا تظهر أدوات الفحص داخل سطح التطبيق نفسه:

- **`#app` — المعاينة المحمولة (الافتراضي):** تطبيق هاتفي متماسك من مكونات المكتبة الحقيقية (الرئيسية/الطلبات/التقارير/حسابي + تسجيل الدخول) ببيانات محلية حتمية، بلا وسوم مكوّنات ولا أدوات فحص ولا إطار جهاز؛ منفذ العرض نفسه هو الهاتف (360×780 قياسًا مرجعيًا).
- **`#component-review` — مراجعة المكونات الكاملة:** منتقي عائلات معنون يعرض كل عائلة من العائلات الـ14 على حدة في سطح بعرض هاتف. Donut وBubbles وPacked Circle الفعلي (PROPOSED) والمقياس الرئيسي المميز ولمحة Info Strip أمثلة عاملة وليست شارات تغطية؛ الأعمدة تبقى بديل المقارنة الدقيقة بجانب مثال Packed الاختياري. «نظرة عامة» بقيت ملخصًا قصيرًا اختياريًا وليست تغطية كاملة.
- **`#state-lab` — مختبر الحالات:** كل الأقسام الـ15 مع أزرار الاتجاه/العرض/الإجهاد وسجلات الأحداث؛ أدوات التحكم بالعرض والاتجاه والـfixtures وسجلات الأحداث تخص هذا السطح وحده.

إجراء «مكتبة المكونات» في معاينة الحساب داخل `#app` يفتح مراجعة المكونات الكاملة. افتراضات الرسوم في المعرض: أعمدة/صفوف/جداول للمقارنة الدقيقة، والخط (Line) اختياري فقط لتسلسل زمني أو مرتب ذي معنى. النضج يبقى ملك الكتالوج ([`COMPONENT-CATALOG.json`](COMPONENT-CATALOG.json))، وعلامتا `DRAFT FOR REVIEW` و`PROPOSED` حالتا عرض وليستا اعتمادًا إنتاجيًا.

## تشغيل المعرض

من جذر المستودع:

```bash
python3 tools/preview-server.py
```

ثم افتح `http://localhost:5000/previews/ui-system-showcase/index.html`، أو افتح [`standalone.html`](../previews/ui-system-showcase/standalone.html) مباشرة من `file://`.

مصدر حقيقة المعرض: `index.html` (التركيب) و`showcase.css` (CSS المعرض بتوكنز المكتبة) و`showcase.js` (fixtures والتحكم في العرض)، والمكونات الفعلية تأتي من `components/` عبر المسارات النسبية. `standalone.html` ملف مولّد: لا تعدّله يدويًا.

## قواعد الإصلاح

- أصلح المصدر داخل `components/` أو `shared/` أو مصدر المعرض، لا `standalone.html`.
- لا تغيّر ألوان الهوية أو الخطوط أو الأيقونات أو التوكنز دون قرار صريح.
- لا تحل ضيق الهاتف بقص البيانات أو hard-coding جديد عندما يوجد توكن أو عقد قائم.
- راجع RTL، النص الطويل، الأرقام، الحالات المفقودة والسالبة، الطبقات، التركيز والحركة المخفّضة.
- بعد كل إصلاح، شغّل الفحص الأقرب ثم المشغّل الكامل `uv run python tools/check-all.py`، وسجّل ما لم يُختبر فعليًا.

## ما لا يُختبر آليًا

الفحوص الآلية كلها Chromium/Playwright على سطح المكتب فقط. ما يلي خارج التغطية الآلية ويحتاج مسارًا يدويًا أو منفصلًا يملكه المالك:

- Safari/WebKit.
- الأجهزة الحقيقية، ومنها Samsung Galaxy S25/Chrome.
- اللمس الحقيقي (اللمس في الفحوص محاكاة داخل Chromium).
- قارئات الشاشة (TalkBack/VoiceOver).
- safe areas (مناطق الأمان).
- native zoom (تكبير المتصفح الفعلي؛ المفحوص آليًا هو تكبير نص CSS فقط).
- forced-colors (أنماط الألوان القسرية).

نجاح فحوص Chromium ليس اختبار منصة ولا اعتمادًا بصريًا. لأدوار المالك بعد التسليم — التقبل البصري والاختبار على أجهزة حقيقية وقرارات النضج والدمج — راجع [HANDOFF.md](../docs/HANDOFF.md).

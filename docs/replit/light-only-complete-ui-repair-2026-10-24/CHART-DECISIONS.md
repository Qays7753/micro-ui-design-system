## Decisions

Comprehension scores are reasoned design estimates for a non-specialist, not results from a user study. Technical and communication judgments are separate.

| Type | Decision | Technical verdict | Visual / communication verdict | Comprehension | Reason and evidence |
|---|---|---|---|---:|---|
| Bars | REFINE | Existing renderer preserves values, zero, missing, invalid scale, signed-axis rules and data-table source. Existing CSS boundary applies to actual marks. | Best direct comparison for categories and exact readings. The source label and value stay available when marks cannot carry all text. | 5/5 | Keep as primary comparison. Existing SVG bar boundary was sufficient; no new bar decoration. Baseline and after fixture show the same marks and readings. |
| Line | KEEP | Segments, gaps, categories, signed zero axis and explicit time-axis validation remain intact. Font-ready render remains deterministic in the focused regression. | Useful for ordered trend; categorical labels are not misrepresented as time. Dense labels are sampled or moved to complete rows. | 4/5 | Use for a real ordered trend. No data or axis math changed. |
| Donut | MAKE OPT-IN | Existing denominator, zero, missing, invalid and overflow rules remain; disclosure table rebuilds from source. Arc geometry and palette unchanged. | Limited to a few broad shares. Similar categories require reading the legend and matching colors back to arcs; it is slower than bars for precise comparison. | 3/5 | Keep the specialized share view, but request explicit opt-in in the catalog. Use bars/rows for close values. The same fixture includes three close shares and the exact key. |
| Bubbles | MAKE OPT-IN | Existing radius remains proportional to square-root of value; zero, negative, and missing remain non-area states. Added a one-pixel SVG stroke on positive marks, with SVG overflow visible so the edge is not clipped. | Area differences are less exact than aligned bars; values remain outside the circles. The new boundary separates light fills from the canvas without changing radius. | 2/5 | Retain only for a small number of independent magnitudes, never as the default precision comparison. |
| Packed Circle | MAKE OPT-IN | Existing grouped geometry and area ratio remain; HTML circles receive an inset one-pixel token boundary. No new engine or math. | The overlap reads as clustering, not a precise ranking; labels and the exact key remain. It takes more visual area than its accurate comparison merits. | 2/5 | Keep as explicit experimental/specialized presentation. Existing `data-chart-packed` is already an explicit activation. |
| Metric Circles | MAKE OPT-IN | Existing shared absolute-magnitude scale, state handling, and complete external readings remain. | The visual encodes area only and its external key is necessary for exact reading. Its existing internal edge is already clear in Light. No extra decoration was added. | 2/5 | Keep as an opt-in illustration of approximate magnitude only. Prefer rows/bars for exact comparison. |
| Main Metric, flat | KEEP | Source values, common-unit/period validation, zero and signed bars remain as implemented. | Strongest compact composition for a main reading beside exact comparisons; context is visible and honest when host metadata exists. | 5/5 | Recommended standard comparison composition. The fixture shows positive, negative and missing values without implying a shared unit when absent. |
| Main Metric, featured | MAKE OPT-IN | Same renderer and mathematical rules as flat; the hero remains one value and does not enter comparison scale. | One featured rounded block signals emphasis; repeating it would weaken hierarchy. The hero contains its own value and unit; comparison readings stay outside their bar tracks. | 4/5 | Preserve as an explicit one-off emphasis variant, not the default for every comparison row. |
| Stats | KEEP | Value, label, optional unit, sign, missing state and long-value wrapping remain explicit. | A direct reading is clearer than a chart when no comparison is required. Long values wrap rather than shrink or disappear. | 5/5 | Recommended for a single value. Fixture checks a long Arabic/Latin-safe numeric string at narrow widths and simulated 200% type. |
| Progress | KEEP | Determinate amount and indeterminate state remain distinct; reduced motion is already supported. | A labelled track communicates completion efficiently when a real target and amount are provided. | 4/5 | Keep for actual progress only. The component does not infer a target from a value. |
| Steps | KEEP | Status and order remain host-supplied, with a textual current marker. | Vertical sequence is familiar and mobile-readable; state is not encoded by color alone. | 4/5 | Keep for ordered stages, not a numeric comparison. |
| Disclosure Table | KEEP | Semantic caption, column and row headers, values and state details rebuild from the same DOM source each render. | Best exact-reading and verification surface. It complements a graphic; it is not a replacement for a concise visual overview. | 5/5 | Keep available for every chart; test opens the table and verifies caption, row count and expanded state. |

## Boundary-only changes

| Selector / property | Evidence and change | Why it is limited |
|---|---|---|
| `.m-chart--bubbles .m-bubble__circle circle` | Add `stroke: var(--micro-data-boundary)`, `stroke-width: 1px`, and `vector-effect: non-scaling-stroke` to the SVG data mark. | Positive category fills include pale colors that need separation from the Light canvas. Stroke is on the mark itself. |
| `.m-chart--bubbles .m-bubble__circle` | Set `overflow: visible` on the SVG viewport. | Positive circles use a radius that reaches `viewBox` edge; visible overflow prevents the newly added stroke from being clipped. |
| `.m-chart--packed .m-bubble__circle` | Add `box-shadow: inset 0 0 0 1px var(--micro-data-boundary)`. | Packed circles are HTML spans, so their boundary is inset on the actual visible mark. Diameter and overlap calculations do not change. |
| `.m-metric-circles__bubble` | No change. | The original audit already has an inset edge. Adding another would be redundant. |
| `.m-main-metric__bar` | No change. | An existing token-derived inset edge was present. |
| `.m-chart__bar`, `.m-chart__point`, `.m-legend__swatch`, donut SVG arcs | No change. | Their current boundary rules already target visible marks; donut geometry already has the two ring boundaries. |

## Host context contract

For `.m-chart`, `data-unit` and `data-period` are optional and are rendered only when non-empty. The visible `.m-chart__title` is not repeated. `data-title` is shown only when no visible title exists. Existing `data-common-unit` and `data-common-period` remain the required comparison context for Main Metric bars. The host owns the title, unit, and period; no currency, timezone, range, or business meaning is synthesized. The component does not use axis-label strings to infer dates or periods.

## Catalog request for the owning agent

Please update the shared component catalog and its consumer-facing usage guidance outside this delegated file boundary:

1. Mark Donut, Bubbles, Packed Circle, Metric Circles, and Main Metric featured as opt-in / specialized presentations.
2. Recommend Bars/Rows or Main Metric flat for exact category comparison.
3. State that Donut is for a few broad shares and is not the recommended comparison for close categories.
4. Preserve Stats, Progress, Steps, and Disclosure Table as distinct utilities with their documented meanings.
5. Record that this repair is Light-only; no Dark-mode finding was evaluated or fixed.

No chart was removed: same-data evidence supports retaining the specialized circular types behind deliberate use rather than discarding their bounded use cases. Existing custom SVG/DOM renderer and all numerical rules remain the source of truth.

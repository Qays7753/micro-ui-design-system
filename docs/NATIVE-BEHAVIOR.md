# عقد السلوك الأصلي — Micro UI على الهاتف

هذا العقد يحدد كيف تتصرف مكوّنات المكتبة **كمكوّنات تطبيق هاتف أصلي قدر ما يسمح به المتصفح**: ما تملكه المكتبة، ما يملكه المضيف، وحدود كل منصة. مرجع القرارات: `docs/DECISIONS.md` (N-D1–N-D14). لكل سلوك قسم مرقّم تشير إليه المواصفات والفحوص.

القاعدة العامة: المكتبة UI فقط — لا تملك History ولا بيانات ولا جلسات؛ وكل ما يتجاوز حدود المتصفح يُقال صراحةً (قسم 11).

## 1. استجابة الضغط (Press state)

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | تغذية راجعة فورية للمس (تغميق/تكبير طفيف)، بلا وميض، بلا تأخير 300ms للتكبير. |
| تملكه المكتبة | `:active` فوري بلا انتقال دخول، `touch-action: manipulation` على كل العناصر التفاعلية (يمنع تأخير النقر المزدوج)، `-webkit-tap-highlight-color: transparent` على الجذر التفاعلي، مدة الضغط `--micro-motion-press` (110ms). |
| يملكه المضيف | لا شيء إضافيًا؛ لا يستخدم `cursor` أو تأثيرات hover للتلميح على اللمس. |
| Android/Chrome | يعمل كاملًا؛ النقر السريع المتتابع لا يُغلق التكبير. |
| iOS/Safari | يعمل؛ لا يوجد وميض tap-highlight. |
| حدود المتصفح | لا محاكاة للضغط المطول أو القوة (3D Touch/Haptic Touch) — غير مطلوب. |
| الفحص | آليًا: فحوص الحالة النشطة في بوابات المراجعة (`audit`, `component-consumption`). يدويًا: قائمة الفحص — اللمس السريع والمزدوج على كل زر. |

## 2. التمرير الداخلي

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | تمرير محصور داخل الطبقة/القائمة المفتوحة؛ الخلفية لا تتحرك خلفها؛ لا «سحب للتحديث» عرَضي. |
| تملكه المكتبة | `overscroll-behavior: contain` على كل حاوية تمرير داخل طبقة أو قائمة، ومنع تمرير الخلفية خلف طبقة مفتوحة (عند فتح طبقة من عائلة navigation/action-sheet). |
| يملكه المضيف | تمرير جذر الصفحة (عند عدم استخدام `screen`). |
| Android/Chrome | يدعم `overscroll-behavior` كاملًا. |
| iOS/Safari | يدعمها (15+)؛ قبل ذلك تبقى الحاوية تتمرر داخليًا بدون قصّ، والسلوك الزائد نادر. |
| حدود المتصفح | إيماءة الرجوع الإيمائية من الحافة (Android) قد تبدأ تمريرًا أفقيًا في عناصر أفقية (carousel) — السلوك الأصلي نفسه. |
| الفحص | آليًا: فحص التمرير في `screen-check` و`device-lab-check`. يدويًا: افتح طبقة ومرّر داخلها حتى نهايتها — الخلفية ثابتة. |

## 3. لوحة المفاتيح

قرار N-D10. يتحقق عبر هيكل الشاشة (عائلة `screen`) والحقول (عائلة `fields`).

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | الحقل المركّز يبقى ظاهرًا فوق لوحة المفاتيح؛ شريط الإجراءات السفلي يرتفع فوق اللوحة أو يختفي؛ مفتاح Enter يحمل تلميح فعله (next/done/search/send). |
| تملكه المكتبة | `screen` يتبع `visualViewport` (قسم 5 من مواصفة screen)، `enterkeyhint` افتراضي على حقول fields وفق ترتيب الحقول في النموذج (بدون كتابة فوق قيمة المستهلك)، وEnter في حقل نص مفرد ينقل التركيز للحقل التالي. |
| يملكه المضيف | `viewport-fit` و`interactive-widget` في meta viewport إن أراد سلوكًا مختلفًا للمتصفح نفسه. |
| Android/Chrome | يعمل (حجم نافذة العرض يتقلص مع اللوحة). |
| iOS/Safari | يعمل (اللوحة ترسم فوق الصفحة؛ visualViewport يلتقط الارتفاع). |
| حدود المتصفح | لا تحكم في تخطيط لوحة المفاتيح نفسها ولا في مفتاح الإرجاع الفعلي — `enterkeyhint` تلميح فقط. |
| الفحص | آليًا: `screen-check` (محاكاة تقليص visualViewport) وفحوص fields لقيم enterkeyhint والانتقال. يدويًا: افتح كل نموذج في مختبر الهاتف واكتب. |

## 4. زر الرجوع وإيماءة الرجوع

قرار N-D8.

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | الرجوع يغلق الطبقة العليا أولًا (modal/ورقة/منتقٍ/لوحة تصفية) ويعيد التركيز لفاتحها، ثم يخرج من الشاشة. |
| تملكه المكتبة | وحدة اختيارية `shared/back.js`: `bindBackToLayers(options?) → { destroy() }` — عند فتح طبقة تضيف حالة سجل، والرجوع يغلق الطبقة العليا ويعيد التركيز؛ لا حالات سجل زائدة بعد الإغلاق بالطرق الأخرى. تعمل مع كل عائلة تطلق `micro-layer:open` / `micro-layer:close`. المكتبة **لا تكتب في السجل تلقائيًا** بدونه. |
| يملكه المضيف | استدعاء `bindBackToLayers()` في بداية التطبيق إن أراد السلوك؛ وإلا فالرجوع سلوك المتصفح الخام. |
| Android/Chrome | زر الرجوع وإيماءة الحافة تعملان عبر popstate. |
| iOS/Safari | زر الرجوع في شريط الأدوات يعمل؛ إيماءة السحب من الحافة داخل Safari تعمل في معظم الحالات (قسم 11). |
| حدود المتصفح | لا اعتراض على خروج المستخدم من الصفحة نفسها (السجل له حدود أمان). |
| الفحص | آليًا: فحوص `back.js` (فتح طبقة ثم history.back يغلقها؛ طبقتان بالترتيب؛ الإغلاق بالزر لا يترك حالة؛ destroy). يدويًا: زر الرجوع في الهاتف مع كل طبقة في المختبر. |

## 5. السحب (Drag)

قرار N-D9.

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | سحب أفقي يقلّب البطاقات (carousel/peek) باثبات مغناطيسي؛ سحب عمودي هبوطًا على ورقة سفلية يغلقها؛ modal مركزي لا يغلق بالسحب. |
| تملكه المكتبة | Carousel وPeek عبر `scroll-snap` أصلي (أزرار التنقل وحدث change كما هما؛ **لا تنفيذ أفعال بالسحب**). الورقة السفلية (action-sheet): مقبض سحب ظاهر، سحب هبوطًا بعتبة (30% من الارتفاع أو سرعة كافية) يغلقها عبر مسار الإغلاق نفسه (إعادة التركيز والأحداث)، وإلا ترتد. Pointer events مع `touch-action` صحيح. |
| يملكه المضيف | لا شيء — السلوك داخلي. |
| Android/Chrome | scroll-snap وpointer events مدعومان كاملًا. |
| iOS/Safari | مدعومان (scroll-snap منذ 11). |
| حدود المتصفح | سلاسة القصور الذاتي في scroll-snap من المتصفح، لا تُحاكى. |
| الفحص | آليًا: فحوص السحب في بوابات المراجعة (سحب فوق العتبة يغلق، تحتها يرتد؛ snap يغيّر الموضع ويطلق change مرة). يدويًا: اسحب كل ورقة وكل شريط بطاقات في المختبر. |

## 6. تكبير الخط من إعدادات الجهاز

قرار N-D6.

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | تكبير خط النظام يعيد تدفق النص بلا قص ولا فقدان أرقام/وحدات حتى 200%. |
| تملكه المكتبة | كل توكنز أحجام النص بـ`rem` (قيم مكافئة تمامًا عند جذر 16px)، وأي `font-size` مباشر في CSS المكوّنات محوّل كذلك؛ بوابة `text-scale-check` تثبت إعادة التدفق عند 100/150/200% بلا قص ولا overflow أفقي، وأهداف اللمس تبقى ≥ 48px. |
| يملكه المضيف | لا يثبّت `font-size` على html ببكسل (يفسد التكبير). |
| Android/Chrome | تكبير خط النظام يعمل (يغير حجم خط جذر الصفحة). |
| iOS/Safari | حجم النص الديناميكي لا ينعكس على صفحات الويب إلا عبر إعداد المتصفح نفسه (قسم 11). |
| حدود المتصفح | rem يتبع خط الجذر فقط — التكبير من إعدادات العرض (Display size) يكبر كل شيء ولا يمكن فصله. |
| الفحص | آليًا: `text-scale-check`. يدويًا: كبّر خط النظام إلى الأقصى وافتح المختبر. |

## 7. الاهتزاز (Haptics)

قرار N-D7.

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | نبضة لمس قصيرة عند تأكيد فعل حساس أو خطأ أو إغلاق ورقة بالسحب. |
| تملكه المكتبة | `shared/haptics.js`: `setHaptics(enabled)` و`pulse(kind)` — **معطل افتراضيًا**؛ عند التفعيل `navigator.vibrate(10–15ms)` في الأفعال المحددة فقط؛ يُهمل مع `prefers-reduced-motion: reduce`. |
| يملكه المضيف | استدعاء `setHaptics(true)` إن أراد تفعيله. |
| Android/Chrome | يعمل. |
| iOS/Safari | **لا يتوفر** `navigator.vibrate` — لا شيء يحدث، موثق. |
| حدود المتصفح | لا أنماط اهتزاز متقدمة ولا محرك بدقة (Taptic). |
| الفحص | آليًا: فحوص haptics (معطل افتراضيًا لا استدعاء؛ مفعل يستدعي بالمدة؛ لا استدعاء مع تقليل الحركة). يدويًا: فعّل الاهتزاز من أدوات المختبر (Android فقط). |

## 8. حواف الشاشة الآمنة (Safe areas)

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | المحتوى والحقول والأزرار لا تقطعها النوتش ولا شريط الإيماءات. |
| تملكه المكتبة | `env(safe-area-inset-*)` في هيكل الشاشة (`screen`) للحواف الأربع، والحشوة السفلية للمحتوى تُحسب بارتفاع الأشرطة الفعلي (ResizeObserver). |
| يملكه المضيف | `<meta name="viewport" content="…, viewport-fit=cover">` بدونه ترجع env إلى 0 (موثق في README لكل من screen والمختبر). |
| Android/Chrome | يعمل في وضع ملء الشاشة/التطبيق المثبت. |
| iOS/Safari | يعمل مع viewport-fit=cover (النوتش وDynamic Island). |
| حدود المتصفح | لا كشف لشكل النوتش نفسه، فقط القياسات الرسمية. |
| الفحص | آليًا: `screen-check` بمحاكاة قيم safe area. يدويًا: جهاز بنوتش — راجع هوامش أعلى/أسفل. |

## 9. الحركة

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | حركة سريعة هادفة (فتح/إغلاق/تحديد) لا حركة تزيينية. |
| تملكه المكتبة | كل المدد والمنحنيات من `shared/tokens.css` (`--micro-motion-*`, `--micro-ease-*`)؛ لا حركة تغيّر layout؛ `prefers-reduced-motion: reduce` يجعل الانتقالات فورية/مختصرة بلا حركة مكانية. |
| يملكه المضيف | لا شيء إضافيًا. |
| Android/Chrome | كما هو. |
| iOS/Safari | كما هو (منحنيات cubic-bezier مدعومة). |
| حدود المتصفح | لا حركات نظام أصلية (shared element transitions) — خارج النطاق. |
| الفحص | آليًا: بوابات المراجعة تعمل بـ`reduced-motion: reduce`، وفحوص الحركة في audit. يدويًا: أوقف «إزالة الحركة» من إعدادات الوصول وجرّب الفتح/الإغلاق. |

## 10. التركيز وقارئات الشاشة

| البند | العقد |
|---|---|
| كما في التطبيقات الأصلية | كل عنصر تفاعلي له اسم ودور وقيمة بالعربية، والترتيب منطقي، والتركيز مرئي ومُعاد بعد الإغلاق. |
| تملكه المكتبة | أسماء/أدوار ARIA في كل عائلة، إعادة التركيز لفاتح الطبقة، حصر التركيز داخل الطبقات، `dir="rtl"` واضح، الفحوص الآلية تثبت الترتيب والحصر. |
| يملكه المضيف | تشغيل قارئ الشاشة نفسه وخياراته. |
| Android/Chrome | TalkBack يقرأ الأسماء المعلنة. |
| iOS/Safari | VoiceOver يقرأها. |
| حدود المتصفح | الفحص الآلي (Chromium) لا يثبت تجربة القارئ الفعلية — تحتاج جهازًا (قسم «ما لا يُختبر آليًا» في AGENTS.md). |
| الفحص | آليًا: بوابات audit/layers. يدويًا: TalkBack/VoiceOver على خطوات قائمة الفحص الأساسية. |

## 11. ما لا يمكن مطابقته في الويب — بصراحة

1. **الاهتزاز على iOS/Safari:** `navigator.vibrate` غير موجود — لا اهتزاز هناك إطلاقًا (قسم 7).
2. **إيماءة الرجوع على iOS داخل Safari غير المثبت (PWA بدون تثبيت):** إيماءة الحافة قد ترجع في السجل بدل أن تُلتقط — سلوك النظام، لا يتحكم به الويب.
3. **لوحة مفاتيح النظام بلا قياس دقيق قبل ظهورها** ولا التحكم في تخطيطها أو مفاتيحها (تلميح فقط).
4. **تكبير خط iOS الديناميكي (Dynamic Type):** لا ينعكس تلقائيًا على محتوى الويب — المستخدم يكبر من المتصفح أو إعدادات العرض.
5. **القصور الذاتي الأصلي للسحب (native scroll physics)** في scroll-snap: سلوك المتصفح القريب جدًا، ليس مطابقًا بايت-ببايت.
6. **safe-area داخل متصفح بدون viewport-fit=cover** أو على أجهزة بلا قياسات معلنة: القيم صفر والمسؤولية على المضيف.
7. **قارئات الشاشة واللمس الحقيقي وأجهزة فعلية:** غير مختبرة آليًا — قائمة فحص المالك (`docs/DEVICE-CHECKLIST.md`) هي الأداة.

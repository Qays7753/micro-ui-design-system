# إقفال مكتبة المكونات واعتماد الدمج

وافق المالك صراحة على إكمال العمل داخل مكتبة المكونات ودمجه في main، ثم إخباره بالجاهزية لبدء مرحلة التطبيق. هذا الإقفال لا يفتح أو يفحص أو يعدّل تطبيق Micro، ولا ينفذ خدماته. استُخدم فرع Feature الموجود فقط، دون إنشاء PR أو نشر أو حذف فرع.

مرجع بداية المراجعة `aed8bce26960b75723ac89d4cd9c672b6a5ee475`، وmain المفحوص `280b33b988428e3085c28cc150a0c71deb419889`. مرجع الإقفال هو commit الذي يحتوي هذا التقرير والتغييرات الموثقة؛ SHA النهائي وحالة main تؤكدان بعد الرفع في رسالة التسليم. لا commit ذاتي داخل الملف ولا إعادة تحرير لمرجع handoff السابق.

## النطاق المنجز

أُقفلت مراجعة المصدر والتفاعل لتراكيب C07–C12: الحساب والسياق، العملية والاتصال، Market، Delivery، Ask Micro، والمراجعة. [جدول التغطية](COVERAGE.md) و[العقد والأبعاد](../../components/product-context/specification.md) و[المختبر ذو26 عينة](../../previews/product-context/index.html) ودليل [الاستهلاك والنقل](TRANSFER.md) موجودة. لم تُنشأ عائلات أو أزرار أو طبقات أو عارض صور بديل عن المصدر الحالي.

الكتالوج14 عائلة/8 متغيرات/12 تركيبًا، ونضجه محفوظ. موافقة الدمج اعتماد لهذه الدفعة من المصدر وليست اختبار جهاز فعلي أو ترقية تلقائية لـDraft/Proposed. الهوية والشعار والخطوط والتوكنز الأصلية محفوظة، Light وهاتف/RTL، ولا تشغيل Dark أو تخطيط ديسكتوب.

## عيبان مؤكّدان أُغلقا قبل الدمج

[الدليل قبل الإصلاح](closure-evidence/before.json) أُخذ منaed8bce عبر مصدر المكتبة عند360×780 RTL:

| الحالة | النتيجة قبل الإصلاح | الإصلاح والتحقق |
|---|---|---|
| تبديل سجل إعلان داخل Workspace نفسه | عنوان المسودة وملف الصورة من السجل الأول بقيا في محرر السجل الثاني | ربط المسودة بـmode/id/draftKey إضافة إلىscope؛ تُمسح الحقول وتُلغىFile URLs عند تبديل مالكها. اختبار إعادة النشر يثبت أن payload يخص المدخل الجديد بلا مرفقات قديمة. |
| سحب visibility.addresses بعد تعبئة نموذج الطلب | أخفى العرض الساكن العنوان، لكن input احتفظ بالقيمة السابقة | سحب visibility.addresses/contact/evidence الممنوحة ينظف البيانات المحلية قبل العرض؛ العنوان المخفي لا يُعاد إرساله كمسودة قديمة. |

المصدر المعدّل: [product-core.js](../../components/product-context/product-core.js). أضيفت8 اختبارات انحدار مركزة إلى [product-context-check.py](../../tools/product-context-check.py)، دون حذف أو إضعاف الـ230 السابقة. اختُبر تبديل mode وسجل ومحادثة مستقلة، إلغاء روابط المرفقات، وبقاء التحرير في السجل نفسه عند تحديث revision العادي. API الجديدة الاختيارية draftKey تمكّن المضيف من تعريف هوية محادثة أو نموذج إنشاء بلا id؛ لا تخزين أو cache متعددة السجلات أو سياسة أعمال جديدة.

## نتائج الإقفال

[سجل البوابات النهائي](closure-evidence/GATES.md) وروابط JSON الخام والبصمات يثبتان المصدر المختبر. نُفذت238 تحققًا مركزًا و948 تحققًا لبوابات المكتبة الحالية: **1186 ناجحًا/0 إخفاق في18 بوابة متصفح**. نجحت368 فحصًا ساكنًا، والبناء الحتمي والكتالوج وملفات المراجعة وMANIFEST وgit diff --check بعد تثبيت الأدلة كما في السجل. صُححت أوامر AGENTS الحالية لتشير إلى بوابات Light بدل أمر تاريخي يشمل Dark.

القياس360×780 RTL Light، و320 للحالات الضيقة المحددة، وLTR360 للصور/المحادثة، والحركة العادية/المخفّضة. لا browser exceptions أو موارد فاشلة في التشغيل الناجح. اللقطات الفعلية: [Market](closure-evidence/market360.png)، [Delivery](closure-evidence/delivery360.png)، [Ask](closure-evidence/assistant360.png)، [محرر320](closure-evidence/market320.png). لا تغيّر بصريًا مقصودًا في هذه التنقيحات؛ الإصلاح لدورة حياة البيانات المحلية.

## ما يعنيه «اكتملت» هنا

لا توجد عيوب مؤكدة مفتوحة ضمن إقفال المصدر الحالي. حُسمت مراجعة المصدر والدمج بتفويض المالك؛ لا انتظار موافقة إضافية لهذا الدمج. وثائق انتظار المراجعة في [تقرير الدفعة السابق](REPORT.md) سجل سابق تتقدم عليه هذه الموافقة.

الخدمات والمصادقة الحقيقية والصلاحيات الخادمية ورفع الملفات وAI والمزامنة ليست تنفيذًا ناقصًا مخفيًا داخل المكتبة؛ هي خارج نطاقها. قرارات المنتج المحفوظة في [COVERAGE](COVERAGE.md) — مثل مهلة عرض التوصيل، قواعد الموافقات والإثبات، سياسة الإعلان وأدوات المساعد — تبقى مداخل قابلة للتهيئة حتى تُحسم مع المنتج. لم تُخترع قواعد لتعبئة قائمة، ولم يُضف أثر مالي تلقائي من Market/Delivery إلىManage.

فحص Samsung S25 الفعلي وTalkBack/Safari وsafe areas لم يُنفذ، ولا يدعي الدمج نجاحها. تظل بوابة منصة مستقلة خلال التحقق داخل التطبيق لاحقًا. لا ادعاء اكتمال تطبيق إنتاجي أو تجربة Native أصلية.

الخطوة التالية هي بدء مرحلة مستقلة للتطبيق بعد هذا الإقفال: فحص البنية المصرح بها وتخطيط الاستهلاك دون اعتماد تصميمه أو سلوكه القديم مرجعًا صحيحًا. تُنقل المصادر مرة واحدة عبر adapter مشترك، مع scope/dataContext وid/mode/draftKey وresolve/destroy ومالك طبقات واحد، حسب [دليل النقل والتعارضات المحتملة](TRANSFER.md). لم تبدأ هذه المرحلة هنا.

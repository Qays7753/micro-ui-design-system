# قراءات منظمة من مصدر المكونات — C04

قرار المالك 2026-11-12، تنفيذ اختياري بحالة **Draft للمراجعة**. هذا امتداد للمصدر القابل لإعادة الاستخدام، وليس نقلًا للـprototype أو شاشة منتج. [المعاينة الفعلية](../previews/readable-source/index.html)، [ملف مراجعة مستقل مولّد](audits/readable-source-2026-11-12/review.html).

## ما يُحمّل مرة

الخطوط و`shared/tokens.css`، ثم `components/buttons/buttons.css` مرة قبل CSS العائلة عند استخدام رسوم JavaScript وجداولها أو أدوات التحديد، ثم CSS وJS العائلة المستخدمة. `buttons.js` غير مطلوب لهذه الأفعال العادية. `components/compositions/reading-layout.css` يوفر إطار المجموعة، الرأس، القراءة الرئيسية، الزوج الدلالي، الفصل والإفصاح. لا يلزم CSS أو JavaScript من previews. أبعاد الأدوار تستعمل التوكنز الحالية؛ لا تعديل للهوية أو المقاسات العامة.

C04 ليس عائلة خامسة عشرة. C01/C02/C03 باقية. يمكن وضع `data-reading-unit` على وحدة C01 أو قيمة C02 واستخدام سياق C04 نفسه، دون نسخ تنسيقات الصف أو البطاقة. `.m-reading-group__amount` للقراءة الرئيسية36؛ عنوان المجموعة18؛ النص16؛ تسمية14؛ سياق13. الزوج `.m-reading-group__pair` لقيمتين مستقلتين، وليس بديلًا عامًا لكل بطاقة أو جدول. لا تُحشر فئات كثيرة في الزوج.

## الوحدات: أمان افتراضي

الوحدة ظاهرة افتراضيًا: **150 د.أ** تختلف عن **149 قطعة**. لا اختصار K/ألف تلقائي، ولا نسبة بدل المقدار. `data-display` في Data و`data-display-value` في Metric بالعرض الجديد لتنسيق الرقم نفسه؛ الوحدة منفصلة في `data-unit`، فلا تُضمّن مرة ثانية داخل النص المنسق. تبقى القيم الخام في الجدول، ولا يُستنتج نوعها من حجمها.

الاختصار الموضعي اختياري عبر تحميل `reading-context.js` مع CSS السابق:

```html
<section class="m-reading-group" data-reading-context="money-context" data-unit="د.أ" aria-describedby="money-context">
  <p id="money-context">هذا الأسبوع · د.أ</p>
  <span><bdi dir="ltr">150</bdi> <span data-reading-unit="د.أ">د.أ</span></span>
</section>
```

`MicroReadings.init(root?)` و`sync(root?)` يقبلان الجذر وأبناءه؛ `disconnect(root?)` يعيد الوحدات إلى الظهور. لا مستمعات أو مراقب أو مؤقت لكل مجموعة. المستهلك يستدعي sync بعد تغيير النص/الوضوح/السياق، بما فيه تغييرات responsive خارج رندر العائلة، وdisconnect عند التنظيف. Data وMetric يستدعيان sync بعد رندرهما إن كان المساعد محمّلًا. غيابه يعني إبقاء الوحدات ظاهرة.

لا يختصر المساعد إلا إذا عرّف الجذر `data-unit` أو `data-common-unit`، وطابقت الوحدات كلها هذا السياق، وكان المعرّف يشير إلى نص ظاهر كامل غير مقصوص يذكر الوحدة حرفيًا كوحدة مستقلة، لا كجزء من كلمة أو وحدة أخرى: g داخل kg و«م» داخل «المخزون» لا يكفيان. اكتب الوحدة بفواصل واضحة مثل «الوزن (g)» أو «هذا الأسبوع · د.أ»؛ عند الالتباس تبقى بجانب القيمة. المجموعات المتداخلة تملك سياقها. الاختصار بصري فقط: تبقى الوحدة في DOM وشجرة الإتاحة، ولا يُحذف metadata. لا تكتب `.m-reading-unit--contextual` يدويًا. المجموعة المختلطة أو العنوان الغائب/المخفي/المقصوص تستعيد الوحدات عند sync. لا تستخدم label محجوبًا أو سياقًا لا يستطيع المستخدم ربطه بصريًا بالقيم. يشمل التحقق قصّ العنوان من حاوية أب؛ لا تكفي عملة داخل ابن hidden/شفاف/مقصوص بصريًا لإخفاء الوحدة. يبقى تحقق sync صريحًا عند تغيير السياق، ولا يضاف مراقب أو مؤقت.

## Data: قراءة مباشرة واختيار مستقل

`data-presentation="readable"` يفعّل سياقًا موجزًا، مفاتيح دونات بصفوف كاملة وقيم بوحداتها، وجدولًا بقيم خام ووحدات. عند اختلاف وحدة أو فترة العناصر لا يرسم مقياسًا نسبيًا مضللًا؛ يعرض كل قراءة ووحدتها وفترتها، مع `data-reading-state="mixed-context"` وتعطيل اختيار المقارنة (`data-selection-state="mixed-context"`)؛ لا إجمالي أو نسبة مشتركة بين وحدات مختلفة. لا تُستنتج فترات أو عملات. في هذه الحالة يحتوي الجدول عمود «الفترة» لكل صف، مع «(فترة غير محددة)» إذا غابت، ويحتفظ caption باسم الرسم. يعود الجدول للبنية المعتادة عند تجانس السياق. سمات العنصر `data-unit`/`data-period` تتقدم على الجذر في هذا المتغير فقط. السلوك القديم بلا العلمين باقٍ.

`data-selection="single"` مستقل عن readable ويدعم bars/line/donut فقط. كل `li` في مصدر البيانات يحتاج `data-key` نصيًا فريدًا غير فارغ؛ `data-series` هو لون الفئة وليس هوية العنصر. لا اختيار افتراضي مخترع. `data-selected-key` اختيار أولي صريح من المستهلك؛ وبلا اختيار يختار زر «التالي» أول عنصر فعليًا. لا يفتح الجدول أو الإفصاح تغييرًا للاختيار.

```js
MicroData.init(chart);                       // API التهيئة الحالي
MicroData.setSelection(chart, 'stable-key'); // صامت
const selection = MicroData.getSelection(chart);
MicroData.setSelection(chart, null);         // مسح صامت
chart.addEventListener('micro-data:selection-change', event => {
  // استجابة المستهلك لاختيار المستخدم فقط، دون حفظ أو شبكة من المكتبة.
  console.log(event.detail);
});
MicroData.render(chart);                     // رسم واحد بعد تحديث source DOM
MicroData.disconnect(chart);                 // إلغاء الحراس والمراقبين قبل الإزالة
```

نص aria-valuetext يتبع القيمة والحالة والوحدة المرئية نفسها؛ data-display قديم لا يغلب المفقود أو الخام غير الصالح، والسالب غير المرسوم يبقى موصوفًا. هذا تحقق للنص المتاح، وليس إثبات نطق قارئ شاشة فعلي.

النتيجة نسخة جديدة أو null: `{key,label,value,rawValue,display,invalid,unit,period,share}`؛ `share` كسر0..1 فقط لتوزيع دونات بمقام صالح وإلا null. المعطيات الخام محفوظة، والمفقود null وليس0. مفتاح غير موجود في setter يُتجاهل. الحدث يتصاعد مرة واحدة لتغير اختيار المستخدم فعليًا؛ setters وinit/render لا يطلقونه. حدث `micro-data:rendered` القديم يبقى مستقلًا.

إعادة ترتيب البيانات تحفظ الهوية بالمفتاح؛ حذف المحدد يمسحه صامتًا دون اختيار بديل. مفاتيح مكررة/فارغة أو مصدر فارغ تعطل الاختيار وحده (`data-selection-state=invalid-keys|empty`) وتحفظ القراءات. لا تستخدم ترتيب li كهوية. تحديث البيانات والسياق يتبعه render؛ لا يراقب المكوّن كل تعديل source DOM. disconnect يحتفظ بالبيانات/المفتاح ويوقف التفاعل؛ init يعيد ربط نسخة واحدة. لا تكتب في العقد المولدة من إطار المضيف والـrenderer معًا.

الأعمدة والخط يملكان range أصليًا وزري B01 secondary بارتفاع أدنى48px وخط16 تحت الرسم، وقراءة محددة حية وعلامة على العنصر. مفتاح الدونات أزرار48px مع aria-pressed واسم/قيمة واضحين؛ النسبة ثانوية وتظهر للفئة المحددة فقط. لا نضيف هدف لمس صغيرًا إلى كل SVG. التركيز يبقى في range عند التحديث، أو يرجع إلى زر الفئة بمفتاحه بعد إعادة بناء المفتاح؛ عند حذفها ينتقل إلى تحكم متاح في الرسم. إذا تعطّل زر الحدود ينتقل التركيز إلى range المتاح؛ وإذا أزيلت أدوات التحديد أثناء render ينتقل إلى تحكم باقٍ، مثل إفصاح البيانات. لا يغير render التركيز الموجود خارج الرسم. disconnect عند إزالة التركيب يترك إرجاع التركيز لمالك التركيب.

**اتجاه المحور لم يتغير:** الأعمدة غير الموقعة الحالية ترتب مصدرها من اليسار إلى اليمين في SVG، فيتبعها range. الخط والأعمدة الموقعة يتبعان `data-axis-dir` الحالي، وافتراضيه RTL؛ وقت الخط من `data-axis-type="time"` و`data-x` وفق العقد الحالي. لا تغيير محور تلقائي بسبب لغة الصفحة.

الدونات خيار متخصص لتركيب أجزاء من إجمالي، والخط فقط إذا كانت علاقة الزمن مفيدة ومفهومة. البداية البسيطة bars/rows + المقدار الحقيقي. لا نسبة من سالب أو مقام غير صالح، ولا تحويل غياب إلى صفر. لا تغيير للخيارات المتخصصة الموجودة أو حذفها أو ترقية نضجها.

## MetricComparison: صفوف متراصفة

`.m-main-metric--readable` يضع اسم الفئة والمسار والقيمة في ثلاثة أعمدة مشتركة، مع وحدات منفصلة وأرقام معزولة. الأسماء والقيم الطويلة تلتف كاملة، ولا يصبح مسار صف أقصر لمجرد طول تسميته. المحركات بلا subgrid تحتفظ بالصفوف الأصلية كاملة العرض. ارتفاع المسار الحالي12، أو8 فقط عند اختيار compact الموجود؛ لا تصغير عام.

التحقق الحالي من الوحدة والفترة والمقياس يبقى. الصفر والمفقود والخطأ والسالب مميزون؛ الخام غير الصالح ظاهر في المتغير الجديد مع تشخيصه. API الحالي `init/render/disconnect` لا يتغير. ليست الأعمدة الثلاثة جدولًا إجباريًا لكل شاشة أو لكل عائلة.

## تقدم عام، لا محرك فواتير

Progress يبقى CSS فقط. المستهلك يوفّر القيمة والهدف والمتبقي والنسبة والتجاوز وحالة الهدف المفقود/الصفر. الشريط يحدّ قصّ الرسم، لكن النص يحتفظ مثلًا بـ130% عند التجاوز؛ aria-valuenow لا يتجاوز max، وaria-valuetext يذكر القيمة الحقيقية. عند غياب/عدم صلاحية المقام لا تعرض0% مخترعة؛ اذكر الحالة وأزل aria-valuenow عند النسبة غير المحددة. صفر الهدف حالة موصوفة لا قسمة على صفر. الربط بين فواتير وحسابات أو عمليات دفع ليس مسؤولية هذا المستودع.

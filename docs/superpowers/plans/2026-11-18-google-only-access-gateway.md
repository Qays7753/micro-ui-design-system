# Google-only Access Gateway UI Implementation Plan

**Goal:** تجهيز تركيب ترحيب ودخول Google داخل عائلة Access Gateway الحالية كمصدر UI قابل للاستهلاك، مع فصل واضح بين تصميم النظام وزر Google الرسمي وخدمة المصادقة التي يملكها المضيف.

**Architecture:** لا ننشئ نظام مصادقة أو عائلة جديدة. يبقى `MicroAccessGateway` API عامًا للنموذج وموفّري UI المخصصين. يوفّر تركيب Google-only موضعًا `data-google-provider-slot` يرسم داخله المضيف زر Google Identity Services الرسمي. لا نعيد رسم زر Google داخل مكتبة Micro ولا نربط GIS أو OAuth أو الجلسة هنا.

**Tech Stack:** HTML/CSS/JavaScript الحالي وأدوات Python/Playwright الموجودة؛ لا حزم أو مصادر شبكة جديدة في المستودع.

**Spec:** `components/access-gateway/specification.md` وقرارات المستخدم: Google فقط للمستخدم الجديد والعائد، دون شاشة Sign-up منفصلة؛ المستودع مستقل عن Micro وخدمات المصادقة.

## Global Constraints

- قاعدة العمل `origin/main` عند `91744a5904eaf8bbd18d6239fcd288aa3eb0c26f`؛ لا تعديل مباشر لـ`main`.
- المستودع الحالي وحده؛ لا فتح أو تعديل أو تكامل مع مستودع Micro.
- Light-only؛ لا تعديل للتوكنز أو الخطوط أو الأيقونات أو شعار v2 أو سياسة اللون.
- Google هو وسيلة الدخول والتركيب المستهدف؛ المستخدم الجديد والعائد يسلكان المسار نفسه.
- زر GIS الرسمي يرسمه المضيف داخل `data-google-provider-slot` وفق تعليمات Google السارية. `.m-google-button` وأصل G المحلي عينات بصرية لا أزرار إنتاج.
- لا OAuth أو backend أو طلبات شبكة أو إنشاء/حفظ جلسة أو تخزين بيانات اعتماد داخل مكتبة UI.
- المضيف يملك credential callback، نتيجة الدخول، حالة الجلسة، الصلاحيات، والروابط/الأفعال التي تخص المنتج.
- لا Splash مستقل أو شاشة Sign-up منفصلة في هذا النطاق، ولا عائلة مكوّنات جديدة.
- اختبار العرض المستهدف 360×780 RTL Light؛ لا ندّعي اختبار جهاز حقيقي أو المتصفح المحمول.

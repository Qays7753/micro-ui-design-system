# قدرات المكونات للهاتف — D01 / C05 / C06

وافق المالك على تنفيذ البنود الثلاثة2026-11-13، وأكد أن Micro **للهاتف فقط حاليًا**. التنفيذ في مكتبة UI المستقلة؛ لا نسخة ديسكتوب أو popover/hover خاص بها، ولا وصول إلى مستودع التطبيق. [مختبر الهاتف](../previews/mobile-capabilities/index.html).

## D01 / UX-06 — طلب إغلاق قابل للاعتراض

`MicroNavigation.requestClose(layer,{reason?,trigger?})` قناة طلب خروج للمستخدم، قبل أي تغيير تقوم به المكتبة للمكدس أو focus أو hidden أو inert أو scroll. تقبل الطبقة المفتوحة العليا فقط؛ الطبقة السفلية أو المغلقة أو التي بدأت الإغلاق والطلب المتداخل لنفس الطبقة no-op تعيد false.

يرسل `micro-navigation:close-request` على الطبقة، bubbles=true وcancelable=true، والتفصيل `{reason,trigger}`. reason أحد escape أوclose-button أوbackdrop أوprogrammatic-request؛ القيمة الغائبة/غير المعروفة تعود إلىprogrammatic-request. trigger عنصر DOM أوnull. لا dirty أو بيانات نموذج أو URL في الحدث.

- `preventDefault()` **متزامن** يمنع الطلب. false تعني عدم بدء الإغلاق بهذه الدعوة؛ true تعني قبول بدء الإغلاق، وليست Promise أو إثبات انتهاء الانتقال. `micro-navigation:closed` هو إشعار الانتهاء الحالي.
- Escape غير المعالج، وdata-layer-close، والخلفية ذاتdata-backdrop=close تمر من الطلب. الخلفية keep لا ترسل طلبًا. Escape يخص أعلى طبقة فقط.
- `closeLayer` يبقى أمرًا صريحًا متوافقًا؛ بعد نتيجة حفظ مؤكدة يمكن للمستهلك استعماله دون تأكيد مكرر. `disconnect` تنظيف قسري لا يمكن منعه. استدعاءات Picker/Settings/الفلاتر الحالية لم تتحول تلقائيًا إلى خروج نموذج dirty.
- إعادة الفتح أو التنظيف أو تغيير الطبقة العليا داخل dispatch يبطل الطلب القديم؛ لا يسمح إغلاق أصل بتجاوز تأكيد أعلى.
- القرار غير المتزامن: امنع الطلب أولًا، ثم افتح تأكيدًا بمالك الطبقات نفسه، واستدعِ closeLayer بعد القبول. لا تعِد إرسال الطلب الذي يعيد السؤال نفسه، ولا تنتظر Promise من dispatchEvent.

المستهلك يملك معرفة التعديلات والانتظار والتحقق والحفظ ونص التأكيد. إذا استعمل مستمعًا على حاوية، يفحص `event.target` حتى لا يمنع خروج طبقة ابن بالخطأ. [مثال محلي](../previews/mobile-capabilities/protected-form.html) يثبت متابعة التعديل أو تجاهله، دون خدمة حفظ. لا يربط Navigation بحوارHTML أصلي في الجذر نفسه.

**حد النطاق:** لا History/URL أو اعتراض لرجوع Chrome/Android بين الصفحات أو إغلاق المتصفح. هذه مسؤولية تكامل التطبيق لاحقًا، ولا تُستنتج من حماية dismissal داخل الطبقة.

## C05 / UX-07 — قائمة إجراءات للهاتف

[المصدر والعقد](../components/navigation/action-sheet.md): تركيب Navigation/B01 بنفس اللون والمقاسات والـsafe-area الحاليين. modal dialog بأزرار أصلية؛ لا menu/listbox roles أو نمط ديسكتوب. [سياقا الصف والبطاقة](../previews/mobile-capabilities/actions.html) يستعملان قائمة مصدر واحدة.

`MicroActionSheet.init/open/close/disconnect` يملك lifetime التركيب فقط. `open(sheet,{trigger,contextKey})` يمرر مفتاح سياق معتمًا؛ المستهلك يملك التسميات والمعرّفات والإتاحة والتعطيل والحالة الفارغة. `micro-actions:request` يحمل `{id,contextKey}` **بعد closed**؛ يسمح للمستهلك فتح واجهة لاحقة دون تداخل مالكي تركيز. لا ينفذ نسخًا أو حذفًا أو صلاحيات أو شبكة.

رفض الإغلاق لا يرسل أمرًا. إعادة الفتح أو التنظيف أثناء الحركة تلغي النية القديمة؛ التكرار لا يكرر التنفيذ. يجب تنظيف التركيب قبل إزالته عبر MicroActionSheet.disconnect، مع غشاء مخصص لكل قائمة. لا APIإجراءات إضافية داخل Picker.

## C06 / UX-08 — ملخص تقويم خارجي

[وصفة الاستهلاك](../components/compositions/calendar-context.md) و[المثال](../previews/mobile-capabilities/calendar-summary.html) يعيدان استخدام C01، خارج جذر Order Schedule. لا تعديل في مصدر التقويم أو حقول الطلب أو حساب مالي/سعة/تكرار.

اختر صراحة «اليوم المحدد» أو «الشهر المعروض»؛ getState يعيدهما مستقلين. مستمع state-change يزامن أفعال المستخدم، ومالك setter البرمجي أو تحديث البيانات يزامن الملخص صراحة لأن setters صامتة. الانتظار لا يعرض قراءة قديمة لفترة جديدة؛ الغياب والخطأ ليسا صفرًا، والفراغ المعلوم يُعرض0 مع الوحدة. أوقف المستمعات والنتائج المتأخرة قبل destroy.

هذه إغلاق لقرار **التركيب الخارجي**، وليست تنفيذًا لحقول metadata داخل الطلب. لا حاجة محددة لتلك الحقول حاليًا؛ أي توسعة لاحقة تُراجع بمحتواها واستخدامها، دون حقن HTMLعام.

## التحقق والنضج

`python3 tools/mobile-capabilities-check.py --out /tmp/mobile-capabilities` يفحص360×780 RTL بمحاكاة لمس هاتف، و320 لضيق الأوامر و360 LTR للاتجاه، وحركة عادية/مخففة، دون Dark أو desktop layout أو zoom. لوحة المفاتيح ضمن إتاحة الهاتف؛ لا نسخة واجهة مكتبية.

يبقى المصدر14 عائلة و8 متغيرات، وأصبح6 تراكيب. C05/C06 Draft، وسائر النضج محفوظ؛ معاينة Galaxy S25/Chrome الفعلية النهائية مؤجلة. نجاح Chromium لا يساوي تحقق اللمس أو قارئ الشاشة أو لوحة مفاتيح الجهاز الفعلية.

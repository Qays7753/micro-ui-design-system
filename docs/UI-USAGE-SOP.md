# SOP استخدام وتعديل Micro UI

## قبل التعديل

اقرأ `AGENTS.md` ثم `DESIGN.md` و`docs/CURRENT-STATE.md` و`docs/COMPONENT-INVENTORY.md`. لا تبدأ من صورة أو standalone أو نتيجة تاريخية.

## مصدر الحقيقة

المكون داخل `components/`، والقيم المشتركة داخل `shared/`، والأصول داخل `assets/`. المعاينة في `previews/` مستهلك للمصدر وليست مصدرًا بديلًا.

## قواعد التنفيذ

- لا hard-coding لألوان أو مسافات لها توكن قائم.
- لا تغيّر الهوية أو التوكنز أو الخطوط أو الأيقونات دون قرار صريح.
- لا تجعل كل معلومة بطاقة، ولا تجعل العنصر غير التفاعلي يبدو تفاعليًا.
- حافظ على RTL والنص الطويل والأرقام والوحدات والإشارات والبيانات المفقودة.
- لا تقص البيانات المهمة ولا تستخدم اللون وحده للدلالة.
- حافظ على الحالات المعلنة `STABLE UI` و`DRAFT FOR REVIEW` و`PROPOSED`.
- لا تعدل ملفات standalone المولدة يدويًا.

## دورة التحقق

بعد تعديل المصدر:

1. حدّث المواصفة والمثال عند تغير العقد.
2. شغّل فحص البناء الحتمي.
3. شغّل فحص الـshowcase وفحص العائلة المتأثرة.
4. تحقق من 320/360/390/430 وRTL والحالات الحدية.
5. شغّل `git diff --check`.
6. سجّل ما لم يُختبر على أجهزة أو متصفحات فعلية.

## التسليم

التسليم هو المصدر القابل للتعديل مع المواصفة والفحص. الصور والملفات المولدة أدلة أو مخرجات نقل فقط، ولا تستبدل HTML/CSS/JS/SVG.

# هندسة مكوّنات Micro على الهاتف

النطاق: مكوّنات UI المستقلة، دون تصميم شاشات منتج أو تطبيق فعلي.
المرجع التنفيذي هو `shared/tokens.css` وCSS المكوّنات. هذه مراجعة للأبعاد
والتفاعل، وليست اعتماد أجهزة Android/iOS أو شهادة مطابقة native.

## الوحدات والهدف

كل الأرقام أدناه **CSS px**؛ لا تعني بكسلات الشاشة الفيزيائية، ولا تُحوّل
تلقائيًا إلى dp أو pt. يوصي Android بهدف 48×48dp وApple بهدف 44×44pt؛
قاعدة Micro المستقلة 48×48 CSS px حيث ينطبق العقد.

- [Android: أهداف اللمس](https://developer.android.com/guide/topics/ui/accessibility/views/apps-views)
- [Apple: هندسة التحكم والقراءة](https://developer.apple.com/design/tips/)
- [MDN: viewport ووحدات CSS](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Viewport)

الحجم المرئي وحجم الإصابة الفعلي قد يختلفان: علامة checkbox ذات قطر/عرض
24px لا تحتاج أن تصبح 48px لأن صف label كله هو هدف اللمس. المقطع المرئي
40px يمد الإصابة رأسيًا إلى 48px، ويجب فحص الامتداد بالنقر لا بالحد الأدنى
في CSS وحده. الأيقونات والعناوين والشارات غير التفاعلية ليست أهداف لمس.

| لمس الحقل | الحشو والوحدة يركزان المدخل؛ المسح والخطوة أهداف مستقلة | الغلاف 52px يشارك فعليًا في الإصابة، رغم أن صندوق نص input نفسه 26px |

| Segmented | شكل بارتفاع 40؛ عرض أدنى 48؛ امتداد رأسي 4 من كل جانب | هدف فعلي 48×48 أدنى؛ صف واحد وتمرير داخلي عند الضيق، وstack صريح |
| صف بمعلومتين | 72 أدنى؛ عنوان 16/26 ووصف 13/20 | مناسب للقراءة واللمس؛ صف إعدادات العينة بلغ 73 حسب البنية الفعلية |

| تبويب المحتوى | 48 أدنى؛ نص 16/24؛ حشو أفقي 16 | التسمية كاملة؛ التمرير الأفقي ملك التبويبات عند الضيق |
| شريط التنقل السفلي | 61 في مثال الأيقونة والتسمية: عنصر 52 + حشو 4/4 + فاصل 1، قبل safe area | أهداف مناسبة؛ صف واحد؛ التسميات تلتف داخل العناصر والارتفاع يتبعها |
| شريط الأفعال | 73 في عينة أزرار 48، قبل safe area | الارتفاع مشتق من الأزرار والحشو والفاصل؛ لا تُفرض إزاحة ثابتة على المستهلك |
| دائرة القيمة الرئيسية | 144×144 في الوضع العادي، ونسخة compact موجودة في المصدر | اختيار بروز وكثافة؛ حجمها لا يثبت تفوقًا أو مطابقة native |
| الأعمدة والخط | viewBox بعرض المكوّن؛ تسميات 13؛ عمود حتى 40؛ خط 2 ونقطة بنصف قطر 4 | النص والحدود ثابتان؛ ارتفاع منطقة البيانات يتبع العرض ضمن حد موثق |
| الدونات | قطر SVG 148؛ نصف قطر المسار 58؛ سماكة 16 | مفتاح تحته قبل عرض مكوّن 340 وبجانبه بعده؛ القراءة الطويلة كاملة خارج الحلقة |
| فقاعات المقدار | SVG؛ القطر `2×Rmax×sqrt(value/max)` | لا حد أدنى للموجب؛ الصفر/الغياب/السالب علامات محايدة مع قراءة خارجية |

انحناء الحقل 16 والزر 24 وسلّم المسافات 4/8/12/16/20/24 قيم هوية قائمة؛
لم تغير هذه المراجعة التوكنز أو الخطوط أو الأيقونات. تحقق أهداف اللمس
لا يعني أن كل أجزاء المكوّن يجب أن تكون بالمقاس نفسه.

## استثناء شبكة الشهر

`order-schedule` يبقى **DRAFT FOR REVIEW**، واستثناء خلايا الشهر
**PROPOSED** حسب مواصفته. سبعة أهداف 48px وفجوات 4px تتطلب عرض محتوى
360px؛ لا يمكن احتواؤها ضمن عرض محتوى 288px على هاتف 320px.

قياسات من المصدر، بإطار اختبار يطبق هوامش 16px دون 390 و20px من 390:

| عرض viewport | عرض المكوّن | خلية اليوم الفعلية تقريبًا |
|---|---|---|
| 320 | 288 | 37.7×37.8 |
| 360 | 328 | 43.4×43.4 |
| 390 | 350 | 46.6×46.6 |
| 430 | 390 | 52.3×52.3 |

هذه الخلايا لا تحقق قاعدة Micro عند أول ثلاثة عروض. لا تُوسّع أهداف
متداخلة بين الأيام ولا يُصغّر النص لإعلان نجاح وهمي. عرض اليوم والقائمة
بديلان موجودان بأهداف أكبر؛ سياسة اعتماد شبكة الشهر تحتاج مراجعة بصرية
وتجربة لمس فعلية. الأزرار الرئيسية للتقويم بقيت 48×48.

## تحقق Web App وحدوده

المكوّنات تستخدم HTML/CSS/JavaScript وتعمل في أمثلتها المستقلة داخل
المتصفح. مسؤولية التطبيق المستهلك تشمل viewport الصحيح، تركيب المكوّنات،
التثبيت بوضع PWA أو WebView، وموضعها بالنسبة إلى أشرطة النظام ولوحة
المفاتيح. لا تُضاف هذه الوظائف إلى مكتبة UI.

- الحافة العليا والجانبية تتبع الحاوية الخارجية. ملكية الحافة السفلية
  للتنقل والأفعال والطبقات موثقة في مواصفة navigation؛ لا تُكررها حاوية
  ومكوّن في التركيب نفسه.
- [WebKit: safe areas وviewport-fit](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)
- [MDN: visual viewport ولوحة المفاتيح](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)

الهندسة وحدها لا تثبت إحساس native: يلزم أيضًا استجابة الضغط، التمرير،
استعادة التركيز، ثبات البيانات، وحركة مناسبة. اختلاف Android وiOS لا
يفرض تغيير هوية Micro، لكنه يتطلب التحقق على المنصتين عند التركيب.

## دليل المراجعة الحالية

المراجعة في 2026-10-12 على فرع `ui/native-svg-polish-2026-10-12` انطلاقًا من رأس `main`
`a27ff0fd22a488175b55f502ba6df082a7c4fd48`؛ ليست نتائج نسخة GitHub المنشورة
قبل هذه التعديلات.

`python3 tools/component-mobile-check.py` يفحص الإصابة الفعلية، المقاطع
القصيرة، تمركز المفتاح واتجاهه، الحقول وأزرار الكمية عند
320/360/390/430 ومحاكاة النص 200%. يحتفظ سجل JSON ببصمة المصادر الفعلية
SHA-256، وتذهب الأدلة إلى مجلد مؤقت افتراضيًا.

`python3 tools/chart-mobile-check.py` يفحص نسب SVG وعرضه، انقطاع الخط
عند الغياب، نقل قراءة الدونات الطويلة، صف التنقل والمقطّع عند تكبير النص
والأسهم في RTL/LTR. مثال الرسوم المستقل داخل `components/data/example-usage.html`.

مراجعة القياسات الإضافية استخدمت CSS المكوّنات دون تنسيق المعرض، مع
viewport الصحيح وخطوط المشروع. بقي عرض الصفحة مساويًا للviewport عند
محاكاة النص 200%، والتمرير الأفقي للتبويبات بقي داخل مكوّنها. قياسات CSS
عند 390 وDPR=1 وDPR=3 كانت متطابقة؛ هذه محاكاة كثافة، لا قياس جهاز فعلي.

ملاحظة تحقق: فحص نسبة مساحات الدوائر السالبة أخفق مرة في تشغيل
`concepts-check.py` المتزامن مع فحوص أخرى، ثم نجح عند الإعادة (157/157).
فحص مستقل تكرر 12 مرة حافظ على نسب 64:25:9 في كل مرة. سبب التقطع لم
يُحسم؛ يبقى ملاحظة تحقق، دون ادعاء إصلاح عيب في المقارنة العددية.

**غير مختبر:** أجهزة Android/iOS الفعلية، Safari/WebKit، لوحة مفاتيح
الهاتف واللمس الحقيقي، TalkBack/VoiceOver، safe areas الفعلية، native zoom
وتكبير النظام، واختبار تثبيت التطبيق بوضع PWA/WebView. لا اعتماد 100%
للمنصتين قبل هذه الجولة.

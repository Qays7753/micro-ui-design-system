## البنود اللازمة للجولة التالية

### SUI-R1-01 — P2: رسالة نجاح دخول لا تضمنها نتيجة المستهلك

**المصدر:** components/access-gateway/access-gateway.js عند handlers.providers ثم onSubmit completion (حول 77 و138–141).

مزوّد تجريبي يعيد undefined ولا ينفذ مصادقة، ومع ذلك يظهر «تم الدخول بنجاح». onSubmit يعيد `{authenticated:false,message:'لم يتم الدخول'}`؛ مستمع `micro-access:submitted` يكتب رسالة عدم الدخول، ثم يستبدلها المكوّن بـ«تم التحقق من بيانات الدخول». لا أدعي أن authenticated هو schema ملزم للمكتبة؛ التجربة تثبت أن المكوّن لا يقرأ النتيجة التي يملكها المستهلك، ويفرض استنتاجًا بعد تنفيذ مستمعه. كان العقد السابق يترك نتيجة الدخول للمستهلك.

**المطلوب:** صياغة بشرية محايدة عند انتهاء handler دون نتيجة مؤكدة، وعقد موثق يسمح للمستهلك بتحديد الرسالة/النتيجة دون overwrite لاحق. لا تستنتج تسجيل دخول أو إرسال مساعدة من مجرد fulfilled Promise؛ راجع recovery أيضًا. لا تضف خدمة مصادقة أو schema أعمال قسريًا.

**قبول:** handler ينجز تسليمًا فقط لا يعرض نجاح مصادقة؛ رسالة المستهلك لا تُمحى؛ نتائج معلومة/غير مؤكدة/رفض ودون handler تختبر، مع حفظ حارس الطلب الواحد والحالات المشغولة وعدم تخزين كلمة المرور.

### SUI-R1-02 — P2: disconnect ثم init لا يعيد المراقبة في peek وcarousel

**المصدر:** components/info-strip/info-strip-peek.js: initStrip يعيد return عند data-info-peek-ready (حوالي259)؛ components/carousel/carousel.js: initOne يعود عند stateOf (حوالي474). disconnect يمسح المراقب، لكن init لا يصل إلى observeViewport. هذا يخالف وعد المواصفتين بإعادة الإلحاق.

**الإعادة:** الفهرس1، عرض320، disconnect → init → عرض الأب360 دون window resize. peek يبقى على transform242 بحواف −10/70 بدل30/30؛ goTo لنفس الفهرس يصححه إلى282. carousel يبقى224 بحواف−4/76 بدل36/36؛ goTo يصححه إلى264. عداد المراقبين يبقى1: لم يُنشأ بديل. الفهرس0 وحده لا يكشف المشكلة لأن إزاحته ثابتة في هذه البنية.

**المطلوب:** إعادة إلحاق المراقب والقياس للحالة الجاهزة المفصولة، دون إعادة ربط الأزرار أو إنشاء صفحات/أحداث مكررة. راجع rAF المعلق ودورة التنظيف؛ لا تعد كتابة المحرك.

**قبول:** ثلاث دورات disconnect/init عند فهرس غير صفري، ثم تغير عرض الأب وإخفاء/كشف، بتوسيط صحيح وفهرس/تركيز محفوظين ومراقب فعّال واحد ومن دون تكرار events أو controls. المصدر والملف المستقل.

### SUI-R1-03 — P2: منع التكرار لا يغطي عودة الحدث نفسه بعد حدث آخر

**المصدر:** components/messages/messages.js:34 و61–64 يحفظ آخر إعلان فقط.

التسلسل `{id:A}` ثم `{id:B}` ثم `{id:A}` بالنص نفسه يعطي **3 إضافات نصية**؛ العقد يقول إن الحدث نفسه يعلن مرة واحدة، أي2 هنا. التجربة الحالية للمنفذ A,A,B تمر، لكنها لا تغطي هذا المسار.

**المطلوب:** هوية ذات دورة حياة محددة تمنع إعادة الحدث ذاته بعد حدث مستقل، مع تنظيف/حد ذاكرة صريح وعدم ابتلاع حدث جديد بالنص نفسه. إن احتاج العقد reset أو نطاق حدث، وثّقه واختبره؛ لا تدّع منع الحدث طوال حياته مع last-only.

**قبول:** A,A,B=2 وA,B,A=2 داخل نطاق الحدث الموثق؛ حدثان بلا id يسمحان بالتكرار؛ النص/الإلحاح وإعادة استخدام الهوية وحدود التنظيف موثقة. الأدلة DOM فقط، لا ادعاء صوت.

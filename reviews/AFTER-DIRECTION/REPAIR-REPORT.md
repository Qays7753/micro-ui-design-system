### ما تغير في الاختبارات ولماذا

لم ينخفض عدد الفحوص الأصلية. بعض توقعاتها القديمة صُححت لتطابق العقد الجديد المطلوب:

- Carousel والمثال المستقل كانا يتوقعان أن المعاينة الجزئية غير معزولة؛ أصبح الشرط أشد: النشطة وحدها غير `inert`.
- assertions Packed القديمة لا تطلب حلقات بديلة للحالات غير الموجبة؛ تتحقق من فصلها وعدم إدخالها الرسم. مقارنة التخطيط أصبحت مسافة ثنائية الأبعاد، لا افتراض صف أفقي.
- B01 A18 يختبر التركيز + الضغط الفعلي بـSpace، مع الإبقاء على تحقق حلقة التركيز ولون الضغط نفسه. اختبار mouse السابق كان يبدّل `focus-visible` وقد يستخدم إحداثيات بعد تمرير لقطة قسم آخر.
- الفحص الجديد للأسهم يستخدم بطاقة موجودة فعلًا في fixture ذي بطاقتين. حلقة B01 تقاس من `box-shadow` الفعلي، لا `outline` الذي تصميم B01 يزيله أصلًا.
- قياس التباين يخفي الحروف أثناء التقاط خلفيتها ويوقف **انتقال لونها أثناء القياس فقط**، ثم يعيد style الأصلي. هذا يمنع قياس الحرف المتلاشي كأنه الخلفية. الموجة والتدرج وبقية السطح لا تُزال.
- الفحوص الجديدة تشمل 102 تركيبة Packed: 17 مجموعة بيانات × 3 أعروض × حالتي حجم نص، إلى جانب التفاعل والتنقل والأسطح. جرى تقويتها لقراءة **القيم المرئية** فقط ووجود مفتاح موجب مرئي واحد، مع حفظ fallback عند legend off. أُضيفت أربعة فحوص لأصول SVG وعزل الزخرفة. الزيادة من 316 إلى 617 هي **301 assertion جديدة**، لا إعادة تسمية القديم ولا جمع التشغيل الفاشل الأول إلى الإجمالي.

## القرارات البصرية التي تبقى PROPOSED

- التدرج الفاتح للملخص، توزيع المعلومات، استخدام الموجات، والاحتفاظ بالداكن كخيار محدود.
- التخطيط المتدرج للدوائر، الحجم المرجعي، ترتيب المجموعات، ومسافات المراجعة. التداخل الافتراضي **8px كحد مطلوب** لا ضمان تداخل ثابت؛ يُقيَّد بالأحجام والنص. المثال القديم ذي **28px** ليس افتراضي CSS ولا مقدارًا معتمدًا، حتى إن طلبه المستهلك.
- `aft-summary` موثق **Composition Pattern**، لا component type جديدًا ولا قرار منتج بإضافة دائرة إلى الصفحة الرئيسية.
- B01–B06 لم تُعد بناؤها. `components/data/data.js` لم يتغير؛ Packed opt-in منفصل.
- لا API أو منطق أعمال أو شاشة منتج كاملة أو theme migration أو dark mode.

## حدود الفحوص

- Chromium headless فقط؛ لا ادعاء بتحقق Firefox أو Safari/WebKit أو قارئ شاشة أو جهاز لمس حقيقي.
- 200% في هذه الأدوات هو مضاعفة `font-size` المحسوب، وليس zoom أصليًا في المتصفح أو تكبير نظام التشغيل.
- screenshot العادية لا تثبت السلوك التفاعلي؛ البوابات التفاعلية اختُبرت بالمفاتيح وDOM والـevents، واللقطات دليل بصري مكمل.
- القياس الموضعي يأخذ خلفية PNG الحقيقية تحت منطقة النص، وليس لون token منفصلًا. لا يمثل كل جهاز أو كل وضع تباين مرتفع.
- الدورات اختُبرت 8 مرات لكل بطاقة، لا «عددًا لا نهائيًا» تجريبيًا؛ إصلاح سبب state يزيل الاعتماد على عدد مرات الفتح.
- هذه الحدود ليست ادعاء بفحوص لم تُنفذ، وليست blockers متبقية من M1–M7 ضمن البوابات المطلوبة.

## خطة الدمج والتنظيف — مُحضَّرة ولم تُنفَّذ

1. مراجعة رأس التسليم النهائي لـ`task/after-direction-components` والـSHA الوارد في رسالة الخاتمة.
2. مراجعة هذا التقرير واللقطات والنتائج الخام.
3. موافقة المالك على كل القرارات البصرية PROPOSED.
4. **بعد الموافقة الصريحة فقط:** دمج PR#6 وحده إلى main، لأنه يتضمن PR#5 وحزمة المراجع تراكميًا.
5. التحقق أن main يحتوي الملفات المعتمدة فعلًا؛ مقارنة محتوى الشجرة وليس الاعتماد على عنوان PR وحده.
6. إغلاق PR#5 دون دمج منفصل إذا ثبت بقاء محتواه ضمن main.
7. فحص ancestry ووجود العمل المعتمد في main قبل حذف الفروع القديمة؛ لا نفترض أن كل رأس مستقل يجب دمجه.
8. إبقاء main الفرع الوحيد بعد تحقق الخطوة السابقة، ثم فحص GitHub نهائيًا.

الصياغة المقصودة: **دمج كل العمل المعتمد في main، مع عدم إعادة دمج الفروع المدموجة أو الأسلاف التراكميين بشكل منفصل.**

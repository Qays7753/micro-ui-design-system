# UX-F02 — عينة دورة الاختيار (choice-lifecycle)

الحالة: **DRAFT FOR REVIEW** — عينة محاكاة مستقلة للمراجعة؛ ليست سياسة أعمال ولا API جديدة للمكتبة. المصدر القاعدي: [بطاقة F02](../../../docs/ux/F02-ACCEPTANCE.md) §3 و[التكليف](../../../prompts/UX-F02-ZAI.md).

## 1) التشغيل

من جذر المستودع (خادم ملفات ساكن يكفي):

```bash
python3 tools/preview-server.py
# ثم افتح: /previews/ux-patterns/choice-lifecycle/index.html
```

تعمل الصفحة بلا لوحة معرض ولا عينات أخرى: مصادر المكوّن مباشرة من `components/` و`shared/` وأيقونات HugeIcons معلنة inline في `index.html` (بنفس محتوى `assets/icons`). لا بناء ولا تبعيات خارجية.

## 2) الهدف والخارج

| تثبتها العينة | لا تعنيه |
|---|---|
| اختيار محلي فوري (checkboxes/radio/مقطّع) مع «تحديد الكل» يخص المفعّل فقط | حفظ اختيار على خدمة أو صلاحيات |
| قراءة منتقي قابل للبحث داخل طبقة B07: loading/ready/empty/error + no-results بحثية | شبكة حقيقية أو إلغاء طلب فعلي عند الإغلاق |
| رد قراءة قديم بمعرف أقدم يُتجاهل كليًا وتسوية الأحدث في الصفحة نفسها | ادعاء سلوك قارئ شاشة فعلي من وجود role/status |

## 3) ثوابت البداية — مصدر وحيد

في `example.js` أعلى الملف، وتنعكس في العرض والموصل والفحص دون تعديل HTML:

| الثابت | القيمة الافتراضية | ملاحظة |
|---|---|---|
| `CHOICES_INIT` | alpha/beta/gamma — gamma معطلة محددة أصلًا | الأعلام `disabled`/`checked` على المصدر الواحد وفق البطاقة §3.1 |
| `PICKER_SELECTED_INIT` | `null` | بداية بديلة مجربة: `{value:'beta', label:'عينة ب'}` تظهر «المحدد: عينة ب» عند الإقلاع بلا أحداث ولا طلبات |
| `PICKER_READ_ITEMS_INIT` | alpha/beta/gamma | يمرر إلى الموصل كمصدر خيارات القراءة |

تبدأ المجموعات القصيرة من نفس الثابت (checkboxes + راديو)؛ مجموعة «بلا خيارات مفعّلة» (فحص F02-P01) تركيب ثابت في HTML لأنها هيكل اختبار لا بيانات.

## 5) جدول الحالات وسلوك العينة

| الحالة/الحدث | السلوك الموثق |
|---|---|
| إقلاع | بناء المجموعات من الثابت + عرض `PICKER_SELECTED_INIT`؛ **بلا أحداث ولا قراءات** |
| تحديد الكل | يخص المفعّل فقط؛ المعطل وقيمته محفوظان؛ مجموعة بلا مفعّلين = صفر صريح (`checked=false` و`indeterminate=false`) عند التهيئة والنقر (F02-P01) |
| مقطّع موجز/تفصيلي | `aria-pressed` + تبديل محتوى مطابق؛ العنصر الثالث `aria-disabled=true` لا يتفاعل نقرًا أو Enter/Space ولا يطلق حدثًا (F02-P02)؛ لا أثر على المنتقي |
| فتح طبقة المنتقي | قراءة جديدة بمعرف متزايد؛ الحالة `loading` تخفي الخيارات القديمة (لا اختيار نتائج عتيقة) |
| نتيجة ready | `setOptions` يُبقي اختيارًا باقيًا بالمعرف ويزامن التسمية الداخلية والخارجية **حتى دون `change`**؛ سقوط المعرف يمسح الاختيار والعرض مع رسالة الزوال الظاهرة داخل الطبقة (`#f02c-drop-note` — بند R2-01 أدناه) — بلا اختيار تلقائي لأول خيار |
| مصدر فارغ | حالة `empty` صريحة بعد `setOptions` — لا اعتماد على قائمة بيضاء |
| خطأ قراءة | حالة `error` بزر إعادة محاولة (حدث `micro-picker:retry` → قراءة واحدة جديدة)؛ البحث لا يزيل حالة الخطأ |
| no-results | صف بحث فقط ولا يخلط بحالة القراءة؛ مسح البحث يعيد القائمة دون قراءة جديدة؛ **والبحث المكتوب أثناء القراءة** تعلن نتيجته عند وصول ready من الظاهر: بلا مطابقة «لا نتائج مطابقة للبحث» ومع مطابقة «نتائج البحث: N» (R2-02) |
| اختيار مستخدم | فوري ومحلي: قيمة + عرض خارجي متطابقان ثم إغلاق الطبقة؛ لا Apply ثانٍ ولا حفظ |
| مسح الاختيار (خارج الطبقة) | قيمة وعرض خارجي وداخلي إلى null — لا مكالمات حفظ |
| رد بمعرف قديم | تُتجاهل كليًا (لا قيمة/رسالة/تركيز)؛ النتيجة المقبولة تزامن العرض ولو كانت الطبقة مغلقة؛ لا إعادة فتح تلقائية |

## 6) سياسة الإغلاق والتركيز والإعلان

- **الإغلاق بكل الوسائل** (زر الطبقة، زر المنتقي، Escape، الخلفية — `data-backdrop="close"`) هو إغلاق عرض لا «إلغاء تعديل»: لا مسودات منتقي هنا، فلا حوار فقد تعديل ولا إعادة فتح تلقائية.
- **التركيز**: فتح الطبقة يعيد التركيز داخلها (B07)؛ قبل استبدال/إخفاء عنصر مركّز داخل منتقي مفتوح ينتقل التركيز إلى حقل البحث الثابت — وإن كان المستخدم خارج الخيارات فلا سرقة؛ عند الإغلاق يدير B07 الاستعادة إلى المشغّل وحده.
- **الإعلان (حدث = قناة واحدة)**: حالة القراءة تُعلن داخل الطبقة المفتوحة في `#f02c-picker-live` (role=status) كي لا تسقط في خلفية inert؛ تغيّر الاختيار (اختيار/مسح/سقوط) له قناتان حسب الموضع — تفصيلهما في §10 أدناه (R2-01). لا `MicroMessages.announce` لأي من النصين ولا منطقة حية ثالثة. **وجود role=status/alert يثبت البنية لا سلوك قارئ شاشة فعلي.**

## 7) UX IDs المستعملة

UX-12 (نوع التحكم: checkbox/radio/segmented بأدوارها الأصلية)، UX-14 (منتقي وبيانات متجددة: loading/error/empty وعدم اختيار النتائج العتيقة وعدم البديل التلقائي)، UX-17 (الطبقة والتركيز: B07 كما هو)، UX-19 (إعلان الحالة دون مقاطعة وقناة واحدة)، UX-20 (قراءة وإعادة محاولة وسياسة الرد القديم)، UX-05 (اختيار محلي = قيمة معروضة لا حفظ)، UX-28 (لا افتراضات أعمال — بيانات تركيبية فقط).

## 8) حدود المحاكاة

- الموصل `mock-adapter.js` حتمي: قراءات متداخلة مسموحة، التسوية بأمر صريح (`settle` أقدم / `settleLatest` أحدث) — لا مؤقت واجهة يقرر نتيجة ولا شبكة/تخزين/مصادقة.
- «تسليم رد قراءة بمعرف قديم» في SIMULATION يمر عبر مسار معالجة النتائج لدى المستهلك (`F02Choice.deliverTestReadResponse`) دون استهلاك أي Promise معلقة: يثبت **فلتر المستهلك وتجاهله**، لا وصولًا شبكيًا فعليًا لرد محاولة سابقة.
- عدادات `readCalls`/`staleIgnored` وآخر readId في قسم SIMULATION للفحص التقني فقط — ليست رسائل مستفيد.
- المجموعات القصيرة والراديو محلية تمامًا: لا موصل ولا مكالمات حفظ، ولا رسائل نجاح/فشل عنها.
- لم تُنفذ فعليًا (NOT RUN): WebKit/Safari، أجهزة حقيقية، TalkBack/VoiceOver، native zoom، اللمس وsafe areas. الفحص الآلي: `python3 tools/ux-f02-check.py` (المسارات F02-01..32).

## 9) تحديث جولة R2 — سياسات مطلوبة من مراجعة CHATGPT-REVIEW-R1

- **بذرة البداية (R1-01) — مصدر واحد:** `PICKER_SELECTED_INIT` يُزرع عند الإقلاع في حالة المستهلك وداخل المنتقي نفسه (`aria-selected` على العقدة الموثقة + ملخص `[data-picker-summary]`) عبر `MicroPicker.setOptions` بلا أي حدث اختيار أو قراءة مبكرة. أول `ready` صحيح يُبقي معرف البداية الموجود محددًا داخل المنتقي وخارجه (وبرسمية التسمية المحدثة). معرف غائب فعلًا: لا بذرة داخل المنتقي، وأول ready يُمسح برسالة الزوال الظاهرة. بداية `null` تبقى الإعداد الافتراضي وبلا خيارات عند الإقلاع.
- **empty مؤكدة (R1-02):** فرع `empty` يطبق مصدرًا فارغًا (`setOptions([])`) ويزامن null والملخص والعرض مع رسالة الزوال — مطابق لـ`ready` بقائمة فارغة. `loading/error` يحفظان آخر اختيار محلي وفق البطاقة §3.2. لا اختيار تلقائي لأول خيار ولا استبدال عقدة الصفحة.
- **حرس التركيز (R1-03):** التركيز يُنقل إلى البحث الثابت فقط قبل زوال عنصر مركّز سيُخفى أو تُستبدل عقده (خيار/صف حالة/زر إعادة محاولة). العناصر الثابتة — البحث وزر رأس الطبقة — لا تُسرق منها، وإن انتقل المستخدم إلى هدف آخر صالح فلا نقل.
- **توجيه الرسالة (R1-04 — حدثه بجولة R3/§10):** سابًا كانت رسالة السقوط تُدمج في إعلان القراءة على `#f02c-picker-live`؛ جولة مراجعة R2 أظهرت أن السبب محجوب بصريًا (القناة live-only مقصوصة) — السياسة الحالية في §10 أدناه. `no-results` ومسح البحث يزامنان إعلانًا مفهومًا بدل عدد قراءة قديم؛ المستمع مسجل بعد `DOMContentLoaded` ليقرأ DOM بعد تصفية المنتقي.
- **لقطة الموصل (R1-05 + R2-03):** كل `read` يأخذ نسخة بيانات مستقلة عند بدئه (`itemsSnapshot` بنسخ العناصر أنفسها وفق المخطط الموثق أدناه)؛ تعديل fixture بعد الدعوة — تبديل `setSource` أو تعديل كائنات عناصر المصدر نفسها (label/value) — يخص القراءة التالية فحسب؛ نتيجة كل Promise تخص مصدرها وreadId ولو سُوّيت الأحدث أولًا.
- **إغلاق ظاهر واحد (R1-06):** التركيب فيه زر رأس الطبقة فقط؛ مسار المنتقي المستقل `[data-picker-close]` لا يستخدم هنا، وEscape/الخلفية كما هي. القناة داخل الطبقة live-only (`clip`) — الحالة المرئية لكل معنى هي صف حالة المنتقي من المكوّن والملخص، بلا strip مرئي مكرر للخطأ/الانتظار.

## 10) تحديث جولة R3 — سياسات مطلوبة من مراجعة CHATGPT-REVIEW-R2

- **رسالة زوال الاختيار الظاهرة (R2-01):** داخل الطبقة المفتوحة رسالة المعالجة الظاهرة نفسها هي القناة الوحيدة لحدث الزوال: `#f02c-drop-note` بنمط B06 المعتمد (`m-note m-note--warning` + `role=status` وفق عقد B06 المحدث في REPAIR-R1/SUI-010: التحذير لا يقاطع آليًا، alert للخطأ القابل للتصرف فقط) داخل `.m-layer__body`. ظاهرة للمستخدم (لا نص في قناة مقصوصة 1×1) وتُعلن مرة واحدة، ونصها **لا يُكتب في قناة القراءة `#f02c-picker-live` ولا في الخارجية معًا** (لا تجميع مسارين للنص نفسه). تظهر عند زوال الاختيار فقط — لا strip عام يكرر loading/error/count؛ الحالة المرئية العامة تبقى صف حالة المنتقي (core) والملخص. خارج الطبقة: قناة العرض المغلق القائمة `#f02c-selection-note` كما هي. **سياسة المسح:** الرسالة تُمسح حين يزول سببها — اختيار جديد للمستخدم، مسح صريح من الزر، بدء قراءة جديدة (سياق معالجة جديد)، أو إغلاق الطبقة (خارج النطاق القناة الخارجية هي المالكة). **وتحديث البيانات وحده لا يمسحها:** لا استعادة تلقائية لاختيار ساقط (سياسة بلا اختيار تلقائي) فسببها — وجوب اختيار جديد — ما يزال قائمًا.
- **إعلان البحث بعد القراءة (R2-02):** عند وصول `ready` مع استعلام بحث قائم (مكتوب قبل أو أثناء القراءة) يُبنى الإعلان من الحالة الفعلية الظاهرة لا من `res.items.length` وحده: بلا مطابقة «لا نتائج مطابقة للبحث. جرّب اسمًا آخر.» ومع مطابقة «نتائج البحث: N خيارات.» — مطابقًا لما يعلنه الكتابة بعد ready. مسح البحث يعلن «الخيارات الظاهرة: N». حالات `loading/error/empty` المصدر تبقى منفصلة عن no-results البحثية. رسالة زوال الاختيار إن اجتمعت مع no-results تبقى في قناتها الظاهرة الخاصة فلا تُطغى عليها إعلان القراءة ولا تتكرر القنوات.
- **مخطط بيانات اللقطة وحدود نسخها (R2-03):** مخطط خيارات العينة `{value, label}` إلزاميان سلوكيًا و`{disabled, checked}` أعلام اختيارية — كلها قيم أولية تُنسخ بنسخ مباشر عند بدء كل `read` (`snapshotItem` في `mock-adapter.js`). **حد موثق:** مفاتيح خارج المخطط لا تُحمل، والكائنات المتداخلة لا تُستنسخ عميقًا (لا مكتبة استنساخ عامة — العينة لا تحتاجها). نتيجة كل Promise تخص لقطة طلبها: تعديل كائنات المصدر بعد بدء الدعوة (label أو value، في مصدر الإنشاء أو مصدر `setSource`) لا يمس النتيجة الجارية.
- **فحوص الجولة (R2-04):** أداة `tools/ux-f02-check.py` تقيس الظهور الفعلي للرسالة (display/hidden/مستطيل/clip + داخل الطبقة + قناة واحدة)، والبحث أثناء القراءة (مطابقة/بلا مطابقة/تحديث باستعلام قائم/مسح)، وتعديل خصائص كائنات اللقطة (label وvalue في المصدرين)، و`setSwitchPending(false)` قبل أي pending للمتاح والمعطل أصلًا — ولقطة `f02-12-selection-dropped.png` تُلتقط والطبقة مفتوحة والرسالة ظاهرة ومستقرة (قياسان متطابقان قبل اللقطة)، ولقطة العرض المغلق مستقلة `f02-12-selection-dropped-closed.png`.

# UX-F02 — عينة تحديث إعداد تجريبي (switch-lifecycle)

## 2) الهدف والخارج

| تثبتها العينة | لا تعنيه |
|---|---|
| مفتاح بحفظ تلقائي: تبديل واحد = تحديث واحد بمعرف محاولة | صلاحيات، تفعيل خدمة، أو إلغاء معاملة حقيقية |
| انتظار/نجاح مؤكد/رفض مؤكد باسترجاع/نتيجة مجهولة بتحقق صريح | ادعاء أن `change` أو زوال pending أو `rendered` دليل حفظ |
| تحقق لنفس attemptId دون تحديث جديد، ورد قديم لا يفسد الحالي | وصولًا شبكيًا فعليًا لرد محاولة سابقة (حد موثق أدناه) |
| سياسة تركيز محددة قبل التعطيل وبعد الحسم | سلوك TalkBack/VoiceOver فعلي من وجود role=status |

## 5) جدول الحالات (وفق البطاقة §5)

| الحالة/النتيجة | السلوك الموثق |
|---|---|
| idle | checked = confirmed؛ نتيجة قديمة (الرسالة) تزال عند بدء محاولة أخرى |
| pending | checked يعرض القيمة المقصودة؛ «جارٍ تحديث الإعداد»؛ confirmed لا يتغير؛ `setSwitchPending(true)` يمنع تكرار التبديل (input معطل فعليًا + حارس المستهلك + حارس المكوّن للتبديلات الموثوقة) |
| saved | confirmed = قيمة الإرسال؛ «تم تحديث الإعداد» فقط بعد النتيجة المؤكدة؛ checked متزامن |
| not-saved | confirmed لم يتغير؛ checked يُسترجع إلى confirmed؛ «لم يُحدَّث الإعداد. حاول مجددًا» باقية والتبديل متاح |
| unknown / رفض Promise | لا ادعاء رفض/نجاح؛ confirmed لا يتغير؛ checked يبقى المقصودة بوصفها غير مؤكدة؛ المفتاح محجوب؛ «تعذر تأكيد التحديث. تحقق من النتيجة» وزر التحقق ظاهر فعليًا |
| checking | استعلام عن attemptId نفسه — check واحد رغم تكرار التفعيل (busy B01 + guard المستهلك)؛ لا تحديث ثانٍ |
| check saved / not-saved | الحسم على **قيمة إرسال المحاولة** نفسها؛ ثم إخفاء زر التحقق فعليًا (hidden + قاعدة `#f02s-check[hidden]{display:none}` — درس F01-R1-01) |
| check unknown / رفض | عودة unknown مع إتاحة تحقق جديد — بلا إرسال تلقائي ولا rollback يوهم الرفض |
| رد قديم | لا قيمة ولا رسالة ولا تركيز؛ يُسلَّم عبر مسار المستهلك (فلتر attemptId) أثناء معلونية الحالي ثم يُسوى الحالي بعده في الصفحة نفسها بلا reload |

## 6) سياسة التركيز المحددة (نص البطاقة مطبق حرفيًا)

- **قبل التعطيل**: إن كان `input` هو التركيز عند بدء العملية ينتقل التركيز إلى وصف الانتظار الثابت `#f02s-note` (`tabindex=-1`، مرتبط بالمفتاح عبر `aria-describedby`) قبل `setSwitchPending(true)`. لا تركيز BODY ولا عنصر معطل.
- **بعد الحسم**: الوصف نفسه يبقى وإن تغير نصه — **لا** نقل تلقائي إلى المفتاح حين يعود متاحًا، وإن كان المستخدم في موضع آخر فلا سرقة تركيز (الحسم لا يحرك التركيز إطلاقًا — مقاس في الفحص قبل/بعد).
- **زر التحقق عند الحسم**: إن كان التركيز عليه ينتقل إلى المفتاح **بعد تفعيله وقبل إخفاء الزر**؛ وإن كان في موضع آخر فلا نقله.
- لا `aria-disabled` وحدها كحراسة (تعطيل input فعلي عبر عقد B03)، ولا تعطيل fieldset يحجب زر التحقق. تكرار `setSwitchPending(sw,false)` ومفتاح معطل أصلًا يحفظان عقد R2-06.

## 7) الإعلان (حدث = قناة واحدة)

`#f02s-note` (`m-note` ثابتة `role=status`) قناة العملية الوحيدة: انتظار/نجاح/رفض/مجهولة/تحقق — باقية حتى يستبدلها حدث أحدث (لا toast يختفي). بلا `MicroMessages.announce` لنصها وبلا منطقة حية ثانية. وجود role=status يثبت البنية لا سلوك قارئ شاشة فعلي.

## 8) UX IDs المستعملة

UX-13 (تحديث إعداد غير متزامن: انتظار/رفض يسترجع/مجهولة لا تُملأ بافتراض)، UX-03 (منع التفعيل المكرر ونجاح الواجهة يتبع النتيجة)، UX-12 (switch لإعداد on/off لا تنقل)، UX-11 (تعطيل أثناء الانتظار مع سبب ظاهر ومسار تحقق)، UX-19 (قناة واحدة دون مقاطعة)، UX-18 (رسالة باقية مع فعل المعالجة)، UX-28 (لا افتراضات أعمال — إعداد تركيبي).

## 9) حدود المحاكاة

- الموصل حتمي بلا مؤقت واجهة: `update({attemptId,value})` و`check({attemptId})` وعقود `saved/not-saved/unknown/reject` كما في §6 من البطاقة. رفض update = unknown (لا يثبت عدم الحفظ)؛ رفض check يبقي النتيجة مجهولة.
- «استجابة بمعرف قديم» تمر عبر `F02Switch.deliverTestResponse` — مسار معالجة النتائج لدى المستهلك نفسه (نفس فلتر attemptId) دون استهلاك Promise المعلق: يثبت الفلتر والتجاهل واستمرار الحسم، **لا** وصولًا شبكيًا فعليًا لرد محاولة سابقة (حد موثق؛ واجهة الفحص تستبعد من ربط خدمة لاحقًا).
- عدادات `updateCalls/checkCalls` و`staleIgnored` والرد `sim` في قسم SIMULATION للفحص فقط — ليست رسائل مستفيد.
- لم تُنفذ فعليًا (NOT RUN): WebKit/Safari، أجهزة حقيقية، TalkBack/VoiceOver، native zoom، اللمس وsafe areas.

## 9) تحديث جولة R2 — سياسة رسالة واحدة لكل معنى (R1-06)

رسالة العملية معنى واحد موجز: العنوان يحمل المعنى كاملًا، والجسم للخطوة التالية فقط إن وجدت («حاول مجددًا.» / «تحقق من النتيجة.»)، وإعلانها مرة واحدة على القناة ذاتها (role=status واحدة). رسالة النجاح «تم تحديث الإعداد.» بلا تفاصيل داخلية مثل حالة القيمة. الجسم الفارغ لا يشغل مساحة (`.m-note__body:empty { display: none; }` حرس تركيب في example.css). لا تغيير على B05 أو تنويعاتها.

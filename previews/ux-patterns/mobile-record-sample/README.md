# UX-F03 — تجربة هاتف مترابطة: «العناصر» (رئيسية · قائمة · تفاصيل · إضافة/تعديل)

الحالة: **DRAFT FOR RE-REVIEW** — عينة محاكاة للمراجعة، ليست سياسة أعمال معتمدة ولا مكوّنًا جديدًا في المكتبة. التكليف: تكليف المالك المحدّث «تجربة هاتف متكاملة ومترابطة مع إصلاح عيوب التسليم السابق» (2026-10-06)، والموجز: [`docs/ux/F03-EXPERIENCE-BRIEF.md`](../../../docs/ux/F03-EXPERIENCE-BRIEF.md)، ومراجعة R1: [`reviews/UX-F03/CHATGPT-REVIEW-R1.md`](../../../reviews/UX-F03/CHATGPT-REVIEW-R1.md).

وحدة عربية واحدة تبدو جزءًا من تطبيق حقيقي: **رئيسية بملخص من البيانات الفعلية → قائمة ببحث وتصفية → تفاصيل العنصر → إضافة وتعديل وحفظ → ظهور النتيجة في التفاصيل والقائمة وملخص الرئيسية**. كل فعل مرئي يؤدي وظيفة فعلية على بيانات تجريبية. هاتف أولًا · عربي RTL · أرقام 0–9 · مصادر المكوّن كما هي دون تعديل core أو الهوية.

## ما الذي يجربه المالك بالنقر العادي

| الشاشة | المتاح |
|---|---|
| **الرئيسية** | عدد العناصر الموجود فعليًا، توزيعها على الفئات (صفوف `m-progress` المعتمدة: عدد + نص + شريط)، «أحدث العناصر» (حتى 3 بترتيب آخر تحديث، كل صف يفتح تفاصيله)، «إضافة عنصر»، «عرض جميع العناصر (N)» |
| **القائمة** | كل الصفوف، بحث حي على الاسم والملاحظة، زر التصفية المعتمد (عدّاد الشروط المطبقة) بلوحة تطبيق/مسح/إلغاء، حالة «لا عناصر بعد» تختلف عن «لا نتائج مطابقة»، إضافة |
| **التفاصيل** | البيانات المحفوظة، «تعديل»، رجوع يعيد إلى مصدر الوصول مع حفظ البحث والتصفية وموضع التمرير |
| **الإضافة/التعديل** | نموذج صفحة: الاسم (مطلوب)، الفئة عبر المنتقي المعتمد في طبقة B07 (بحث وقراءة loading/ready/empty/error)، الملاحظة (اختيارية)، «تغييرات غير محفوظة»، حفظ بنتائج نجاح/رفض/غير مؤكد بتحقق، حوار «تجاهل التعديلات؟» عند المغادرة |

المسار الافتراضي ينجح وحده دون أدوات مطوّر: كل دعوة تُحسم تلقائيًا بعد 600ms ثابتة داخل الموصل (زمن خدمة محاكاة، لا مؤقت واجهة).

## واجهة الموصل التجريبي (قابلة للاستبدال)

```js
save({attemptId, mode:'add'|'edit', id, values})  // → Promise<{attemptId, outcome:'saved'|'not-saved'|'unknown', item?}>
check({attemptId})                                 // → Promise بالصيغة نفسها — استعلام للمحاولة نفسها بلا حفظ جديد
readCategories({readId})                           // → Promise<{readId, outcome:'ready'|'empty'|'error', items:[{value,label}]}>
cancel(kind, id)                                   // → رفض صريح {cancelled:true} عند انتهاء سياق الطلب
setNextSave/Check/Read(outcome) · settle(kind, override) · setSource(items) · counters · calls · readout()
```

- **حتمي بلا عشوائية**: الافتراضي يُحسم بعد `AUTO_SETTLE_MS` بالنتيجة الافتراضية (`saved`/`saved`/`ready`)؛ المسار الافتراضي ينجح وحده.
- **(R1-03)** كل قراءة تثبت snapshot لعناصرها عند بدء الدعوة؛ تغيير المصدر أو تعديل كائناته بعد الدعوة لا يمس النتيجة.
- **(R1-04)** المؤقت مرتبط بالدخول (entry) الذي أنشأه؛ الطلبات المتداخلة تُعلن overflow وكل دخول يحسم بعقده (مؤقته/أمره/إلغاء المستهلك) — لا وعد يتيم ولا مؤقت قديم يحسم أحدث.
- **التزام الحفظ**: عند `saved` فقط يُكتب العنصر في `F03Store` (معرف جديد للإضافة و`updatedAt` جديد) ويُحل Promise بالعنصر الملزم؛ `check` يعيد نتيجة المحاولة الأصلية حتميًا.
- **رد بمعرف قديم**: يُسلَّم عبر `F03App.deliverTestResponse(kind, payload)` — معالج النتائج نفسه بذات الفلاتر دون استهلاك الطلب المعلق. يثبت فلاتر المستهلك وتجاهلها الكامل؛ **لا يثبت** وصولًا شبكيًا فعليًا (حد موثق).
- رفض Promise أثناء save يعامل unknown؛ رفض check يبقى unknown؛ الرفض المعلوم صراحةً نتيجة `not-saved`.
- العدادات والسجل للفحص فقط — لا تدخل رسائل المستفيد. لا شبكة ولا حسابات ولا بيانات حقيقية.

## وضع المراجعة (الحالات الخاصة من الهاتف — إغلاق R1-01/R1-07)

الواجهة الافتراضية نظيفة تمامًا: لا تقرير تقني ولا عدادات ولا نصوص DRAFT/UX-F03/SIMULATION ولا عناصر فحص قابلة للتبويب. المدخل الوحيد رابط «وضع المراجعة» في تذييل الصفحة يفتح طبقة B07 فيها:

- **تسليح السيناريوهات**: نتيجة الحفظ/التحقق/القراءة التالية (نجاح/رفض/غير مؤكد/رفض بلا نتيجة) — تطبق على الدعوة المقبلة فقط.
- **إنهاء المعلق من الهاتف**: أزرار «إنهاء الحفظ/التحقق/القراءة المعلق» تعمل من الطبقة في أي لحظة (الطبقة عليا فلا تعزل نفسها) — بلا console ولا reload.
- **لا فخ معلق**: كل سيناريو مسلح يُحسم تلقائيًا داخل الموصل بعد `ARMED_SETTLE_MS` (2000ms حتمية) إن لم يُنهَ يدويًا — مساران مستقلان للهروب.
- **أدوات البيانات**: «استعادة البيانات التجريبية الأصلية» و«تفريغ البيانات التجريبية» (لتجربة حالة الفراغ بالنقر)؛ فعل أداة أثناء نموذج مفتوح يعيد للرئيسية مباشرة بلا حوار (موثق).
- **قراءات فحص**: حالة التخزين المحلي المعلنة بصدق، عدادات الدعوات، أزرار «استجابة بمعرف قديم».

## قرارات المستهلك الموثقة

- **نموذج صفحة كاملة** بدل اللوحة السفلية (إذن صريح في تكليف المالك)؛ منتقي الفئة وحوار التجاهل ووضع المراجعة ولوحة التصفية طبقات B07 كما هي بعزل inert وحصر تركيز دون تعطيل.
- **(R1-05) صلاحية رد القراءة** مرتبطة بسياق مزدوج: جلسة فتح المنتقي + جلسة النموذج + ظهور الطبقة فعليًا + كون المستخدم في النموذج؛ الإغلاق أو المغادرة يُبطل السياق ويُلغي الطلب `cancel()` صريحًا، وأي رد خارج سياقه الحي يُتجاهل كليًا (لا قيمة/رسالة/تركيز).
- **(R1-06) نجاح الحفظ**: تحديث المؤكد → تبديل العرض إلى التفاصيل → كتابة رسالة النجاح **مرة واحدة** في قناة سياق التفاصيل (`role=status`) بعد ظهور السياق فعليًا؛ سجل الأحداث يثبت الترتيب (save:saved → view:detail → note:written). لا رسالة مكررة ولا سرقة تركيز.
- **القناة الواحدة لكل سياق**: أخطاء الحقول قرب الحقل (`aria-describedby`/`aria-invalid`)؛ رسالة العملية داخل النموذج `role=status`؛ رسالة زوال الفئة داخل طبقة المنتقي `role=alert` ظاهرة بنمط B06 (درس F02-R2-01) ونصها لا يُكرر. لا Toast في هذه العينة.
- **التركيز**: فتح النموذج → الاسم؛ المنتقي → بحثه؛ الحوار → زر البقاء؛ تبديل العرض → عنوان العرض (بـ`preventScroll` حفاظًا على استعادة التمرير)؛ تجاهل التعديل → زر «تعديل»؛ إخفاء زر تحقق مركز → زر الحفظ (درس F01-R1-02).
- **المغادرة**: clean → عودة مباشرة؛ dirty → حوار قرار (البقاء/Escape/الإغلاق/الخلفية كلها بقاء، والتجاهل وحده يغادر بلا حفظ)؛ pending → حجب برسالة موجزة دون وهم إلغاء عملية.
- **Escape** بطور الالتقاط: طبقة مفتوحة → سلوك B07؛ نموذج dirty → الحوار؛ pending → حجب؛ غير ذلك لا فعل (موثق). «رجوع النظام» NOT RUN.
- **ترتيب القائمة مستقر** (ترتيب الإدراج) حفاظًا على موضع التمرير؛ «أحدث العناصر» في الرئيسية بترتيب آخر تحديث فيصعد المعدّل/الجديد إليها.
- **التخزين المحلي**: مفتاح `micro-f03-mobile-record-v1` — التعديلات المؤكدة تبقى بعد إعادة فتح الملف عند توفر التخزين؛ عند الحجب أو الفشل: حفظ داخل الجلسة بلا انهيار والحالة معلنة بصدق في وضع المراجعة. لا ادعاء دوام خارج المتصفح ولا مزامنة.

## الحالة والرسائل

محاور مستقلة: `dirty` (اختلاف القيم الخام عن أساس النموذج؛ العودة للأصل تعيد clean دون حفظ) و`invalid` (الاسم/الفئة) وحالة العملية `idle | saving | failed | unknown | checking`. أثناء `saving/checking/unknown`: الحقول `readOnly` (القراءة والنسخ محفوظتان) وزر الفئة معطل، وbusy على زر واحد فقط عبر `MicroButtons.setLoading`، والحفظ محروس سلوكيًا، وزر «التحقق من النتيجة» يظهر ظهورًا فعليًا في unknown/checking فقط (`#f03-check[hidden]{display:none}` — درس F01-R1-01). رسائل انتهى سببها تزال عند تغير القيم (درس F01-R1-03).

# UX-F01 — مثال دورة النموذج: «تحرير سجل تجريبي»

الحالة: **DRAFT FOR REVIEW** — عينة مستقلة للمحاكاة والمراجعة، ليست سياسة أعمال معتمدة ولا مكوّنًا جديدًا في المكتبة. التكليف: `prompts/UX-F01-ZAI.md`، وبطاقة القبول: `docs/ux/F01-ACCEPTANCE.md`.

هذه العينة تختبر تركيب مصادر مكتبة UI القائمة مع سلوك مستهلك واضح: تعديل محلي، تحقق عند الإرسال، انتظار، نجاح/رفض مؤكد، نتيجة مجهولة والتحقق منها، ومغادرة بحوار قرار. لا شاشات منتج ولا خدمة حقيقية ولا ربط بنظام Micro الإنتاجي.

## التشغيل

من جذر المستودع فقط (لا بناء ولا تبعيات جديدة):

```bash
python3 -m http.server 8080
# ثم فتح: http://localhost:8080/previews/ux-patterns/form-lifecycle/
```

فحص السيناريوهات كاملة (F01-01..F01-20) بأدلة من commit مصدر مثبت:

```bash
python3 tools/ux-f01-check.py
# النتائج: reviews/UX-F01/verification.json + verification.txt + screenshots/
```

المتصفح المستخدم للفحوص: Chromium headless عبر Playwright. فحوص DOM ولوحة المفاتيح والمقاسات لا تثبت TalkBack/VoiceOver أو لوحة هاتف حقيقية أو native zoom أو WebKit — هذه **NOT RUN** حتى تنفيذها فعليًا.

## واجهة الموصل التجريبي (قابلة للاستبدال)

`mock-adapter.js` يوفر `F01Sim.createConnector()` — واجهة محلية مقترحة للعينة، **ليست API جديدة للمكتبة**. أي موصل بديل (خدمة حقيقية لاحقًا) يطبق الصيغة نفسها:

```js
save({ attemptId, values })  // → Promise<{attemptId, outcome: 'saved'|'not-saved'|'unknown'}>
check({ attemptId })         // → Promise بالصيغة نفسها — استعلام للمحاولة نفسها بلا حفظ جديد
```

- `values` نسخة الإرسال الثابتة كما كُتبت (بلا trim وتحويل).
- رفض Promise أثناء `save` يعامل **unknown** إن لم يؤكد عقد الموصل عدم الحفظ؛ رفض `check` يبقى **unknown**. ولرفض معلوم صريح استخدم نتيجة `not-saved`.
- الإنهاء **حتمي بأمر صريح** (`settle(kind)` أو `respond(kind, payload)`) — لا مؤقت واجهة يقرر نجاحًا ولا sleeps. انتهاء مؤقت أو زوال مؤشر ليس دليل حفظ.
- السيناريو (`setNextSave`/`setNextCheck`) يطبق على **الدعوة المقبلة فقط** ولا يعدّل Promise جارٍ أو نتيجته بعد انطلاقه.
- `respond` يتيح استجابة بأي `attemptId` (قديم مثلًا) لفحص تجاهل الردود القديمة — تجاهلها مسؤولية المستهلك.
- العدادات (`counters.save/check`) وسجل الدعوات (`calls`) للفحص فقط.

## جدول الحالة (F01 المحلي)

محاور مستقلة: `dirty` (اختلاف القيم الخام عن المؤكدة) و`invalid` (خطأ الاسم المعروف) وحالة العملية:

`idle | saving | failed | unknown | checking | saved`

| الحدث | السلوك |
|---|---|
| إدخال في حالة قابلة للتعديل | يحدّث dirty ويعيد تقييم خطأ الاسم المعروف فقط؛ رسالة «تم الحفظ» القديمة تزال وتصبح العملية idle؛ رسالة «تعذر الحفظ» تبقى (تصف بقاء التعديل غير محفوظ) |
| حفظ clean | لا دعوة ولا loading ولا نجاح جديد — رسالة «لا تغييرات للحفظ» |
| حفظ باسم غير صالح | لا عملية — خطأ مرتبط بالحقل، القيم باقية، التركيز إلى الاسم |
| حفظ dirty صالح | `saving` + نسخة إرسال ثابتة + دعوة واحدة بمعرف المحاولة؛ منع التكرار يشمل submit من أي طريق |
| نتيجة saved | المؤكدة = نسخة الإرسال؛ `saved` وclean ورسالة نجاح باقية واحدة |
| نتيجة not-saved | المؤكدة لم تتغير؛ `failed` والقيم الحالية باقية والتصحيح متاح |
| نتيجة unknown | `unknown` — لا نص «لم يُحفظ» ولا إعادة حفظ أو تخلي تلقائي؛ الحقول readonly وزر التحقق متاح |
| تحقق من المحاولة | `checking` بنفس attemptId — استعلام فقط؛ تكرار التفعيل محروس |
| نتيجة تحقق saved/not-saved | تُطبق على نسخة إرسال المحاولة نفسها |
| نتيجة تحقق unknown أو رفض | عودة `unknown` — «تعذر تأكيد النتيجة، تحقق مجددًا»؛ إعادة التحقق متاحة |
| رد بمعرف قديم | يُتجاهل كليًا (قيم/رسالة/تركيز) ويُسجل في حدث `f01:test` لدليل الفحص فقط |

أثناء `saving/unknown/checking` الحقول **readOnly** (قابلة للقراءة والنسخ، ليست fieldset معطلة)، وbusy على زر الحفظ فقط أثناء `saving` وعلى زر التحقق فقط أثناء `checking` عبر `MicroButtons.setLoading` بتحميل B الافتراضي دون تبديل. الحراسة في المستهلك إضافية لحراسة الزر لأن submit لا يلزم أن يأتي من click عليه.

## المغادرة

- **رجوع** إلى منظر القراءة (النسخة المؤكدة فقط) و**تعديل** للعودة. لا `history.back` ولا `beforeunload` ولا ادعاء ربط زر النظام.
- clean: انتقال مباشر بلا حوار.
- dirty في idle/failed: حوار B07 — **البقاء/Escape/الإغلاق الظاهر/الخلفية كلها بقاء** (لا تمس القيم ولا تغادر)؛ **التخلي وحده** يستعيد النسخة المؤكدة ثم يغادر بعد `micro-navigation:closed` مع نقل التركيز إلى عنوان القراءة.
- saving/unknown/checking: المغادرة محجوبة برسالة محلية موجزة بسياسة هذه العينة — لا حوار تخلي ولا وهم إلغاء طلب جارٍ.

## القرارات المعلنة (حواسم العقد)

1. **قناة الإعلان الوحيدة**: رسالة B06 ثابتة `role=status` واحدة لكل نتيجة/انتظار العملية (`#f01-op-note`)، **بدون** `MicroMessages.announce` لنصها نفسه ولا منطقة حية ثانية. حوار المغادرة حوارية بنفسها فلا قناة إعلان إضافية له. خطأ الاسم عبر `aria-describedby`/`aria-invalid` في رسالة الحقل — بلا مصدر إعلان ثانٍ. فحص التفرد في `tools/ux-f01-check.py`.
2. **مؤشر dirty نص عادي** بلا قناة حية: تغيّره أثناء الكتابة لا يعلن لكل تحديث (UX-19)، وحالة dirty تصل لمستخدم قارئ الشاشة عبر رسالة الحوار عند محاولة المغادرة. (قارئ شاشة فعلي NOT RUN).
3. **لا Toast في F01** ولا لون نجاح لكل حقل ممتلئ؛ النجاح نتيجة مثبتة فقط.
4. **محتوى تقني** (attemptId/عدادات) في قسم SIMULATION ودليل الفحص فقط، لا في رسائل المستفيد.
5. **بديل الأرقام**: أرقام 0–9 (لاتينية) وفق الهوية، والاتجاه RTL بخصائص منطقية.
6. **UX-04 هنا فقد تعديل محلي** (لا حذف ولا التزام)، وUX-08/26 على المحتوى المنطبق فقط — لا مبلغ ولا دقة أعمال.

## قواعد خاصة بالعينة

- بيانات تركيبية فقط: بلا شبكة أو تخزين (`localStorage`) أو مصادقة أو تحليلات أو قواعد أعمال.
- النموذج `novalidate` كي تصل محاولة الإرسال إلى سياسة التحقق المحددة هنا؛ `required` والتسمية أصلية بمعناها.
- لا تُنقل نتائج فحص عائلات UI القديمة إلى هذه العينة، وقبولها لا يعتمد رحلة منتج.
- قسم SIMULATION موسوم وخارج واجهة المثال: أي أزراره لا تظهر للمستفيد كجزء من النموذج.

## حدود معلنة

- الفحوص الآلية: Chromium headless فعلي (Playwright) — DOM ولوحة مفاتيح محاكاة ومقاسات 320/360/390/430 ومحاكاة تكبير النص 200% بالآلية المعلنة (مضاعفة أحجام الخط المحسوبة، لا native zoom) ومحاكاة reduced-motion بالتفضيل الحقيقي عبر Playwright.
- **NOT RUN حتى تنفيذ فعلي**: WebKit، أجهزة Android/iPhone حقيقية، TalkBack/VoiceOver، native zoom، لوحة مفاتيح نظام، safe areas فعلية.

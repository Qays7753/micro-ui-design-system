# After Direction References — Micro UI

**Status:** `REFERENCE ONLY` — visual direction, not approved production UI.

These assets were supplied by the project owner as references for the visual direction we want to build for Micro. They do not show Micro’s current UI and must not be treated as product screenshots, business data, final copy, or production assets.

## What to take

- Clear hierarchy and a visible primary action.
- Reduced visual noise and better use of space.
- Grouped content, sections, and rows that make scanning easier.
- A compact summary that can combine a title, a key value, a small visual, and a useful action.
- Overlapping circles as a visual comparison concept.
- Real values inside data marks where the data contract requires them.
- A complete, readable field-state matrix.
- Before/after “After” compositions as target quality for new Micro equivalents.

## What not to copy

- Brand identity, colors, typography, logos, icons, copy, names, avatars, or product-specific navigation.
- Exact screen layouts, dimensions, or information architecture.
- Any data visible in the source images.
- A literal health, profile, login, or dashboard screen.
- Generic card-wall composition or a requirement to put every element inside a card.

## Required translation into Micro

Every derived pattern must use Micro’s approved identity and source contract:

- Deep petroleum identity and approved light surfaces.
- IBM Plex Sans Arabic and IBM Plex Sans for digits/Latin.
- HugeIcons Stroke Rounded.
- Arabic RTL and western digits `0–9`.
- Existing shared tokens and component contracts.
- Editable HTML/CSS/JavaScript/SVG.
- Explicit unknown, zero, invalid, negative, loading, focus, disabled, and read-only states where relevant.

Do not use these images as a CSS background, canvas replacement, or screenshot-only deliverable. The required result is a reusable editable implementation plus an independent preview and review evidence.
